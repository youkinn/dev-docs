## 现象与复现

| 输入（domain=sango-novel） | 期望 | 实际 |
|---|---|---|
| 孙权遣人向关羽求亲，关羽是怎么回复使者的 | 答「吾虎女安肯嫁犬子乎」+ 出处第73回 | 「演义中未涉及」 |

原文确有这场戏，在 `mcp-server/sango/data/corpus/sanguo-yanyi/073.json` 段 5：

> 云长勃然大怒曰：“吾虎女安肯嫁犬子乎！不看汝弟之面，立斩汝首！再休多言！”

**拒答话术本身是正确行为**（设计文档 §1「拒答是验收核心」）。问题在召回没把这段捞进 top5，编排侧按「无命中」注入，模型只能答「未涉及」。即：**不是模型不忠实，是检索层漏了。**

纯检索层复现（不经模型，脚本见课题文件 §2）：

```
index.search('孙权遣人向关羽求亲，关羽是怎么回复使者的', 5)
→ 返回第1回 / 第82回 / 第54回 等 5 段，正确答案段（第73回 段5）排名 #12
```

## 根因

四条独立缺陷叠加，任一条都足以致错。

1. **称谓鸿沟（主因）**：query 说「关羽」，原文写「云长」。`关羽` 在全库 df=7，且**正确段内根本没有「关羽」二字**；`云长` df=153。`data/alias.json`（398 别名 / 148 人物，P002 = 关羽/关云长/关公/云长）已由老陈交付，但**检索侧 `mcp-server/sango/src` 零处引用**——别名表当前只在 orchestrator 用于引用校验（`src/citation.ts:93`）。设计文档 §4 明确别名表用途是「兜住字面层差异」，此环未接上。
2. **段太长，BM25 长度归一化惩罚正确段**：正确段 1555 token（`dl/avg=1.81`），命中更稀有的词（`求亲` df=4、`使者` df=54）却只排 #11；误召 top1 段 639 token、`dl/avg=0.74`。全库 30%（412/1377）段超 1000 token，p90=1671，平均 859。
3. **哈希向量是负资产**：`data/vectors/sanguo-yanyi.bin` 头部 `scheme=0`，即 `build_vectors.py` 中 BGE-M3 降级后的 FNV 哈希向量（256 维随机投影、无语义）。主案例全库最高 cosine 仅 **0.2694**，低于 `MIN_COSINE=0.3` → **纯向量兜底路径永不触发**（「赤壁之战」0.18、「草船借箭」0.19、「桃园结义」0.28 同样是死路）；融合项 `(cos+1)/2` 在候选集内 std 仅 0.0238，加权 0.5 后等于向 BM25 注入噪声，实测把正确段从 #11 挤到 #12。设计文档 §4 要的是 BGE-M3，现状是偏离设计的降级产物。
4. **注入窗口截掉答案句（二阶陷阱）**：`src/citation.ts:158` `trimFragmentToWindow` 锚定「query 关键词最后一次出现」±60 字。正确段正文 778 字，锚点落在「孙权」(337)，窗口 `[277,399)`，答案句在 **454** → 被切掉。**即便修好前三条，模型看到的片段里仍无答案，依旧答「未涉及」。** 24 例基准中，已召回正确答案的 21 例里有 5 例（24%）被窗口截掉答案句。

## 影响面

不止主案例。24 例小基准现状 @1 13/24、@3 17/24、@5 18/24。同类词面鸿沟还有：

- 「草船借箭」：语料第46回回目为「用奇谋孔明借箭」，正文 `草船` 出现 **0 次**
- 「温酒斩华雄」：语料作「其酒尚温」/「酒尚温时斩华雄」，`温酒` 出现 **0 次**
- 称谓类：`关羽` df=7 vs `云长` df=153 vs `关公` df=128

即：**越贴近民间典故 / 成语的提问，越容易踩空。**

## 修复要求

按性价比排序。P0 即可显著改善；P1 涉 chunk 粒度变更（设计文档 §4「H4 待验」决策点），需负责人拍板。

**P0（老陈，检索侧，改动小、不违反 §8「明确不做」）**

1. 检索侧加载 `data/alias.json`，构建期把语料、运行期把 query 双向归一化到规范名（规范名取该 PID 下语料内最高频写法，实测 P002→`云长`、P006→`孙权`、P004→`孔明`）。实测主案例 #12 → **#2**，基准 @1 13/24 → 17/24。
2. `VEC_WEIGHT` 置 0（纯 BM25 已优于现状，且 §8 本就「不做专用向量库」，不引入新依赖）。实测纯 BM25 @1 14/24 > 现状 13/24。
3. 修 `MIN_COSINE=0.3` 死路：或按实际 cosine 分布重定阈值，或在 `scheme=0` 时直接不启用纯向量兜底路径（现状是「永远走不到」的死代码）。

**P0-0（老陈，检索侧，2026-09-19 实测，本期最高性价比）**

**query 改写 / 多路召回。** 实测「华雄是怎么死的」证据段排 #8，改写成事件词后直接进 top3：

| query | 证据段排名 |
|---|---|
| 华雄是怎么死的 | #8 |
| 关羽斩华雄 / 温酒斩华雄 | **#3** |
| 华雄之死 | **#2** |
| 云长提华雄之头 | **#1** |

根因：证据段**不含 query 关键词**（正文无「死」字），纯词法天然打不中。详见 `docs/sango-recall-quality.md` §12。

**已实测否决的路线（勿走）**：段数放大 + 后置重排——ColBERT MaxSim 在 top-20 上仅把证据段从 #8 抬到 **#5**（仍不进 top3），RRF 仅 #8→#7。**重排救不回，必须让第一路就命中。**

**P0-1（老陈，检索侧，2026-09-19 实测新增）**

**分量归一化——修正 P0 第 2 条。** ⚠️ P0 第 2 条「`VEC_WEIGHT` 置 0」是**哈希向量时代**的结论，**真向量时代应撤回**：

- 实测候选集内 `ρ(cos, bm25) ≈ 0.21~0.55`——**两路并非高度重合，向量在提供独立信号**，置 0 会丢掉这部分信息。
- 真正的问题是**量纲不匹配**：候选集内 `cos_std` 仅 **0.023**（挤在 [0.66, 0.81] 窄带），而 `bm25Norm` 经 min-max 是**满量程 1.0**。名义权重 `VEC_WEIGHT=1 > BM25_WEIGHT=0.5`，**实际影响力却相反**。
- **修法**：把向量分也做候选集内 min-max / z-score 归一化，再按权重融合。实测 top3 由 3/10 → **5/10**；`关羽的武器叫什么` 由**完全漏召**救到 #30/#14。

⚠️ **边界（勿过度期待）**：归一化只放大**已有**的排序差异，**不能创造不存在的差异**。「华雄是怎么死的」实测归一化后仍 #8（纯向量本就 #30），**该题只能靠 query 改写（P0-0）解决**。

**已实测否决的路线（勿走）**

1. **段数放大 + 后置重排**：ColBERT MaxSim 在 top-20 上仅把证据段从 #8 抬到 **#5**（仍不进 top3），RRF 仅 #8→#7。**重排救不回，必须让第一路就命中。**
2. **「外置标签表 + 实体名加权」**（2026-09-19 六探针实测）：**实测无效**——「华雄」题标签权重 c 从 0 扫到 2.0，证据段**恒定 #8**；51 题搅动率 13.7% 且**与权重取值无关**（单调平移不改变相对序）。根因：含「华雄」的 9 段里 8 段是干扰段（夜战/潘凤/祖茂/后人诗），**给正确段和错误段加同一个常数，相对排名不变**。
3. **「零成本标签」= chunk 自带回目**：实测 **0/7**（排名 #115~#1209），回目含大量无关实体，信号被稀释。

> **有效替代**：把「标签表」重定义为**「事件表」**（一行 = 一个事件，含短事件名 + `chunk_ids[]`），事件名走**第二路召回**。实测短事件名 5/7 进 top3（`温酒斩华雄` 在毛本 df=0，已排除原文泄漏）。详见 `docs/sango-recall-quality.md` §13。

**P1（需拍板）**

4. chunk 粒度从整段改段内窗口（~200–250 字）：一并解决根因 ②。实测 @3 17/24 → 21/24。代价：语料与向量需重建。
5. （小胡，编排侧）`trimFragmentToWindow` 改为锚定「最稀有 key」或多锚点取并集，确保答案句不掉出窗口；另 `src/agent.ts:543` 注释写「前 3 段」但代码为 `.slice(0, 5)`，口径需统一。

### A 类（本条 bug）根因补充：白话词字面 df = 0

原诊断只写了「称谓鸿沟」（关羽 vs 云长），复验发现**器物 / 关系类白话词整词在原文不存在**，是同一条根因的另一面：

| query 双字 token | 原文 df | 说明 |
|---|---|---|
| `武器` | **0** | 原文写「造…刀」「点钢矛」 |
| `弟弟` | **0** | 原文写「之弟」（df=21） |
| `望梅` | **0** | 原文写「梅林」（df=1） |
| `嘲讽` | **0** | 原文写「讥」（df=3） |
| `少岁` / `斩六` / `过五` / `三英` | **0** | 均为白话搭配，原文无此连续串 |

实测各例 query 的双字 token 原文命中率：#5 仅 **14%**（7 个只中 `张飞`）、#6 **29%**、#12 **33%**。命中率越低，`lexicalHits` 越是只靠人物名撑起（#6 一次捞进 1379 段），答案段被淹没。

**注**：`tokenize` 只产单字 + 相邻双字 token，故 3 字以上的 df 读数恒为 0、不具证据力（诊断时勿误用）。

### B 类（注入层）根因：窗口锚点在古文拆名下全落空

`citation.ts:trimTextToWindow` 按「query 的 2~4 字连续子串」在原文里找锚点；**一个都找不到时兜底取开头 120 字**。

- #7 `望梅止渴`：原文作「前面有梅林」+「由是不渴」，`望梅/梅止/止渴` 均不在段内 → 兜底 120 字，答案句在 **194 字**处被切。**答案段排名 #1，检索毫无问题。**
- #1 `徐晃字什么`：原文作「姓徐，名晃，字公明」——**`徐晃` 这个连续串在段内根本不存在**（古文拆名写法），锚点全落空 → 兜底 120 字，答案句在 **239 字**（段 96% 位置）被切。答案段排名 #2。
- #10 `张松怎么嘲讽曹操`：有锚点（`张松`），但出现在段首、答案句在 217 字处，窗口 `[0,67)` 照样切掉。

**即：B 类不是召回问题，是「检索词在原文的写法与 query 不一致」导致锚点失效。** 与 A 类同源（都是表述鸿沟），但落在注入层，修法不同（锚点应改为「答案候选句」而非「query 子串」）。

### 归类结论

本条 bug 的修复范围**限定为 A 类**（检索层表述鸿沟）。B 类交小胡（编排侧），D 类另立 bug-00004，E 类另立 bug-00005。

修复后本探针的 A 类应清零；B/D/E 三类的复验归各 bug。
