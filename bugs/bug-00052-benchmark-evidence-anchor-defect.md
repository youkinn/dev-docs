## 现象

改切片 / 改归一化 / 改重排都动不了这批题：不管系统怎么改，它们永远「未命中」。

## 判据（判定链，代码位置）

`parser.ts`（证据列 = 表格倒数第二格）→ `matcher.ts extractAnchors()`（**只认 `“…”` 引号内文字**，另按句读切 ≥4 字短语作回退）→ `matchEvidence()`（正文锚 → 回目锚 → 无回目锚时正文锚回退匹配任意回目）。
→ **证据列没有 `“…”` 引号 = 三条路全空 = 恒 rank 0 = 恒未命中**；引号内文字与语料不符，同样恒 0。

## 根因（三层）

1. **数据**：证据列不合本文件结构契约（14 行无引号锚、2 行引文与语料不符）。
2. **实现**：`runner.ts findNoAnchorItems()` 对零锚题直接 `continue` 豁免（注释「说明型/负例证据」），但逐题判分仍记 miss 并计入分母 → 漏锚静默失分，没人看得见。
3. **实现（本次新发现，原记录没有）**：`matcher` 产出 / 比较回目锚时**未做 norm** → 回目锚只要含中文标点即恒失配（语料回目用全角空格分句，证据列多写「，」）。`战役#3` 因此恒 miss（原记录漏记此题）。

## 口径决策（负责人 2026-09-30）

1. **「拒答」类整类删除**，不保留、不迁移。理由：该类与「证据锚进 top5」判定口径不兼容——拒答题按定义无锚；且原类内混装「语料有答案的正题」（张飞用青龙偃月刀吗、赵云救主张郃）与「语料真无记载题」，任何单一评分标准都救不了；「未进 top10 判对」是伪判据（乱召回也判对，假通过）。
2. **零锚题不参与计算**：单列、不进通过率分母；页面须能直观看出「该题未参与评分」。
3. **不用人工打标**：零锚按结构自动识别（零引号锚即零锚），零人工。
4. 拒答能力（是否拒答 / 是否编造）属**答案层**，另立课题（需新特性号，走 requirement-intake）。
