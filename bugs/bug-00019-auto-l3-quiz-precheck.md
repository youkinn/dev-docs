# bug-00019：auto 路径每条问句先白跑一次 L3 题库预检（与轻量分类轮职责重叠）

> Bug 号：bug-00019
> 状态：待修复（已登记，未分配）
> 关联特性：feat-A011（负责人提测验收中发现；代码符合 A011 定稿口径「L3 保留不动」，是分类轮引入后形成的重复判定层）
> 涉及项目：mcp-orchestrator
> 登记：Coco ／ 报告：负责人 ／ 登记日期：2026-09-22

## 现象

聊天页不选场景标签（auto），输入「夏侯惇眼睛怎么瞎的」，日志页该条出现两条工具调用记录：

| seq | 工具 | 出参 |
|-----|------|------|
| 1 | `fengyunsanguo_quiz_route`（L3 题库预检） | `false`（未命中） |
| 2 | `sango_novel_search` | 第 18 回原文命中 |

traceId `2ef3608a-be62-4c66-856c-ed156f574fb9`（2026-09-22 18:14 CST，`log_type=chat`、`domain=null`、`status=success`、`response_code=200`）。

## 先定性：答案链路是对的，多出来的是 L3 预检

`llm_call_logs` 只有两条，且 `tool_calls` 字段均为空 —— 两条工具调用**都是服务端发起**的，不是模型自主决策：

| seq | stage | prompt_tokens | 内容 |
|-----|-------|---------------|------|
| 1 | classify | 71 | 分类轮输出 `1`（原著检索域） |
| 2 | generation | 2075 | 原著域提示词 + 注入片段，请求体无工具定义 |

即：分类正确（`1`）、只检索演义、生成轮按原著域契约作答，答案与引用均正常。多出的 `fengyunsanguo_quiz_route` 是 auto 路径的 L3 预检，**不是模型乱调工具**（日志页当前无法区分两者，是本次误读的直接原因）。

## 根因

`src/agent.ts:896-907`（auto 分支）**无条件先跑 L3 题库向量预检**，未命中才进轻量分类轮：

```ts
const fengyunsanguoHit = await this.options.fengyunsanguoVectorMatcher?.(query);  // src/agent.ts:898
if (fengyunsanguoHit === true || fengyunsanguoHit === "fengyunsanguo") {
  // 题库快路径
} else {
  // 轻量分类轮（feat-A011）
}
```

matcher 实为一次真实 MCP 调用（`src/index.ts:49` → `transport.fengyunsanguo_quiz_route`），不是本地计算。因此**每条 auto 非题库问句都要多付一次跨进程 MCP 往返**（延迟 + 日志噪声）。

L3 的设立背景是 A003：当时 auto 路径没有域判定能力，需要向量高置信识别兜住题库问句。A011 引入轻量分类轮（编号 `1` / `2` / `99`）后，**分类轮已经覆盖「是不是题库域」这一判断** → L3 与分类轮职责重叠，对非题库问句是纯浪费。

A011 需求文档「非目标」明写「既有 L3 题库向量识别保留不动」，故代码本身符合定稿口径 —— 是**需求口径留下了重叠层**，不是实现走样（Coco 登记时判断，供负责人复核）。

同类前例：`df9e5267-d3ba-4c31-9a2d-7ffaf68c56ab`（「关云长义释曹孟德」，auto）同样是 `fengyunsanguo_quiz_route`(false) + `sango_novel_search` 两条。

## 影响面

- 触发面 = **auto 路径的每条问句**（域标签锁定、L2 关键词命中不受影响，这两条不进 L3）。
- 代价：一次 MCP 往返延迟 + 一条日志噪声；无额外 LLM token 成本（L3 不经 LLM）。
- 可读性：一条问句两条工具调用易被读成「模型乱调工具」（本次负责人即如此报告），日志页无「服务端预检」标识。

## 修复候选（待负责人拍板）

1. **L3 从 auto 主链路移除**（Coco 推荐）：auto 统一「分类轮 → 按编号预调域工具」，与 A011「加能力 = 加编号分支」一致，消除重叠层与孤儿路径；代价是题库问句多一次分类轮 LLM（71 token，flash 模型）。需同步确认题库问句分类准确率达标（A011 目标 13：原著 / 题库问句漏判为 `99` 的条数为 0）。
2. **保留 L3 代码、交换顺序**：先分类轮、再按编号预调（效果同 1，只是保留代码形态）。
3. **只改可读性**：日志页把服务端预检与模型调用区分标识（如「域预检」+ 命中 / 未命中），行为不动 —— 不省延迟，只消歧。
4. **若坚持保留 L3 快通道**：需先给出 L3 命中率数据。当前全库 `tool_call_logs` 中 `fengyunsanguo_quiz_route` 仅 2 条且均为 `false`（无命中样本），不足以证明这条快通道的收益。

## 验证口径（修复后）

- 题库问句（auto 且未命中 L2）：分类轮输出 `2` → 只调题库域工具，答案正常。
- 日志页该条不再出现「未命中的题库预检」记录。
