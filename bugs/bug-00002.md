# bug-00002: 选中"风云三国"标签后模型未路由到题库工具

> Bug 号：bug-00002
> 状态：待修复
> 关联特性：feat-A003
> 涉及项目：mcp-orchestrator, mcp-web
> 日期：2026-09-15
> 决策：方案 B（标签透传 `domain` 字段），2026-09-15 负责人确认

## 复现步骤

1. mcp-web 选择"风云三国"标签 → "问题查询"服务
2. 输入：`三国"三绝"中的智绝指的是谁`
3. 观察：模型未调用 `sango_query`，走自由作答
4. 对比：输入 `风云三国 三国"三绝"中的智绝指的是谁` → 调用 `sango_query` → 返回"诸葛亮"

## 预期行为

选中"风云三国"标签后，三国相关提问应自动路由到题库，不需要用户手动加"风云三国"前缀。

## 根因分析

`agent.ts` 的 `UNIFIED_SYSTEM_PROMPT` 触发条件过严：

> 适用域：仅限风云三国游戏内的招募武将问答题；其他三国历史或常识问答不属于本能力，不要调用 sango_query。

模型判断"三国三绝中的智绝指的是谁"属于普通三国历史问答，不调用工具。只有显式包含"风云三国"关键词时才会命中。

而 feat-A003 将标签降级为纯前端 UX，请求体只有 `{ message }`，后端无法感知用户选择了"风云三国"标签。

## 修复方案（方案 B：标签透传）

### 改动点

**前端（小叶）：**

- `src/api/client.ts`：`sendChatMessage` 新增可选参数 `domain?: "sango"`，序列化时仅非空时写入请求体
- `src/stores/chat.ts`：当 `mode === 'sango' && sangoService === 'query'` 时传 `domain: "sango"`；其余场景不传此字段

**后端（小胡 / 老陈）：**

- `src/server.ts`：`POST /api/chat` 严格白名单新增可选 `domain?: "sango"`，其余未知键仍 400；将 `domain` 透传给 Agent
- `src/agent.ts`：`processQuery` 收到 `domain === "sango"` 时，在 system prompt 末尾追加领域提示（如"当前用户已选择风云三国题库场景，提问视为题库问题，优先调用 sango_query"），普通路径行为不变

### 对普通问答的影响

- `domain` 为可选字段，不传时完全走现有逻辑，普通问答不受任何影响
- 天气标签暂不需要透传（地名自然区分），仅为风云三国场景使用
- 标签从"纯展示"恢复为功能性入口，符合用户选择标签的直觉预期
