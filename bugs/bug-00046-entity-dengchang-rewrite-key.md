# bug-00046 实体表「登场」行改写口径错误：问句被改坏（「刘备首次出场」→「刘备首次人物首次登场」）

## 现象（负责人 test-2031 第 7 项）

- trace `8dd2a372-ead8-4c87-8cb9-70cffd843d03`：问「刘备第一次出场是什么时候」→ normalized `刘备第一次人物首次登场是什么时候`（rewrites：`出场→人物首次登场`）
- trace `57cbb020-30ed-4cc4-a347-2eebc35328f8`：问「刘备首次出场是什么时候」→ normalized `刘备首次人物首次登场是什么时候`

## 根因（2026-09-28 定位）

`sango/data/entity-table.json` 的 `type=登场` 行：

- `canonical = 人物首次登场`——canonical 自带**角色占位词「人物」**，改写后直接进入用户问句；
- `rewriteKeys` 把**不含首次义**的键（`登场 / 出场 / 出世`）与含首次义的键（`首次登场 / 初次登场 / 第一次出现 / 初登场 …`）混在同一行 → bare「出场」被替换成「首次登场」，与问句自带的「首次 / 第一次」叠加。

（事件表中的人物事件名是「刘备首次登场」等具名事件；本行是通用「登场」概念行——两者口径被混用。）

## 目标行为

- 「刘备首次出场是什么时候」→ `刘备首次登场是什么时候`
- 「刘备第一次出场是什么时候」→ `刘备第一次登场是什么时候`
- 含首次义的键（`首次登场 / 初次登场 / 第一次登场 …`）**不得被压成裸「登场」**（不丢语义）

## 修法（09-29 负责人定案：保原词面 + 双写；详见「排查结论」）

- **A 语义分层（推荐）**：canonical 去掉占位词「人物」（→「首次登场」）；不含首次义的键（`登场 / 出场 / 出世`）拆为独立一行（canonical「登场」）。
- **B 最小止血**：仅把 `出场 / 出世` 降级 `fragmentOnly`（query 侧不再替换）。

## 影响面与验证

- 表改动若影响语料归一化：`normVersion` 换代 + 索引 / 向量按 A016 口径重跑（必要性须在回执说明，别漏也别多做）。
- 验证：两条 trace 的 normalized 复验；含首次义键语义不丢的用例；A015 基准同基线 top5 不倒车。
- 门禁：`npm run build` exit 0 + `npm test` 全绿。

## 排查结论（2026-09-29 二稿；按负责人对照实例改定，Coco）

### 关键实验：同一问句、四组配置（真索引代码，零 LLM，可复现）

问句 `“伏龙”指的是谁`；证据段 `0035:c0005`（第 35 回水镜「伏龙、凤雏，两人得一，可安天下」）。做法：用 `SangoIndex` 各建一次索引——现网 `data/`（索引侧替换 + query 侧替换），与临时 dataDir（缺 `entity-table.json` → 归一化降级为恒等，即「保原词面」），重排打分器分别不接 / 接入，四种组合各跑同一问句。

| 配置 | top10 首位 | 证据段名次 |
|------|-----------|-----------|
| 现状（索引替换 + query 替换）· 重排关 | 0104:c0012 | 第 4 |
| 只停 query（索引仍替换、query 原文）· 重排关 | 0041:c0021 | **未进 top10**（反而更差）|

同类读数：`锦马超指的是谁` 在保原词面下 `0065:c0006`（「人言锦马超，名不虚传」）升到第 2 位。

**只停 query 侧不替换是不够的**：索引侧已把「伏龙」从语料里抹掉（11 处 →「诸葛亮」），query 用原文等于去查一个索引里不存在的词，证据段直接掉出 top10。故「query 不替换」必须与「索引侧双写」同批落地。

### 根因（定序：**口径为根、重排为放大器**）

1. **根：改写口径＝替换（破坏性）**。把判别性词面换成高频本名：伏龙 df=11 → 诸葛亮 df=146；锦马超 1 → 马超 215；孟德 24 → 曹操 926。语料侧替换 7354 处、1712/2344 chunk（73%）受影响；465 个语料命中的键里 291 个「本名频次 ≥5× 别名」。BM25 中罕见词的高 idf 加分被摊薄到上百段 → **证据段名次从第 1 掉到第 4**，落入「靠排序运气」区。
   （修正上一稿表述：池子规模 lexicalHits=2301 两种配置相同——由「的 / 是 / 谁」等共同词决定；**判别点是名次，不是池子大小**。）
2. **放大器：重排（bug-00045）**。在同一口径下把已滑到运气区的证据段挤出窗口（上表第 3 行）；口径修好后重排开着也守得住（第 4 行）。
3. **登场行数据错**。问句被改坏（`刘备第一次登场` → `刘备人物首次登场`，丢「第一次」）+ A018 事件桥 160/708 组 alias 永不命中。

### 登场：照死亡同款处理（负责人 09-29 意见；架构上可行，落点明确）

- 死亡路：标签「人物之死-X之死」→ `deathByPerson` 人名词典 + `intent.ts` `matchDeathIntent` → 强命中置顶（`sango-index.ts:631`）。
- 登场现状：标签「人物之生-X登场」**已在**（`data/corpus/tags/event.json`，96 处），但 `sango-index.ts:471` 的口径把登场语义从第三路候选面剔除、交给「事件内容」（A018 事件桥）承载——而该桥正被实体表登场行打死。
- 落地（**负责人 09-29 已定**）：照死亡同款补 `birthByPerson` 词典（由「人物之生-X登场」建，`sango-index.ts:475` 已在解析该标签）+ 登场意图（什么时候出场 / 首次登场 / 第一次出场 / 何时登场）→ 同款强命中置顶（对齐 `sango-index.ts:631`）；同时删掉实体表登场行 `rewriteKeys`（语料侧仅 1 处命中，删之近乎零损失），canonical 去占位词「人物」。属于主方向同一次索引 / 向量重建，不新增第二次重建。

### 修法（主方向）

- **索引侧 `rewriteKeys` 由「替换」改「双写」**（保原词面 token + 追加规范形 token，复用 `fragmentOnly` 现成双写实现）；**query 侧不再替换**。收益即上表第 2 / 4 行（证据段回到第 1–2 名），换说法仍可匹配（`诸葛亮是谁` 在保原词面索引下照常召回）。
- 代价：索引内存重建（重启即建）+ 缓存换代（normVersion 参与 CACHE_VERSION）；**向量无需重跑**——`scripts/build_vectors.py` 本来就以 chunk 原文嵌入，检索改回原文后向量路成为「原文 ↔ 原文」同口径（比改前更一致）；缓存命中率下降（换说法不再合并为同一缓存键）；A016 验收 3 / 8 文字口径需修订。
- `events.json` alias 与 query 同口径（主方向必然配套）。
- 配套口径（Coco 定，负责人无异议即执行）：`sango_query_embed` 缓存判定保持「归一化后编码」（缓存键内部口径，换说法仍合并同一缓存），与检索侧用原文不冲突；诊断面板「归一化改写」环节将恒空，改为展示「索引侧双写扩展命中的键」，A016 验收 3 / 8 同步修订。
- 重排（bug-00045）：**不列为本票前置**（负责人 09-29 口径：解决问题优先、验收非关键；暂时解决不了可先挂着）。待登场类结构路（`birthByPerson`）落地后复测——该类问句不再依赖排序运气，倒车现象预期自然消解，届时关闭 bug-00045。

### 数据盘点：具名「登场」数据落在哪、是不是死重（负责人 09-29 问）

| 落点 | 内容 | 现状 |
|------|------|------|
| 实体表 | 仅 1 行通用概念行（canonical 人物首次登场）+ 1 行 出山；**无按人条目** | 这行的 rewriteKeys 就是问句被改坏与桥失效的来源 |

- 冗余关系：134 组事件里 **133 组**与「人物之生」标签落在同一 chunk（394 个 chunk 引用中 219 带该标签）。
- 定性：**不存在白写的垃圾数据**。现状下 134 组事件属「死重」（接了线但口径不通、不产效果）；口径修好后，「X出场 / X首次登场」这类词面走事件桥直接命中，任意问法（如「X第一次出场」）走 `birthByPerson 结构路。
- 处置口径（负责人 09-29 定）：events.json 134 组**本次不动**；待登场类结构路（`birthByPerson`）落地、该类问句已置顶生效后，再作收尾清理（届时删除无任何影响）。`birthByPerson` 由标签建；本票要清的只有实体表那一行通用「登场」的 rewriteKeys。
