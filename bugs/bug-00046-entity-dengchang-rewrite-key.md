# bug-00046 实体表「登场」行改写口径错误：问句被改坏（「刘备首次出场」→「刘备首次人物首次登场」）

## 现象（负责人 test-2031 第 7 项）

- trace `8dd2a372-ead8-4c87-8cb9-70cffd843d03`：问「刘备第一次出场是什么时候」→ normalized `刘备第一次人物首次登场是什么时候`（rewrites：`出场→人物首次登场`）
- trace `57cbb020-30ed-4cc4-a347-2eebc35328f8`：问「刘备首次出场是什么时候」→ normalized `刘备首次人物首次登场是什么时候`

## 根因（2026-09-28 定位）

`sango/data/entity-table.json` 的 `type=登场` 行：

- `canonical = 人物首次登场`——canonical 自带**角色占位词「人物」**，改写后直接进入用户问句；
- `rewriteKeys` 把**不含首次义**的键（`登场 / 出场 / 出世`）与含首次义的键（`首次登场 / 初次登场 / 第一次出现 / 初登场 …`）混在同一行 → bare「出场」被替换成「首次登场」，与问句自带的「首次 / 第一次」叠加。

（事件表中的人物事件名是「刘备首次登场」等具名事件；本行是通用「登场」概念行——两者口径被混用。）

## 目标行为

- 「刘备首次出场是什么时候」→ `刘备首次登场是什么时候`
- 「刘备第一次出场是什么时候」→ `刘备第一次登场是什么时候`
- 含首次义的键（`首次登场 / 初次登场 / 第一次登场 …`）**不得被压成裸「登场」**（不丢语义）

## 修法（口径待负责人拍板）

- **A 语义分层（推荐）**：canonical 去掉占位词「人物」（→「首次登场」）；不含首次义的键（`登场 / 出场 / 出世`）拆为独立一行（canonical「登场」）。
- **B 最小止血**：仅把 `出场 / 出世` 降级 `fragmentOnly`（query 侧不再替换）。

## 影响面与验证

- 表改动若影响语料归一化：`normVersion` 换代 + 索引 / 向量按 A016 口径重跑（必要性须在回执说明，别漏也别多做）。
- 验证：两条 trace 的 normalized 复验；含首次义键语义不丢的用例；A015 基准同基线 top5 不倒车。
- 门禁：`npm run build` exit 0 + `npm test` 全绿。

## 备忘：query 改写一类问题（test-2031 第 8 项，2026-09-28 登记，**未调查**）

负责人判断这可能是**一类问题**，并怀疑所有 query 改写都有问题；本期**只登记、不修改、不调查**，后续重新调查。

示例（真实 trace）：

- `f2701e09-3419-4176-b2a3-333d1fc49bf8`：「伏龙」指的是谁 → `诸葛亮`指的是谁
- `c562cc1d-dd7f-498e-906a-005c582bcf22`：先主指的是谁 → `刘备`指的是谁

已知线索（供后续调查）：与本票正面案例同一机制——**改写把 query 里的指称 / 别名替换成 canonical 或事件名，但目标词选择与上下文叠加没有约束**（占位词进 query、与问句自带修饰词叠加）。指称类改写（伏龙→诸葛亮、先主→刘备）是否算缺陷取决于口径：若期望行为是「保留用户原词面、只在检索侧扩张」，则替换本身即为系统性偏差，需整体重新调查后再定改法。
