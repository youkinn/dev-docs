# bug-00004：问「第几回」类问句无法作答（提问要的东西被 prompt 明令禁止输出）

> Bug 号：bug-00004
> 状态：待修复
> 关联特性：feat-A004
> 涉及项目：mcp-orchestrator（注入视图 + prompt）
> 登记：Coco ／ 报告：负责人 ／ 登记日期：2026-09-18
> 复现探针：`dev-docs/test/recall-injection-probe.mjs --only 3,4`
> 关联：bug-00003（同类现象「答未涉及」，但根因层不同——本条不是召回问题）

## 现象与复现

| 输入（domain=sango-novel） | 期望 | 实际 |
|---|---|---|
| 诸葛亮死于第几回 | 第104回 | 演义中未涉及 |
| 三英战吕布 是第几回 | 第5回 | 演义中未涉及 |

**关键：这两例的检索与注入都是好的。** 答案段排名 #2，答案句（「孔明奄然归天」/「三姓家奴休走！燕人张飞在此！」）确实进了注入窗口，模型看得见原文——它仍然答「演义中未涉及」。

## 根因：问句要回号，链路两端都把回号拿掉了

三处规定叠加成死结：

1. **注入剥离回目**（spec §6.3）：注入视图只给纯原文 + `[片段N]` / `⟨Qn⟩`，**不带回目、段号、分数**（防模型抄写出处）→ 模型上下文里**不存在任何回号**。
2. **prompt 禁止输出回目**（`agent.ts` 能力三第 6 条、`ROUTE_HINTS['sango-novel']` 第 2 条）：「严禁输出引语原文、回目、出处或段号」→ 模型即便推断出回号也不许写。
3. **唯一间接通道不可预知**：模型输出引语指针 `[Qn]`，服务端渲染成 `「原文」（出处：第N回 回目）`——**渲染结果恰好含回号**，用户其实能看到。但模型无法预知 `[Q1]` 会渲染成第几回，也就无从判断该不该引、引哪一条。

于是模型只能按能力三第 4 条（原文没有相关内容 → 答「演义中未涉及」）处理。**拒答话术本身没错，错在把「上下文没有回号」误判成「原文没有」。**

这不是模型不忠实，也不是召回漏——是**需求与 prompt 的口径缺口**：验收口径只规定「出处只到回目」，从未定义「以回号为答案主体」的问句该怎么答。

## 影响面

所有**答案主体是章节号**的问句：「XX 是第几回」「XX 在第几回」「XX 回讲了什么」「哪一回…」。这是原著解读场景的高频问法（民间典故尤其常这么问，如「三英战吕布是第几回」「望梅止渴在第几回」）。

## 修复要求（**需负责人拍板方向**）

三选一，取舍不同：

| 方案 | 做法 | 代价 |
|---|---|---|
| A. 注入补回号 | 注入视图末尾附「本片段出处：第N回 回目」 | 最小改动；但把回号重新放进模型上下文，削弱 §6.3「防抄写出处」的初衷 |
| B. prompt 开例外 | 允许模型在回号类问句输出回号，服务端按渲染结果校验 | 需新增「回号类问句」识别与回号校验；prompt 例外条款有被泛化滥用的风险 |
| C. 结构化行 + 定向 prompt | 注入附结构化出处行，prompt 明确「仅当用户问回号时可引用该行」 | 折中；改动量中等，边界最清晰 |

**Coco 建议方案 C**：既让回号可达，又把「可输出回号」限定在明确条件下，不放开 §6.3 的通用约束。若负责人认为改动量优先，A 可接受。

## 验收（测试即文档）

- 「诸葛亮死于第几回」→ 答第104回（且出处为第104回）；「三英战吕布是第几回」→ 第5回。
- 负样本不倒退：演义中确无的桥段仍答「演义中未涉及」，不得为凑回号而编造章节。**实测可用的真负样本**：`月下斩貂蝉是第几回`、`关银屏是第几回`、`三十六计是第几回`（三者全库命中均为 0，已核）。
  - ⚠️ 勿用 `空城计是第几回` 当负样本：该事件**在原文**（第95回「马谡拒谏失街亭　武侯弹琴退仲达」），只是不叫「空城计」——它属于 B/E 类「表述鸿沟」，不是负样本。同理 `借东风`、`草船借箭` 的**事件**都在原文（第49回祭风 / 第46回借箭），仅词面不匹配。
- 非回号类问句不得因本条改动而输出回目（守住 §6.3）：如「关羽的武器叫什么」的结论里不得出现回号。
- 探针 `--only 3,4` 的附注 D 应消失。
