# bug-00039：边界语义复核无 LLM 调用次数上限（串行逐句复核，用户等待无封顶）

> Bug 号：bug-00039

## 现象

问「夏侯渊字什么」（trace ba5bb4ec）一次请求触发 3 次 LLM 调用（1 生成 + 2 边界复核）。负责人追问极限情况查到：边界复核对「低重叠句」逐句串行调用 LLM，代码层**无次数上限**；judge 单次约 1s（trace 实测 seq2=1022ms），模型输出多句低重叠结论时，用户等待 = N 秒且无封顶，延迟不可控。

## 完整始末（时间线）

- **a121557（09-26，bug-00032/33/34 修复）**：结构门「句-片段重叠」由「字面一票否决」改为「低重叠 → 边界语义复核」，`for (const sentence of lowOverlap) { await checkNovelBoundarySupport(...) }` 循环**未设上限**。设计假设＝「域提示已约束答案只有一句结论」→ 把 prompt 约定当成硬约束，未做调用预算 / 上限保障。该改动**新增 LLM 调用（+N），未单独向负责人报备调用次数增量**。
- **a2d88d0（09-26，bug-00037 修复）**：把「无指针叙述句」也纳入低重叠候选，N 上界从「答案句数」扩到「答案句数＋无指针叙述句数」，无上限问题被放大。
- **ba5bb4ec（09-26 下午）**：3 次 LLM 调用且返回「空正文+脚注¹」。排查定案双因：裸引用行被当句子复核（→ bug-00038 拒答口径缺失，已修 4bea3ab）；复核次数无上限（→ 本票）。
- **09-26 晚**：负责人打回 test-0825 相关全部 bug；要求本票单独立档写清始末；并立团队红线：**新增 / 增加 LLM 调用必须先报备、必须带次数上限**（AGENTS.md 基本原则 14，story-A999-01 已同步）。

## 根因（为什么能设计出来）

1. 把 prompt 约定（「答案只有一句结论」）当成既成约束，而不是需要硬保障的边界条件——模型越界即无兜底；
2. LLM 调用次数未被当作一等资源（延迟 / 成本 / 抖动）纳入设计评审，没有「调用预算 / 次数上限」检查项；
3. 审查清单缺「新增 LLM 调用必须报备 + 必须有上限」——a121557 的 +N 边界复核、feat-A011 的 +1 classify 均未单独报备。**此为 Coco 架构审查失职**。

## 修复口径

- **复核预算 = 1（2026-09-26 负责人预算原则）**：指定 sango-novel 域正常 1 次生成、第 2 次仅极限复核、3 次以上默认打回；自由模型（auto）极限 = 分类 + 生成 + 复核 = 3 次（负责人明确，走快路径一般 2 次）。`MAX_BOUNDARY_REVIEWS` 从「上限 3」收窄为「单请求复核预算 1」——低重叠候选至多复核 1 句（bestOverlap 最高者），其余直接按 unsupported 裁剪；
- 每环仍受 bug-00018 空答案变参重试约束（单环 ≤2 次，已报备例外）；
- 复核候选另受 bug-00040 引语片段句豁免（引文行不进候选、不占预算）；

## 验证
