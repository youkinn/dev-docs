# bug-00041 关公 被终审误判「跨主条目」禁入改写键（改写明细缺 关公→关羽）

## 现象（负责人 test-1921 #3）

- 问「桃园之盟中关公是老几」（trace 6dd72575-51ce-42a6-a850-edc7aa761194）：改写明细只有 `桃园之盟→桃园三结义`，缺 `关公→关羽`；normalized=`桃园三结义中关公是老几`（关公未被改写）。
- 对照「桃园之盟中云长是老几」：明细完整（`桃园之盟→桃园三结义` + `云长→关羽`）——显示机制无误，问题在数据。

## 根因（2026-09-26 排查定案）

- 实体表关羽行 `关公` 为 fragmentOnly（片段侧同义词素材），不是 query 改写键 → query 侧不替换、不计入 rewrites（接口 §5 语义如此）。
- 之所以 fragmentOnly：终审 `feat-A016-entity-diff-report.md` 判 `关公` 为「跨主条目（多主条目候选）→ 禁入改写键」（R2）。
- 该裁定为误判（证据）：
  - 关公 519 处命中，topPid=P002（关羽）**519/519 = share 100%**；
  - P001x141 / P005x124 是结义场景上下文共现（刘备/张飞），非指称替换；
  - `关公` 仅出现在 P002 行（draft person 表核查无同串跨人）；
  - 设计文档曾留疑点：「share=1 但 verdict 为多主条目候选仍按终审判定禁入」（feat-A016-entity-table-design.md 裁定说明）。

## 修复口径

- 关羽行 `关公`：fragmentOnly → rewriteKey（与 `云长` 等别名同口径），query 侧改写 关公→关羽、计入 rewrites。
- normVersion 换代 + 索引重跑（双侧归一化口径变化）+ recall-bench 同基线回测（验收 6 口径，不回退）。
- 键排斥规则核对：`关公` 非任何行 canonical/rewriteKey 的真子串，安全。
- 生效需重启编排侧（sango 子进程）。
