# bug-00006：答案已召回但注入视图不可见（注入层 top3 截断 / 窗口裁切）

> Bug 号：bug-00006
> 状态：待修复
> 关联特性：feat-A004
> 涉及项目：mcp-orchestrator（`src/citation.ts` 注入视图；`src/agent.ts` 注入段数）
> 登记：Coco ／ 报告：负责人 ／ 登记日期：2026-09-19
> 复现探针：`dev-docs/test/recall-classify-900.mjs`（全量）／ `dev-docs/test/recall-injection-probe.mjs`（单例）
> 关联：bug-00003（检索层漏召）；本条是检索**成功之后**的注入层缺陷，两者根因层不同，故独立成票

## 现象

900 问全量跑**真实检索 + 真实注入**（零 LLM）：**118 题（13.1%）答案各部分已进 top5，但注入视图里看不到答案**——模型上下文里没有答案，只能答「演义中未涉及」。

即：**检索已经把正确的段落捞回来了，是注入层把它丢掉的。**

## 细分（两条独立成因，账目闭合 118）

| 子类 | 题数 | 成因 |
|---|---|---|
| 窗口切掉 | **64** | 答案段已在注入前 3 段内，`trimTextToWindow` 的窗口没盖住答案句 |
| top3 截断 | **54** | 答案段排 #4-5，`INJECT_FRAGMENT_LIMIT = 3` 直接不注入 |

## 根因

### 1. 窗口锚点用「query 子串」，古文拆名下全落空（64 题）

`citation.ts` 的 `trimTextToWindow` 按「query 的 2~4 字连续子串」在原文找锚点；**一个都找不到时兜底取开头 120 字**（`WINDOW_FALLBACK = 120`）。古文「拆名」写法与白话 query 字面不一致时锚点必然全落空：

| 案例 | 原文写法 | 锚点 | 结果 |
|---|---|---|---|
| 徐晃字什么 | 「姓徐，名晃，字公明」 | `徐晃` 连续串在段内**不存在** | 兜底 120 字，答案句在 239 字（段 96%）被切 |
| 望梅止渴 | 「前面有梅林」+「由是不渴」 | `望梅/梅止/止渴` 全落空 | 兜底 120 字，答案句在 194 字被切（**答案段排 #1**） |
| 张松怎么嘲讽曹操 | `张松` 在段首 | 命中 | 窗口 `[0,67)`，答案句在 217 字被切 |

**这与 bug-00003 同源（都是 query 与原文的表述鸿沟），但落在注入层**：修法不是改检索排序，而是把锚点从「query 子串」换成「答案候选句」。

### 2. 注入段数硬上限 3，检索却给 5（54 题）

`INJECT_FRAGMENT_LIMIT = 3` 是硬常量，而检索返回 top5。答案段排 #4-5 的题**结构性看不见答案**，与窗口无关。

另：`src/agent.ts:543` 注释写「前 3 段」但代码历史上是 `.slice(0, 5)`，**注释与代码口径不一致**，修复前必须先统一。

## 影响面

- 当前 **118/900 = 13.1%**。
- **与 bug-00003 有耦合**：A 类（检索漏召）修好后，原本排 #6-80 的答案段会上浮，其中相当一部分会落到 #4-5 → **B 类占比可能不降反升**。故本票必须与 bug-00003 同批验收，否则「修好召回、答对率不动」。

## 修复要求

1. 窗口锚点策略改为「答案候选句」（含「字 / 造 / 死于 / 名」等陈述句特征），或对短段（≤ `WINDOW_BUDGET`）直接全宽注入，避免兜底窗口切掉答案。
2. 注入段数与窗口预算**重新定标**：需与检索 `search()` 返回数、prompt 长度预算联合定，**禁止单方面调大**（会挤压 prompt 预算、影响其他能力）。
3. `agent.ts:543` 注释与代码口径统一。

## 验收（测试即文档）

- `recall-classify-900.mjs` 的 B 类计数：修复前 **118 → 目标 0**（或降到明确可接受的残余并说明）。
- 单例回归：`recall-injection-probe.mjs --only 1,7,10` 的 B 类附注消失。
- 反向用例：不得因扩大注入导致 prompt 超预算或引用质量下降（与 bug-00005 联测）。
