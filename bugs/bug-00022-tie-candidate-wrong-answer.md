1. 当前召回 = 字符 bigram Dice + `filter(score>0)` + 稳定排序 + `limit=1` → **判对判错全由字面重合决定，无任何语义成分**。

## 现象

traceId `9b2825f3-53b6-4425-b812-38c7ff6066bf`：

```
POST /api/chat  {"message":"关于字什么","domain":"fengyunsanguo"}
→ 200 {"code":200,"data":{"answer":"吕布的字是奉先。","citations":[]},"message":""}
```

期望：按需求「候选中没有含义对应的题目 → 只回『题库未收录该题，请换个问法』」；若按用户本意（「关羽字什么」的错字）则应答「云长」。实际返回一条**看起来正确的错答案**。

## 链路核对

| 环节 | 读数 |
|------|------|
| 输入 / 域 | `关于字什么` / `domain=fengyunsanguo`（标签硬锁，快路径） |
| 工具 | `fengyunsanguo_query`，`args={"text":"关于字什么"}`（**无 `limit` → 默认 1**），`caller=server` / `stage=fastpath`，1 ms |
| 工具出参 | `1. 吕布的字是什么？ → 奉先` |
| 生成轮 | `completion_tokens=6`、`finish_reason=stop`、输出 `吕布的字是奉先。` |
| 返回 | `status=success`、`citations=[]` |

## 定性

需求口径（`requirements/feat-A002-sango-quiz.md` 知识问答）：未收录问法 = 召回候选为空，**或候选中没有含义对应的题目** → 回「题库未收录该题，请换个问法」。
本次候选「吕布的字是什么？」与「关于字什么」**没有含义对应** → 应回未收录；实际作答，且违反「只输出该题答案原文」（输出整句）→ **是缺陷**。

严重度：比未收录更糟 —— 返回**看似正确的错答案**，用户无法分辨。

## 根因（机制读数）

实测（题库 88 题、按现算法复算）：

| 输入 | top1 | dice | 说明 |
|------|------|------|------|
| 关于字什么 | 吕布的字是什么？ | 0.200 | 与 16 道「XX的字是什么」**全部并列 0.200**；稳定排序取题库序 #2（吕布） |
| 关羽字什么 | 关羽的字是什么？ | 0.400 | 字面正常时能答对 |

1. **并列分无区分度**：输入与候选只共享「什么」一个 bigram → 所有 6 字题干并列 0.200；`sort` 稳定 + 题库序决定 top-1，**与语义无关**。
2. **`limit=1` 只给一条候选**：trace 的 `args` 无 `limit` → 默认 1，模型没有比对空间。契约本身允许快路径传 8（`mcp-orchestrator/api/feat-A005-fengyunsanguo-mcp.md` §1：快路径内部可传 `limit=8`）。
3. **生成轮未遵守约束 + 无服务端校验**：模型既没走「含义不对应 → 未收录」，也没守「只输出答案原文」；题库域目前**没有服务端硬校验**，域锁定完全依赖提示词 —— 已被两次绕过（bug-00021 与本条）。

### `limit=8` 的效果（实测排序）

「关于字什么」按现算法 top10 **全为 0.200 并列**，「关羽的字是什么？」排第 **6** → 给足 8 条候选时正确项在候选内，模型至少有比对空间（不保证必选对，但可及）。

## 对照案例（2026-09-23 负责人补充；**口径未定义，不是正例**）

traceId `223eb61e-5f69-4f02-a61c-6d2e2fe3c14a`：

```
POST /api/chat  {"message":"运输工具骑着诸葛亮的是发明","domain":"fengyunsanguo"}
→ 200 {"code":200,"data":{"answer":"木牛流马","citations":[]},"message":""}
```

原题 = 「诸葛亮发明的运输工具是？」（题库序 #35 → 木牛流马）；输入是它的**字序打乱**版。

| 环节 | 读数 |
|------|------|
| 工具出参 | `1. 诸葛亮发明的运输工具是？ → 木牛流马`（dice **0.545**，次名 0.160 —— 非并列） |
| 生成轮 | `completion_tokens=4`、输出 `木牛流马`（= 答案原文，格式正确） |

句子本身：**不通顺、无自洽语义**。逐词看 —— 「运输工具」（主语）+「骑着」（谓语）+「诸葛亮」（宾语）语义荒谬（工具骑人）；「…的是发明」搭配不成立（应为「发明的是什么」）；整句无疑问标记，不是问句，只是原题的字序被打乱。人靠词袋能反推原题，但**它不是用户会说的「另一种问法」**。

结论（修正 2026-09-23）：

- 该输入下答对，靠的是 **bigram 集合对字序不敏感**（dice 0.545、次名 0.160 非并列），**不是语义理解**。与本票的失败**同源**：两次都由字面重合决定，而非语义判定 —— 「关于字什么」字面重合弱且并列 → 答错；本句字面重合强且非并列 → 答对。
- 需求未定义此类输入（乱序 / 病句 / 无疑问标记）的口径 → **既不能记为正例，也不擅自记为缺陷**；待需求侧定口径后回填（`AGENTS.md` 第 12 条：口径以需求文档为准）。
- 保留价值（仅作参照，不作验收证据）：它说明「字面重合足够强时，模型会照着候选答」，是本票「候选并列、字面重合弱」情形的镜像，佐证「判定不能只靠字面召回 + LLM 提示词」。

## 修复口径（待负责人确认）

1. **主修 · 服务端 Guard（结构）**：题库域生成轮输出必须严格命中**注入候选的答案集合**，否则回「题库未收录该题，请换个问法」——对齐原著域引用 Guard 的做法。理由：提示词约束已被两次绕过，域锁定的保证不能只靠提示词。
2. **配套**：快路径预调 `limit` 1 → 8（契约内，无需改接口文档）。
3. **可选（老陈）**：并列分的二次判据（如要求共享 bigram ≥ 2、或按题干长度惩罚）；需标定，建议在 1 / 2 之后再看。

## 验证口径（修复后）

- 「关于字什么」→ 未收录话术（或答「云长」，取决于 1 / 2 的组合）；**不得**再出现「吕布的字是奉先。」这类答非所问。
- 负例不回归：「刘备字什么」→ 未收录话术。
- 正例：「关羽字什么」「关羽的字是什么」→「云长」，且格式只有答案原文。
- 新增断言：输出不在候选答案集合内时，服务端必须拦截（Guard 用例）。
