## 现象与复现

| 输入 | 期望 | 实际 |
|------|------|------|
| 夏侯惇的字是什么 | 返回题库答案「元让」 | 正常 |
| 夏侯惇字什么 | 返回题库答案「元让」（接口文档已约定省略/冗余问法命中同一题） | 「题库未收录该题，请换个问法」 |

## 根因

`src/sango.ts`（HEAD `f84b302`）的 `search()` 只有两级比对：归一化完全相等 → 题干单向包含。

- 「夏侯字什么」归一化为 `夏侯惇字什么`，题库原文归一化为 `夏侯惇的字是什么`：既不相等，也不被题干文本包含 → 返回 null → 未收录提示。
- 「夏侯惇的字是什么」走完全相等命中，所以正常。

接口契约已写明该行为（`mcp-orchestrator/api/feat-A002-sango-quiz.md` 匹配用例段），属实现缺口，不改需求。

## 修复要求

- 新增「核心问法」比对：归一化后去掉疑问/语气填充词（的 / 之 / 是 / 有 / 什么 / 啥 / 谁 / 哪 / 请问 …），按「核心相等 → 核心双向包含」排在精确匹配之后。
- 排序不得倒退：精确匹配优先于核心匹配。
- 核心去填充词后过短时（只剩「字」这类）不参与比对，避免误命中。

## 验收（测试即文档）

- 省略/冗余问法命中同一题：「夏侯惇字什么」「请问夏侯惇字什么？」→ 同一题、答案「元让」。
- 负样本不误答：无关问法（含 2 字短查询，如「关羽」「曹操」）不得返回题库中不相关题目的答案。
- 原有用例保持通过：`node --test build/sango.test.js`。
