## 0. 范围一句话

风云三国旁单开「三国演义」标签，该标签下只讨论《三国演义》。现代白话提问 → 召回演义原文 → 原文喂模型 → 模型只做归纳。**不评论、不对比正史、不评价对错。**《三国志》同构，本期不做。

## 1. 现状盘点（为什么不是从零开始）

| 事实 | 出处 | 对本次的意义 |
|---|---|---|
| `sango_query` 是 orchestrator 的**本地工具**，走 `agent.localTools`，**不经 MCP** | `src/index.ts:14` | **已定：检索层做成 MCP 工具**（2026-09-16 Coco 需求变更，见 §3 D1）；本行是变更前的现状 |
| 天气能力才是 MCP 工具（`get-forecast` / `get-alerts`），经 `transport.ts` + mcp-server | `src/index.ts` | 两种工具形态都有先例，可任选 |
| 检索实现 = 字符 bigram + Dice 系数 Top-K，候选上限 8 | `src/sango.ts:61,158` | 现有召回层**零模型依赖**；换 embedding 是新引入的技术 |
| 语料 = `data/sango-questions.json`，19KB / 88 题 | `data/` | 题库规模小，bigram 够用。演义是百万字级，**量级完全不同** |
| `/api/chat` 有 `domain` 字段，但只接受 `"sango"` | `src/server.ts:49` | 新增标签**会动契约**，属接口文档先行范围 |

**关键结论**：「现有 sango_query 换召回层即闭环」——这句话在**工具形态**上成立（模型看到的只是一个 tool 定义，换实现不改路由），在**数据量级**上不成立。88 条 vs 千级 chunk，检索策略要重新设计，不是替换一个函数。

## 2. 需要用到哪些技术（清单）

标 **[现有]** 已有能力，**[新增]** 本特性首次引入。

### L1 语料工程 [新增]
- 文本获取：公版来源；**版本先定死为毛本**（避免毛本 / 嘉靖壬午本的文字与回目差异）
- **版权红线**：正文公版 ≠ 现代点校排印本公版。点校、标点、注释、译文可能另有版权，需用公版文字自行标点
- 清洗：全角 / 半角、异体字、错字、断句
- 结构解析：120 回回目 → 回 → 段
- **段落类型标注**：叙事 / 诗赞（「后人有诗赞曰」）/ 评语。诗赞与评语**不是叙事**，不标注会被模型当情节复述，直接踩回「评论」那条线
- 切分（chunking）：段级为主 + 小重叠 + 回目上下文。按回切太粗——一回 5000–8000 字，而答案常只在 1–2 句内

### L2 向量化 [新增]
- Embedding 选型候选：BGE-M3（中文 / 文言强、一次出 dense + sparse、本地免费）/ Qwen3-Embedding / 云端 API
- 长文本截断策略、向量归一化与维度约定
- 一次性成本：百万 token 级，**元级开销，可忽略**

### L3 索引与存储 [部分新增]
- 原文 + 元数据：SQLite / JSON。**不引入专用向量数据库**（千级 chunk 用不上）
- 向量层：sqlite-vec 或内存余弦，**可独立重建**
- 倒排索引：BM25 轻量实现（现有 bigram 是它的退化版）

### L4 检索 [新增]
- **混合检索 BM25 + dense**：向量兜语义，BM25 兜字面。纯向量对「华雄」「关云长」这类人名 / 地名不可靠
- 融合策略：RRF 或加权
- **别名 / 术语表**：人名、字、号、官爵、地名一对多（关羽 / 关云长 / 关公 / 汉寿亭侯）。**封闭集合，属数据整理，不是 NLP 难题**
- 篇章扩展：回目邻接（三顾茅庐跨 37–38 回）
- 二期不做：Rerank、LLM query 改写

### L5 编排 [部分新增]
- 新工具定义（沿用 `MCPToolDefinition` 形状）+ 系统提示（沿用现有适用域限定的写法）
- **拒答约束**：原文没提到的必须答「演义中未涉及」，不允许先验补全
- **引用注入**：`citations` 由召回元数据填充，**不让模型生成**

### L6 契约 [新增]
- 工具输入 / 输出 schema（保留 `source` 维度，二期接三国志不改契约）
- `/api/chat` 的 `domain` 白名单扩展
- 响应信封维持 `{ code, data, message }`

### L7 评测 [新增]
- 正样本集：现代白话问句，覆盖三层难点
- **负样本集**：演义里没有、影视 / 游戏里有的桥段
- 指标：召回命中率 / 引用忠实度 / **负样本拒答率**
- 复用 BL-015 路由评测基建的思路（固定问题集 + 统计脚本）

| # | 假设 | 不成立的后果 | 怎么验 |

## 5. 探针方案（已批准 2026-09-16）

**排序原则：H2 先做。** 它是生死线，且最便宜（单回语料即可）。H2 不通过，H1 数据再好也没意义。

### 5.1 探针 A —— H2 忠实度（投毒法），语料 = 第五回

**为什么选第五回**：温酒斩华雄是模型记忆中最牢固的一条（演义 / 评书 / 影视反复强化）。**拿最强记忆做对抗样本，结论最硬。**

| 组 | 语料 | 问题 | 观察 |
|---|---|---|---|
| A1 对照 | 原文（关羽斩华雄） | 「斩华雄的是谁」 | 答「关羽」→ 证明链路通（基线） |
| A2 投毒 | 原文改为「张三斩华雄」 | 同一问题 | 见下方三态判定 |
| A3 负样本 | 原文（不含相关内容） | 演义里没有、影视剧里有的桥段 | 答「演义中未涉及」 |

**A2 三态判定**（这才是 H2 的真正读数）：

| 模型回答 | 判定 | 含义 |
|---|---|---|
| 「张三」 | ✅ | 跟随知识库，脚手架成立 |
| 「关羽」 | ❌ | 无视知识库、用记忆作答，**H2 崩，特性不成立** |
| 「原文写的是张三，但实际是关羽」 | ⚠️ | 跟随了，但**越界评论**，违反「只解读不评论」，需 prompt 层加约束 |

第三态最容易漏。模型有「拒绝接受错误前提」的对齐倾向，会主动纠正——而这恰好撞上我们自己划的「不做评论」那条线，必须在探针里显式观察。

**同时必须记录：工具调用率。** 模型可能压根不调检索工具、直接凭记忆作答——这是 H2 的第三种失败形态，和「调了但不跟随」是两回事，要分开统计。现有 `sango_query` 的提示词里已有「必须先调用」的约束，可沿用。

### 5.2 探针 B —— H1 / H3 召回质量，语料 = 5–10 回

单回测不出篇章层问题（跨回事件）。样本覆盖三层：

| 层 | 样本特点 |
|---|---|
| 字面层 | 用字 / 号 / 官爵提问（「云长」「汉寿亭侯」） |
| 语义层 | 现代白话问法（「关羽为什么放走曹操」） |
| 篇章层 | 跨回事件（三顾茅庐等） |

### 5.3 投毒纪律（红线）

1. 投毒语料与正式语料**物理隔离**：独立目录 `data/probe/`，文件名含 `poison`
2. 探针脚本**只读** probe 目录，不触正式语料路径
3. 文件头写明用途 + 「禁止用于生产」
4. 探针语料**可以提交**（可复现的评测资产，将来当回归用例），但目录与命名必须一眼可辨

理由：投毒语料一旦误入正式库，就是**以「原文」的名义给用户喂错信息**——本特性最坏的失败形态。护栏要做在目录结构上，不能靠记性。

## 6. 半文言难点的拆解

先纠正一个期待：**检索难，理解不难。** 模型读文言没障碍，难的是**匹配**——用户用现代白话问，原文是半文言，中间隔一层表达差。

| 层 | 表现 | 对策 | 难度 |
|---|---|---|---|
| 字面层 | 关羽 / 关云长 / 关公 / 汉寿亭侯；地名古今不同 | 混合检索 + 别名表 | **低**（封闭集合，数据整理） |
| 语义层 | 「关羽为什么放走曹操」→ 原文「关云长义释曹操」 | 向量兜语义 | **中**（即 H1） |
| 篇章层 | 三顾茅庐跨 37–38 回 | 召回条数 + 回目邻接扩展 | 中 |

**好消息**：字面层这座山比看上去矮。三国人物的字、号、官爵是封闭集合（几百人），可一次性整理成表，一次投入永久受益。**半文言难点的一半靠一张表解决，不用等模型变强。**
