# 三国演义检索召回质量 · 专题（现状诊断与提升方案）

> 维护：Coco ｜ 创建：2026-09-17 ｜ 状态：**诊断完成 · 已拍板**（2026-09-18 负责人）
> 关联：feat-A004（三国演义解读）／ bug-00003（召回质量不达标）
> 配套：`sango-classics-rag-design.md`（技术方案定稿）／`sango-classics-rag-research.md`（技术调研，§12 探针 A）
> 用途：回答两个问题——① 现状召回为什么差；② 怎么提升。含可复跑评测与分层方案。

## 0. 一句话结论

召回质量低**不是语义理解能力不足，也不是模型不忠实**，而是检索层四处工程缺陷叠加：**别名表没接进检索、chunk 粒度太粗、哈希向量是负资产、注入窗口截掉答案句**。四处都修完，主案例从「排名 #12」变「排名 #2」，24 例基准 @3 从 17/24 提升到 21/24。

其中 P0 三项（别名归一化 / 向量权重 / 阈值死路）**改动小、无新依赖、不违反设计文档 §8「明确不做」**，应优先落地。

## 1. 现象：主案例

domain=sango-novel，输入：

> 孙权遣人向关羽求亲，关羽是怎么回复使者的

实际答「演义中未涉及」。**但原文确有这场戏**——`mcp-server/sango/data/corpus/sanguo-yanyi/073.json` 段 5：

> 瑾曰：“特来求结两家之好：吾主吴侯有一子，甚聪明；闻将军有一女，特来求亲。两家结好，并力破曹。此诚美事，请君侯思之。”云长勃然大怒曰：**“吾虎女安肯嫁犬子乎！**不看汝弟之面，立斩汝首！再休多言！”遂唤左右逐出。

先厘清责任归属：**「演义中未涉及」这个输出本身是正确行为**。设计文档 §1 写明「拒答是验收核心：原文没有的内容必须答『演义中未涉及』」。错的是它判错了「原文有没有」——检索没把这段捞进 top5，编排侧按「无命中」注入 `（检索无命中）`，模型无米下锅，只能拒答。

即：**链路忠实，检索漏召。**

## 2. 诊断方法（可复跑）

纯检索层复现，不经模型、不经 MCP，直接打 `SangoIndex`：

```
index.search('孙权遣人向关羽求亲，关羽是怎么回复使者的', 5)
→ 第1回段11 / 第82回段1 / 第54回段9 / 第16回段7 / 第5回段4
→ 正确答案段（第73回段5）排名 #12（不在召回内）
```

评测基建口径（脚本：`mcp-orchestrator/scripts/probe/recall-bench.mjs`，见 §6）：

- **24 例白话问句**，覆盖称谓鸿沟、成语典故、情节事件三类；
- **答案判定**：人工核对后给每例一个原文正则（如 `/虎女安肯嫁犬子/`），命中该正则的段即「正确答案段」；
- **指标**：正确答案段在召回列表中的排名 → `@1` / `@3` / `@5` 命中率；
- **有效性校验**：正则必须至少命中 1 个段，否则该例剔除（正则与语料表述不符，如「张飞喝断当阳桥」在毛本作「长坂桥」）。25 例候选中剔除 1 例，保留 24 例。

## 3. 现状为什么低（四条根因，均可量化）

### 3.1 称谓鸿沟 —— 主因

query 说「关羽」，原文写「云长」。实测：

| 写法 | 全库 df | 是否出现在正确段（第73回段5） |
|---|---|---|
| 关羽 | 7 | ❌ |
| 云长 | 153 | ✅ |
| 关公 | 128 | ❌ |
| 吴侯 | 45 | ✅ |
| 孙权 | 159 | ✅ |

**正确段里根本没有「关羽」这两个字。** 而词法检索（BM25）只能匹配字面，于是 query 里权重最高的实体名直接落空，只能靠「孙权 / 求亲 / 使者」等残余词凑分。

`data/alias.json` 已由老陈交付（**398 别名 / 148 人物**，`关羽/关云长/关公/云长/汉寿亭侯 → P002`），设计文档 §4 也明确其用途是「兜住 H3 字面层差异」。但实测：

```
mcp-server/sango/src/**  引用 "alias" 的次数 = 0
```

**别名表从未接进检索侧**，只在 orchestrator 侧用于引用校验（`src/citation.ts:93`）。这是最直接、最廉价、收益最大的一环。

### 3.2 chunk 粒度太粗 —— BM25 长度惩罚吃掉正确段

BM25 的分段长度归一化项 `1 - b + b * (dl / avgdl)`（b=0.75）会惩罚长段。现状 **chunk = 整段**，而段落长度分布极不均匀：

| 指标 | 值 |
|---|---|
| 平均段长 | 859 token |
| p50 / p75 / p90 | 671 / 1111 / 1671 |
| 最长 | 4883 |
| > 1000 token 的段 | 412 / 1377（**30%**） |

主案例对比：

| | 段长 | dl/avg | BM25 分 | 排名 |
|---|---|---|---|---|
| 正确段（第73回段5） | 1555 | 1.81 | 24.36 | #11 |
| 误召 top1（第1回段11） | 639 | 0.74 | 38.74 | #1 |

**正确段命中了更稀有的词**（`求亲` df=4、`使者` df=54），**却因段落长 2.4 倍被长度项折半惩罚**，输给了一个只靠「关羽 + 高频单字」凑分的短段。

一句话：**答案句只占长段的一小部分，但整段一起参与打分**，信号被自身长度稀释。

### 3.3 哈希向量是负资产 —— 双重危害

`data/vectors/sanguo-yanyi.bin` 文件头：

```
magic=SNGV  dim=256  count=1377  scheme=0
```

`scheme=0` 即 `build_vectors.py` 中 **BGE-M3 不可用时的降级产物**：FNV-1a 哈希把 token 随机投影到 256 维。它**没有任何语义**，只是确定性的随机投影。危害有二：

**危害一：纯向量兜底路径是死路。** 主案例全库最高 cosine 仅 **0.2694**，而 `MIN_COSINE = 0.3`：

| query | 全库最高 cosine | 纯向量兜底判定 |
|---|---|---|
| 孙权遣人向关羽求亲 | 0.2694 | NO_HIT（死路） |
| 桃园结义 | 0.2795 | NO_HIT（死路） |
| 诸葛亮草船借箭 | 0.1927 | NO_HIT（死路） |
| 赤壁之战 | 0.1808 | NO_HIT（死路） |
| 曹操 | 0.3607 | 可命中 |

设计意图是「词法未命中时走纯向量兜底」，但**阈值高于该向量方案的 cosine 上界，这条路永远走不到**。它同时也是死代码——掩盖了「语义兜底其实不存在」这一事实。

**危害二：融合时注入噪声。** `search()` 的融合打分是 `0.5 * bm25Norm + 0.5 * (cos+1)/2`。实测候选集（1376 段）内：

```
(cos+1)/2:  min=0.4674  max=0.6347  mean=0.5522  std=0.0238
→ 向量项极差 0.1673，乘权重 0.5 后对总分摆动 ±0.0836
→ BM25 归一化项范围 [0,1]，乘权重 0.5 后摆动 0.5
```

向量项几乎是个常量，**且与语义无关**。它不提供任何有效排序信号，只是把 BM25 的判别力砍半。实测代价：加入向量项导致 51138 / 946000 段对相对顺序反转，**正确段从纯 BM25 的 #11 被挤到 #12**。

**这是偏离设计的产物。** 设计文档 §4 明确要 BGE-M3（`build_vectors.py` 里 `try_bge3()` 失败才降级），而 §11 已查明需设 `HF_ENDPOINT=https://hf-mirror.com` 才能下载——即降级是**环境未配置**导致，非有意选择。

### 3.4 注入窗口截掉答案句 —— 二阶陷阱

> 现状更新（2026-09-24）：本条为历史诊断，已随 2026-09-20 注入策略定稿根治——窗口裁剪（`trimFragmentToWindow`）整体删除、前 5 段整段保底注入；main 上 `citation.ts` 已无该函数，B 类「窗口切掉」不再产生。

即使前三条全修好，模型仍可能答「未涉及」。原因在编排侧 `src/citation.ts:158` 的 `trimFragmentToWindow`：

```
锚点 = query 关键词「最后一次出现」的位置
窗口 = [锚点-60, 锚点+关键词长度+60]
找不到关键词 → 取正文开头 120 字
```

主案例实测（正确段正文 778 字）：

```
锚点 key = "孙权"  位置 = 337  → 窗口 = [277, 399)
答案句「吾虎女安肯嫁犬子乎」位置 = 454  → 不在窗口内 ❌
注入内容 = "...其女尚幼，未许字人。某愿往与主公世子求婚。若云长肯许..."
```

**窗口锚在「孙权」，答案句在 454，被切掉了。** 模型看到的片段里只有「诸葛瑾提议求婚」，没有「云长拒绝」——自然答「未涉及」。

量化：24 例基准中，正确答案已被召回 top5 的 21 例里，**5 例（24%）答案句被窗口截掉**：

- 孙权遣人向关羽求亲，关羽是怎么回复使者的
- 诸葛瑾去荆州做什么
- 曹操献刀
- 诸葛亮骂死王朗
- 诸葛亮隆中对

根因是窗口锚点选得太天真：query 里「孙权」出现在前部、答案句在后部，而「最后一次出现」策略对**多实体问句**（同时出现施动者与受动者）必然锚偏。

### 3.5 附：单字 / 标点 token 稀释

分词为「单字 + 相邻双字」（`utils/text.ts`）。query 主案例产出 36 个 token，含标点 `，`（df=1376，几乎全库）与大量高频单字（`人` df=1165、`是` df=813、`回` df=750）。这些 token 的 IDF 接近 0，贡献噪声并拉平区分度。属次要因素，单独修收益有限（实测 @1 无变化），但**与别名归一化叠加时有正向作用**，可在 P1 一并处理。

## 4. 提升方案（分层，含实测收益）

所有数字来自 §6 的评测脚本 `mcp-orchestrator/scripts/probe/recall-bench.mjs`，24 例基准。

| 方案 | @1 | @3 | @5 | 主案例排名 | 改动量 | 新依赖 |
|---|---|---|---|---|---|---|
| **V0 现状**（BM25+哈希向量 / 整段 / 无别名） | 13/24 | 17/24 | 18/24 | #12 | — | — |
| **V1** 纯 BM25（向量权重置 0） | 14/24 | 17/24 | 18/24 | #11 | 1 行 | 无 |
| **V2** V1 + 别名双向归一化 | **17/24** | 20/24 | 21/24 | **#2** | 小 | 无 |
| **V3** V2 + chunk 切窗 250 字 | **17/24** | **21/24** | 21/24 | **#2** | 中（需重建语料） | 无 |

### 4.1 P0 · 别名归一化（收益最大、最该先做）

**做法**：检索侧加载 `alias.json`；**构建期**把语料、**运行期**把 query 都归一化到规范名。规范名取该 PID 下语料内最高频写法，实测 `P002→云长`、`P006→孙权`、`P004→孔明`。

```
query 归一化前: 孙权遣人向关羽求亲，关羽是怎么回复使者的
query 归一化后: 仲谋遣人向云长求亲，云长是怎么回复使者的
```

双向归一化后，query 与语料落在同一称谓空间，「关羽 → 云长」的鸿沟消失。

**实测**：主案例 **#12 → #2**；@1 13/24 → **17/24**，@3 → 20/24，@5 → 21/24。**这是单点收益最大的一项。**

**注意**：归一化必须在**构建期与运行期同时做**，只做一侧等于制造新的不一致（与 `utils/text.ts` 注释里强调的「分词必须两侧逐字节一致」同理）。

### 4.2 P0 · 关掉哈希向量（1 行，立竿见影）

`VEC_WEIGHT = 0.5 → 0`。实测 @1 13/24 → 14/24，主案例 #12 → #11。

理由充分：① 该向量无语义，融合等于加噪；② 纯 BM25 已全面优于现状；③ 不违反 §8「不做专用向量数据库」——反而更贴近「最小版本」；④ 省掉全库余弦计算（`cosineAll` 是 O(n·dim) 全量扫描，也是延迟来源之一）。

**遗留**：`scheme=1`（BGE-M3）分支要保留，供二期恢复真向量时用。

**后续（2026-09-18 Step 2 已完成）**：真向量接线后 `VEC_WEIGHT` 由 0 调回 **1**（chunk 级实测平台期，见 §4.6）。哈希向量编码器 `src/utils/hash.ts` 已随接线删除（零引用，属孤儿代码）；`scheme=0` 分支保留为「无语义向量不参与检索」的显式路径。

**现状更新（2026-09-19 生产接线定参，覆盖前句）**：多路融合改为 BGE-M3×0.6 + BM25×0.3 + 标签×0.1（`sango-index.ts` 常量 `VEC_WEIGHT=0.6` / `BM25_WEIGHT=0.3` / `TAG_WEIGHT=0.1`，见维护记录 2026-09-19 条目）。

### 4.3 P0 · 修 `MIN_COSINE` 死路

现状 `0.3` 高于哈希向量 cosine 上界（0.27），纯向量兜底永不触发。两个选项：

> **2026-09-18 更新**：Step 2 接通真向量后，该阈值**已可被触发**（实测繁体 query `張飛/趙雲/劉備` 词法零命中，靠向量兜底召回，cosine 0.45~0.48 > 0.3，见 §4.6）。但「无关 query 是否被误召回」尚未测——零词法命中的乱码 query（如 `1234567890`）会命中 cosine 最高的段落，属 Step 4 的拒答率范围。

- **推荐**：`scheme=0` 时**直接不启用纯向量兜底**，代码路径显式化（现在是「隐式永远返回 NO_HIT」，属死代码，审查该打回）；词法无命中时直接返回 `NO_HIT_TEXT`，行为更可预期。
- 备选：按实际分布重定阈值（如 0.2）。但哈希向量无语义，调阈值只是让随机结果偶尔漏进答案，**不建议**。

### 4.4 P1 · chunk 粒度改段内窗口（需拍板）

**做法**：不再整段当 chunk，按句边界切 ~200–250 字窗口（保留段号映射回原文）。实测 1377 段 → 3106 chunk，平均 190 字。

**实测**：@3 20/24 → **21/24**，@5 保持 21/24；主案例仍 #2。@1 持平 17/24（段级折算口径下略降，需按 chunk 级重排复测）。

**收益**：直接解决根因 3.2（长度惩罚 + 信号稀释），且**顺带改善注入**——窗口从「切长段」变成「取整 chunk」，`trimFragmentToWindow` 的截断风险同步下降。

**代价**：语料与向量需重建；`Doc` 结构要加 `chunkIndex` / 回指段号的字段；工具出参格式（`【出处】第N回 <回目> · 段M`）保持不变，回目与段号仍取所属段。

**这是设计文档 §4「chunk 粒度：段级（H4 待验）」的决策点，需要负责人拍板。**

### 4.5 P1 · 修注入窗口锚点（小胡，编排侧）

三个候选，建议 ①+③ 组合：

1. **锚定「最稀有 key」**：不取 query 关键词的最后一次出现，而取 IDF 最高的那个 key（如「求亲」df=4 优于「孙权」df=159）。主案例中「求亲」在 420，窗口 `[360, 484)` 可覆盖答案句 454 ✅
2. **多锚点取并集**：所有 key 命中位置各取窗口再合并（代价：注入变长，与「2500→~500 字」的收窄目标冲突）
3. **兜底扩窗**：窗口内不含任何 query 的**双字 key** 时，退化为取正文开头 120 字（现状逻辑）→ 或改取「最靠近段尾」的窗口（答案常在段末）

另需修正：`src/agent.ts:543` 注释写「只取最符合的前 3 段」，代码实为 `.slice(0, 5)`，**口径不一致**，审查项。

### 9.1 A 类根因补充：白话词整词 df = 0（§3.1 同源的另一面）

§3.1 只写了「称谓鸿沟」（`关羽` vs `云长`）。复验发现器物 / 关系类**白话词整词在原文不存在**：

| query 双字 token | 原文 df | 原文实际写法 |
|---|---|---|
| `武器` | **0** | 「造…刀」「点钢矛」 |
| `弟弟` | **0** | 「之弟」（df=21） |
| `望梅` | **0** | 「梅林」（df=1） |
| `嘲讽` | **0** | 「讥」（df=3） |
| `少岁` / `斩六` / `过五` / `三英` | **0** | 白话搭配，原文无此连续串 |

query 双字 token 的原文命中率：#5 **14%**（7 个只中 `张飞`）、#6 **29%**、#12 **33%**。命中率越低，`lexicalHits` 越只靠人物名撑起（#6 一次捞进 1379 段），答案段被淹没。

> **诊断口径提醒**：`tokenize` 只产单字 + 相邻双字 token，**3 字以上的 df 读数恒为 0、不具证据力**。写诊断时勿用 `/丈八蛇矛/` 之类的多字串去测 df。

### 9.3 D 类（bug-00004）：问句要的东西被链路两端剥离

1. 注入视图按 spec §6.3 剥离回目 → 模型上下文里**不存在任何回号**；

**这是需求与 prompt 的口径缺口，不是召回问题。** 详见 `bugs/bug-00004-chapter-number-unanswerable.md`。

### 9.4 E 类（bug-00005）：指针通道对「叙述型答案」结构性失效

`quotes[]` 只抽引号内文本，而《三国演义》大量答案是**叙述句**（无引号）：11 例中 4 例的答案句不在 `quotes[]` 内（`张飞造丈八点钢矛`、`云长造青龙偃月刀`、`孔明奄然归天`、`六将阻关`）。此时该段可用引语只剩无关对话——第 1 回段 `0001:c0011` 的引语表只有 `Q1(3字)：冷艳锯`。

叠加两条：`validateQuotePointers` 的 `pointers.length > 0` 硬条件**逼模型凑一条引语**；引语表无信息量下限（全库 19.0% 引语 ≤8 字）。于是出现「我在此等候多时了！」「四散摆开。」这类引用。**这不是模型不忠实，是校验规则把它逼到这一步。** 详见 `bugs/bug-00005-citation-irrelevant.md`。

### 9.5 复验结论

- 本文档 §4 的修复方案**只解 A 类**；B 类需按 §9.2 改锚点策略，D/E 两类另立 bug。
- 探针 `recall-injection-probe.mjs` 已固化，修复后按类复跑：A 类应清零，B/D/E 各自归零。

## 12. 定点诊断：「华雄是怎么死的」为什么证据段排 #8（2026-09-19，零 LLM）

背景：负责人实测 `index.search('华雄是怎么死的', 10)` 返回 10 条，**证据段**（`云长提华雄之头，掷于地上。其酒尚温。`）排 **#8**。

### 12.1 三路排序对比（同一 query）

| 排序方式 | 证据段排名 |
|---|---|
| 纯 BM25 | #9 |
| 纯向量（BGE-M3） | **#30** |
| 现融合（`0.5*bm25norm + 1*cos`） | #8 |
| RRF（k=60） | #7 |

### 12.2 排除项：BGE-M3 未降级、空间一致 ✅

| 检验 | 余弦 |
|---|---|
| 运行期编码【证据段原文】 vs 向量表存的那条 | **1.000000** |
| 对照（段0 原文 vs 段0 存向量） | 1.000000 |
| 运行期 query vs 证据段存向量 | 0.4266 |

**→ 向量表与运行期编码同空间，无静默降级。** 「语义路径没生效」这一假设**排除**（此前曾列为候选根因，实测证伪）。

### 12.3 重排实验：无效（ColBERT MaxSim）

BGE-M3 ONNX 输出 **`token_embeddings` + `sentence_embedding` 双通道**（`IN: input_ids, attention_mask`｜`OUT: token_embeddings, sentence_embedding`），**无需引入新模型**即可做 token 级重排。

在现融合 top-20 上做 MaxSim 重排：

| | 结果 |
|---|---|
| 证据段 | **#8 → #5**（仍不进 top3） |
| 重排后 #1 | 「华佗在狱…」（ms=0.6941）——与**纯向量 #1 是同一错段** |

**→ 重排对本题无效**：候选集够宽（top-20 已含证据段），但重排信号不足以把它抬进 top3。

> 旁证：纯向量与 MaxSim **同时**把「华佗在狱」排 #1，说明该 query 下向量对主题的判断失准（疑似被「华」字面与「狱/死」语境牵引）。

### 12.4 有效手段：query 改写（实测 #8 → #1~#3）

| query 变体 | 证据段排名 |
|---|---|
| 华雄是怎么死的 | #8 |
| 谁斩了华雄 | #8 |
| 华雄被谁所杀 | #8 |
| **关羽斩华雄** | **#3** |
| **温酒斩华雄** | **#3** |
| **华雄之死** | **#2** |
| **云长提华雄之头** | **#1** |

**→ 把白话问法换成事件词/典故词，证据段直接进 top3。** 这是本题最高性价比的修法，也印证「之前跳过了 query 修改」这一判断。

### 12.5 根因（三条）

1. **证据段不含 query 关键词**：证据段正文**没有「死」字**。query 的「死」token 反而把含「死」的**无关段**（孙坚夜战、祖茂被斩）顶上来。**纯语义题，词法天然打不中。**
2. **实体高频淹没**：`华雄` 出现在夜战 / 潘凤 / 祖茂 / 鲍忠等多段，词法信号被「华雄」共现主导，而非「华雄之死」这一**事件**。
3. **事件在 chunk 层碎裂**：斩华雄 = #4（后人诗「酒尚温时斩华雄」）+ #8（叙述「提华雄之头」），**没有单段含完整事件**。

### 12.6 结论与优先级修订

| 手段 | 实测效果 | 建议 |
|---|---|---|
| **query 改写 / 多路召回** | **#8 → #1~#3** | **P0（本期最高性价比）** |

## 13. 「外置标签 + 权重重排」方案评估（2026-09-19，零 LLM，五探针实测）

### 13.0 结论速览

| 问题 | 结论 |
|---|---|
| 结构可行性（不动向量文件、不重建索引、业务层加权） | ✅ **成立**——向量文件只读、按 chunk 同序，标签表独立可挂，零重建跑通 |
| 用户式公式 `0.6*语义 + 0.3*关键词 + 0.1*标签` | ⚠️ 数学上等于「**现有融合分 × 0.6 + 标签分 × 0.1**」：`0.3/0.6 = 0.5` 与线上 `BM25_WEIGHT/VEC_WEIGHT = 0.5/1` **比例相同**，故未改语义/词法配比；标签相对影响力 ≈ `0.1/0.6 ≈ 17%` |
| `tags` 数组（实体名）加权 | ❌ **几乎无效**——「华雄」题 c 从 0 扫到 2.0 排名**恒定 #8**；51 题搅动率仅 13.7% |
| 标签**文本**当 query / query 扩展 | ✅ **有效**——短事件名 5/7 进 top3，长描述 7/7 |
| 「零成本标签」= chunk 自带回目（`title` 字段） | ❌ **实测无效**（0/7，排名 #115~#1209） |
| 判据 | **证据段是否进 top3**（同 bug-00008 定稿口径，不用参考答案判对错） |

> **一句话**：**结构可行，但「标签」不能是实体名数组——真正起作用的是标签文本作为「白话问法 → 典故/事件词」的语义桥。** 而这座桥的零成本版本（回目）实测不通。

### 13.2 决定性反例：给「含实体名的段」加权 = 加噪声

「华雄是怎么死的」三种标注口径对照（`test/label-weight-probe.json`）：

| `anchorOnly` 只标证据段 | #8 | **#1** | #1 | #1 | **循环论证**：标注时已知答案位置 = 直接把答案告诉系统，**不可作为方案** |
| `entity` 标全部含「华雄」段 | #8 | #8 | #8 | **#8** | **完全不动** |
| `entityVerb` 含「华雄」+ 死亡动词 | #8 | #9 | #9 | **#9** | **更差** |

`entity` 口径下 c=1.0 的 top5（**全是干扰段，证据段纹丝不动**）：

| 排名 | chunk | 判定 | 内容 |
|---|---|---|---|
| #1 | `0005:c0011` | 干扰 | 是夜月白风清…正遇华雄。两马相交…（**孙坚夜战**） |
| #2 | `0005:c0014` | 干扰 | 吾有上将潘凤，可斩华雄（**潘凤出战**） |
| #3 | `0005:c0012` | 干扰 | 祖茂于林后杀出…雄大喝一声，将祖茂一刀砍（**祖茂被斩**） |

### 13.4 ⚠️ 方法论自查：泄漏隔离实验

前两轮探针的事件描述由我参照原文撰写，**可能泄漏原文措辞**，增益有虚高风险。本轮按信息量分档隔离（`test/sango-label-leak-probe.mjs`，n=7）：

| 标签资产 | 成本 | 进 top3 |
|---|---|---|
| A 原 query（基线） | — | 3/7 |
| F **回目**当 query（**零成本**，语料自带 `title`） | 零 | **0/7** |
| G 原 query + 回目（零成本） | 零 | 2/7 |
| B **短事件名**当 query（2–6 字，如「温酒斩华雄」） | 低 | **5/7** |
| C 原 query + 短事件名 | 低 | **5/7** |
| D 长描述当 query（可能泄漏） | 高 | 6/7 |
| E 原 query + 长描述（可能泄漏） | 高 | **7/7** |

**三条关键读数**：

1. **零成本的回目实测无效**（0/7，排名 #115~#1209）。回目是「8+8 对仗古文标题」，含大量与 query 无关的实体（如证据段所在回目「屯土山关公约三事 救白马曹操解重围」），**信号被稀释**。「零成本」这条路走不通。
2. **短事件名有效且不是泄漏**：`温酒斩华雄` 在毛本 **df=0**（原文写「其酒尚温」），**不在证据段正文里**——5/7 的增益来自真实的「白话问法 → 典故词」桥接，**不是原文泄漏**。

### 13.8 深层追问：向量到底有没有在"说话"？（信号强度量化）

§12.2 证明了「向量空间一致」，但**空间一致 ≠ 信号有效**。为回答负责人「是不是 BGE-M3 没生效」的疑问，量化候选集内的向量区分度（`test/sango-vector-signal-probe.mjs`）：

| query | 候选数 | cos 均值 | **cos_std** | cos 极差 | bm25_std | **ρ(cos, bm25)** |
|---|---|---|---|---|---|---|
| 华雄是怎么死的 | 1620 | 0.6613 | **0.0232** | 0.1470 | 0.0852 | 0.2134 |
| 杨修是怎么死的 | 1605 | 0.6897 | 0.0235 | 0.1812 | 0.0878 | 0.3061 |
| 许攸是怎么死的 | 1668 | 0.6936 | 0.0237 | 0.1609 | 0.1030 | 0.2615 |
| 糜夫人是怎么死的 | 2200 | 0.6713 | 0.0243 | 0.2362 | 0.0917 | 0.3230 |
| 颜良是怎么死的 | 1620 | 0.6720 | 0.0236 | 0.1811 | 0.1145 | 0.2694 |
| 孙权遣人向关羽求亲… | 2344 | 0.7341 | 0.0234 | 0.1705 | 0.1417 | 0.5533 |

**两条关键读数**：

1. **向量确实在说话，但声音很小**：`ρ(cos, bm25) ≈ 0.21~0.55`——两路**并非高度重合**，向量提供了独立信号（若向量无意义，ρ 应趋于随机或与 BM25 无关的噪声）。**故「BGE-M3 未生效」再次证伪**。
2. ⚠️ **但向量分被量纲压制**：候选集内 `cos_std` 仅 **0.023**、极差 **0.147**；而 `bm25Norm` 经 min-max 被拉到**满量程 1.0**（std 0.085~0.142）。即：

> **名义权重 `VEC_WEIGHT=1 > BM25_WEIGHT=0.5`，但实际影响力可能相反**——向量分挤在 [0.66, 0.81] 的窄带里，加权后近似于**给所有候选加同一个常数**，对排序的边际贡献被 BM25 的满量程信号淹没。

**这解释了 §13.2 的"加权无效"现象的同源机制**：无论加的是实体标签分还是向量分，只要它**动态范围远小于 BM25**，就无法改变相对序。

## 15. 定点调查：「华雄是怎么死的」664 行答案被 672 行 Guard 改坏（2026-09-19，零 LLM 复现）

现象：模型最终回答 `关羽（云长）温酒斩华雄。[Q2]`（agent.ts:664 后），经 `applyNovelCitationGuard`（agent.ts:672）后被替换为错误兜底。

根因链（全部确定性复现：真实检索 → `toRecallFragments` → `buildInjectionView` → `validateQuotePointers` / `verifyCitation`）：

1. 检索 top5：`0005:c0011`（孙坚夜战）#1、`0005:c0015`（证据：云长提华雄之头）**#2**、`0005:c0014`（潘凤）等。
2. 注入窗口按 query key「华雄」锚定；`c0015` 唯一引语「酒且斟下，某去便来」在锚点窗口之前 → `⟨Q2⟩` 标记被窗口裁掉 → `quotes` map 实得 `{Q1,Q3,Q4,Q5,Q6}`，**无 Q2**。
3. 注入文本出现可见编号空洞（Q1 后直接 Q3…），模型照常输出 `[Q2]` → 指针校验 invalid。
4. 人物断言本可通过（关羽 P002 ∈ 召回集），但指针失败 → 整体走兜底。
5. 兜底 `concludeFallback/buildFallback`（citation.ts:484）取 `fragments[0]` = **`0005:c0011`（孙坚夜战，非证据段）** → 原文片段与结论答非所问，即「结果不对」。

对照：若 Q2 有效，渲染为 `关羽（云长）温酒斩华雄。「酒且斟下，某去便来。」（出处：第5回 …）`——答案本是对的，系被 Guard 兜底替换坏。

- A. qid 改为**窗口裁剪后再连续编号**，消除可见空洞；或将片段引语并入窗口（至少保住 top 片段引语）。
- B. 兜底选段不再盲目 `fragments[0]`，按 query 锚点命中 / 引语覆盖选最相关段（本例应选 `c0015`）。
- C. **已登记 bug-00009**（注入指针 qid 空洞 + 兜底盲取 fragments[0]），与 bug-00006 联动回归。
