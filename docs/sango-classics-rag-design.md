## 1. 目标与边界

- 场景：三国迷问演义情节，只给「原文怎么说」。独立标签，标签内只讨论演义。
- 拒答是验收核心：原文没有的内容必须答「演义中未涉及」，禁止用先验补全。
- 非目标：不做演义 / 正史对比、不评价对错、不做文学批评；最小版本不做 query 改写、不做 rerank、不接专用向量数据库。

## 2. 架构与数据流（D1 定案：检索 = MCP 工具）

- 检索层落点 = **mcp-server 的 MCP 工具**（D1 决策 B，2026-09-16 Coco 需求变更），非 orchestrator 本地工具。
- **单入参定上下文**：检索工具只收一个上下文入参 `source`，系统据此确定本次会话上下文（source=sanguo-yanyi → 注入领域提示词），大模型调度 MCP 工具。
- 数据流（domain=sango-novel 快路径，确定性优先）：
  `用户问句 → 服务端预先调 MCP 工具(source, query, limit=5) → mcp-server 本地检索（向量 + BM25 hybrid，只读离线向量）→ 返回「原文段落 + 出处（回目 / 段号）」→ 按【出处】拆分为独立片段，只取最符合的前 3 段、每段截为「出处头 + 检索词附近窗口」注入 user 消息 → 单次 LLM 生成（避免多轮 tool-use 的 2+ 次串行调用，注入 2500→~500 字）→ 本地引用校验 + 固定格式校验 → 通过出答案 / 不通过兜底（只输出最符合一段 + 结论句）`
- LLM 自主 tool-use 调度保留为兜底路径（非 sango-novel 域 / 模型仍可自行调工具）。
- 多一层 stdio 延迟与调试成本是 D1 已接受的代价；换来二期接《三国志》只换入参与语料、不动编排骨架。

## 3. 契约（L6）

- 工具 `sango_novel_search`（MCP）：
  - 入参：`source`（enum，本期 `sanguo-yanyi`，唯一上下文入参，D4 预留二期 `sanguozhi`）、`query`（白话问句）、`limit`（默认 5）
  - 出参：单条文本块（多段合并，按相关度降序，含全部出处头），条目格式 `【出处】第N回 <回目> · 段M（类型）\n<原文段落>`；无命中返回「未召回到任何原文段落」
- 会话上下文：`source` 单值决定领域提示词（§5 规则集），提示词由系统注入，不靠用户提供。
- 工具隔离（D3）：与 `sango_query` 并存为独立工具——「本标签只讨论演义」是产品承诺，靠工具隔离保证，不靠 prompt 祈祷。

## 4. 检索实现

- 语料：毛本 120 回全本（已定来源，见 §6）；段级切分 + 段落类型（narration / verse / comment）。
- 索引：**BM25 + 向量 hybrid**。向量是离线产物：D2 本地 embedding、D5 Python 侧车只在构建期出向量、线上只读；BGE-M3 下载走 `hf-mirror.com`，实施前设 `HF_ENDPOINT`（见研究 §11）。
- 别名表（封闭集合，数据整理非 NLP）：人名 / 字 / 号 / 官爵 → 规范 ID（P001 起），如 关羽/关云长/关公/云长/汉寿亭侯 → P002；兜住 H3 字面层差异。
- chunk 粒度：段级（H4 待验）；召回片段须自足，模型只归纳不补全。
  → **2026-09-18 已出规范：`sango-corpus-spec.md`（250 字目标 / 400 字硬上限 / 零重叠 / 只在句末切 / 出处改元数据），待负责人拍板。**

> ⚠️ **现状偏差（2026-09-17 诊断，详见 `sango-recall-quality.md` / bug-00003）**：
> 1. 别名表**未接入检索侧**（`mcp-server/sango/src` 零引用），仅在编排侧用于引用校验 → §4 本条未落地；
> 2. 离线向量实为 `scheme=0` 哈希向量（BGE-M3 降级产物），无语义，且 `MIN_COSINE=0.3` 高于其 cosine 上界 → **向量 hybrid 的语义兜底能力实际为零**；
> 3. 段级 chunk 实测拖累 BM25（30% 段超 1000 token），H4 倾向改为段内窗口（**待拍板**）；参数与算法已定稿在 `sango-corpus-spec.md`。

## 5. 生成约束（探针 A 已验证的三件套）

**prompt 限定 ②（2026-09-16 复测通过版，规则原文）**：

1. 回答前必须先调用 `sango_novel_search` 工具检索《三国演义》原文（domain=sango-novel 快路径下系统已预先检索并注入片段，模型直接依据片段作答、不再调工具）。
2. 只依据工具返回的原文作答：人物、情节、数字都必须能在原文里找到。
3. 人名一律以召回原文为准：原文写谁就是谁，不得按常识 / 记忆替换、不得补别名、不得解释成别人。
4. 原文里没有相关内容时，只回复「演义中未涉及」，不得用其他知识补全。
5. 不评论、不纠正、不对比：不得说原文写错，不得提正史 / 影视 / 游戏，不得出现「实际是…」这类转折。
6. 回答格式固定：先写一句结论，再写「引用的原文」（出处：第X回 回目），出处只到回目、不写段落编号；有多段时匹配优先度最高的那一段即可。

**引用硬校验（定稿落地版，2026-09-16）**：校验「答案断言人物集合 ⊆ 召回原文人物集合」，识别链本地化（0 次 LLM）。

流程（以断言「关羽斩颜良」为例）：
1. 答案侧先剥除「（出处：…）」头（回目可能含他人名，如「三英战吕布」→ 吕布，不参与断言扫描）；
2. 用**别名表封闭集合**本地扫描，得到断言人物 ID 集合：关羽 → P002、颜良 → Pxxx；
3. 别名表未命中的名字，退化为**字符串包含**校验（名字出现在召回原文即通过），避免误杀别名表外小角色；
4. 召回原文侧同样本地扫描，得到召回人物 ID 集合。

判定：断言人物集合（ID 级）⊆ 召回原文人物集合（同一流程 ID 化）。不成立 → 判定「引用不成立」→ 走兜底。另做**固定格式校验**（答案须为「结论 + 「引用的原文」（出处：第X回 回目）」格式，出处只到回目）；不满足 → 兜底。

Coco 补充（已落地）：
- a. 检索侧原文同样 ID 化，才能做集合包含判定；
- b. 别名表未命中的次要人物：退化为**字符串包含**校验（名字出现在召回原文即通过），避免误杀别名表外小角色；
- c. v1 只校验人名（与探针一致）；数字 / 情节 / 事件暂靠 prompt 约束，二期再扩；
- d. 别名表是构建期数据交付（老陈），ID 方案 P001 起，按人物规范名去重。

**兜底 ③（产品降级路径，定稿）**：引用校验不过或未检索 → 不做归纳生成，输出「原文片段 + 出处」并补一句结论归纳（如「按原文，斩华雄者系张三」）；**只输出最符合的一段（检索词附近窗口），禁止整段全文刷屏**。探针实测：A2 四连中（3 次自然跟随、1 次兜底兜住），A3 拒答不变，工具调用率 7/7，生死线解除。
