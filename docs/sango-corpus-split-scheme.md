## 1. 段（自然段）

- 段边界 = 原文件行边界。原文本一行即一个自然段，回目行（`第N回 …`）不入段。
- 实测 **2129 段**：正文 1891 段、诗词 238 段。**段号 = 该回正文行序号 = 底本行号**（自检 I9）。
- **不做任何段级合并**（含卷首「词曰：」这类单点例外，全部撤销）：段与原文行一一对应，出处可精确指到行。
- 折行检查：正文 2129 行中以非句末标点结尾的 526 行，末字符分布为「：」299 行（引题行）+ 收尾引号 227 行（引语结尾），**没有一行是真正的折行**，故不需要行合并修复。旧口径把引题行与诗文并成「叙述 + 诗」融合段，正是它必须再做诗句级切分的根因；本方案从段定义上消除该问题。

## 2. 块与切分算法

1. **整段成块**：段长 ≤ CAP → 该段自身即一块（`parent_id` = 自身）。
2. **切句**：段长 > CAP → 按句末标点 `。！？；` 切句；紧跟其后的收尾引号 `” ’ 』 」 》 】` 归前句，不从下一句开头孤悬。
3. **引号感知切点**：候选切点必须处在该位置**引号深度为 0** 之处（`“”` 与 `‘’` 都计入深度）。引号内部的句末标点**不作为切点**——实测全文 29014 处句末标点中有 **14854 处（51%）在引号内**，若不加此约束会把人物引语拦腰截断。
4. **装箱**：按句顺序累积，累积长度 ≥ TARGET 时在**最近一个合法切点**收口；再纳入一句会越过 CAP 时提前收口；全部处理完后，若尾块 < 60 字且并入前块后仍 ≤ CAP，则回并。
5. **只拆不改**：子块按原文顺序拼接后必须逐字等于父段原文（不增删改字）。

例（第 2 回第 3 段，977 字）：切为 3 块 —— 383 + 375 + 219 字。

| 一段一块 | 1993/2129 = **93.6%** |
| 被切父段 | 136 段（均 2.2 子块/段） |
| 块长（全库） | p50 255 / p90 467 / 均值 258 |
| 子块长 | p50 354 / p90 391（不含 1 处引语溢出） |

参数对照（同为引号感知口径、无段级合并）：

| 参数 | 一段一块 | 块总数 | 被切父段 | 块长 p50/p90 | 子块 <60 |
|---|---|---|---|---|---|
| T250 / CAP400 | 75.0% | 2812 | 533 | 238 / 321 | 6 |
| T300 / CAP500 | 87.1% | 2459 | 274 | 251 / 412 | 3 |
| **T350 / CAP600** | **93.6%** | **2290** | **136** | **255 / 467** | **1** |
| T400 / CAP800 | 98.9% | 2159 | 24 | 251 / 521 | 0 |

取 350/600 的理由：
- 「一段一块」是本方案的硬原则，CAP 越大达成率越高；600 在达成率与块长之间取折中，且把切分产生的碎块压到 1 个。
- TARGET/CAP = 0.58 与 250/400 的 0.625 同档，尾块回并仍有效（若 TARGET 逼近 CAP，回并将因越限而失效）。
- CAP 不能无限放大：它直接决定「前 5 条保底注入」的字数上限（5 × CAP，见 §9）；800 以上会让单次注入不可控。

## 4. 诗词、引题行与多行韵文

行级判定口径（次序即优先级）：

1. 独占一行、带诗词标记的引题（`词曰`／`又诗曰`／`又有古风一篇曰` 等，行首至行尾无正文）→ 诗词段；
2. 前一自然段以「：」结尾，且**其段尾引题短语（段末两句：最后一个句末标点之前的尾句 + 其后的收尾，如「……写下八句言语，付与刘璝。其文曰：」）内**包含诗词标记（`诗`／`歌`／`词曰`／`赋`／`吟`／`赞`／`谣`／`偈`／`古风`／`一绝`／`联`／`祭文`／`单道`／`正是`／`为证`／`一首`／`八句`／`十六字`／`口占` 等）→ 该行为诗词段；
3. 赋／祭文／联等多行韵文，其续行（紧跟上一条诗词段、含续行本身逐行级联、不含全角引号，且满足两种对仗形态之一：① 含 ≥2 个分号且各分句 ≤ 9 字，分句按 `，。；！？：` 切；② 分句 ≥ 4 且各分句 ≤ 5 字，分句按 `，。；！？：、` 切（含顿号））→ 诗词段；
4. **引语内的标记不计**：标记落在未闭合引号内时不判为诗词（引语中转述的歌谣属叙述内容）；
5. **标记只在引题短语（段末两句）内匹配**：第 2 条不得用「前一段任意位置出现标记」判下一段，否则 5 处书信／表／诏段会被误标为诗词（第 37 回 20 段、第 45 回 16 段、第 57 回 19 段、第 61 回 19 段、第 96 回 6 段）。

处理方式：诗词段**整段成块、不切**，超长不适用 CAP。全书 238 个诗词段：中位 32 字、p90 64 字、最长 416 字（第一百二十回末尾《古风》）。

**引题行（`role=引题`）**：行尾「：」+ 行内无句末标点 + **≤ 12 字** —— 全书 19 处（如「唐妃亦作歌曰：」7 字、「先是东南有童谣云：」9 字；含 2 处短文书引题「又与袁尚书曰：」7 字、「造流马之法云：」7 字）。它们**照常出块、段号 = 行号不变**，但**不进检索索引**（BM25／向量都不收录）：这些 4~12 字短语无独立语义，进索引即噪声，只在所属上下文组被命中时作为引子随组给出。

**含叙述前缀的引题**：同判据但 > 12 字 —— 全书 2 处：第 91 回第 2 段（52 字，「维大汉建兴三年秋九月一日……阴魂曰：」，是祭文开篇）、第 118 回第 14 段（33 字，「司马昭览毕……随后降封艾诏曰：」）。它们有独立语义，按普通段处理（`role=主体`，正常进索引）。

不设 `comment` 类型：原文仅 2 处含「评曰」，实为人物「**辛评**曰」（第 32、33 回对白），旧口径的 comment 类型即此处误判。

## 5. 父子契约与注入闭包

块记录字段：`chunk_id`、`parent_id`、`seq_in_parent`、`type`（`正文`／`诗词`）、`text`、`char_count`、`group_id`（§6）、`role`（`主体`／`引题`，§4）。一段一块时 `seq_in_parent` = 1。

ID 格式（契约）：`parent_id` = `{source}:{回号4位补零}:p{段号4位补零}`（段号 = 该回正文行序号，从 1 起，回目行不计）；`chunk_id` = `{parent_id}:c{seq_in_parent 两位补零}`。例：第 2 回第 3 段被切成 3 块 → `sanguo-yanyi:0002:p0003` / `…:c01`／`…:c02`／`…:c03`；一段一块即 `…:p0003:c01`。`char_count` = 该块字符数（码点计数）。

- **检索以块为单元**（不做父段扩展检索，避免长段 BM25 长度归一化被稀释）；`role=引题` 的块不参与打分。
- **出处与引用原文**：出处由服务端按父段渲染（回目 + 段号 = 行号），引用原文按注入字段回填，模型不生成。
- **命中后的注入闭包**（按序补全，统一去重）：① 父段补全 —— 命中块所属父段被切分时补同父其余子块（未切段零成本）；② 上下文组补全 —— 按 `group_id` 补同组其余块（§6）；③ 事件／典故行补全 —— 命中表行时按 `chunkIds` 注入（上限见 §9）。
- 同一块在出参中只出现一次（块级去重）；闭包按上述顺序展开，预算不足时逆序裁尾（先保命中块，再保父段，再保组，最后事件行）。

## 6. 上下文组（`group_id`）

**用途**：表达段与段之间「割断就会召回不全」的体裁／结构相邻关系，保证命中任一块即整组给全。它与表驱动的事件／典故组正交 —— 上下文组是**回内的注入单元**，事件／典故组是**跨回的语义聚合**，两者不互相顶替。

**生成规则**（回内连续段区间；两条边取并集）：
- G1 相邻两段的 `type` 都是 `诗词` → 同组（引题行与其诗、祭文各段、连续赞／诗歌）；
- G2 段尾以「：」结尾 → 与下一段同组（不限行内有无句末标点；覆盖引题行、含叙述前缀的引题、第 20 回段 2「……令宗正卿宣读曰：」这类叙述引题）。

**实测读数**：281 组 / 覆盖 602 段（28.3%）；组字数 p50 296 / p90 623 / p99 934 / max 1069；组内段数 p50 2 / max 6；组内块数 p50 2 / max 6。

**组定义表**：`mcp-server/sango/data/corpus/context-groups.json`（与 `events.json`／`allusions.json` 同目录、同形制：`meta` + `rows`）。它是上下文组的**单一真源**，人工维护、可直接编辑：

```json
{ "meta": { "schemaVersion": 1, "source": "sanguo-yanyi" },
  "rows": [ { "groupId": "ba4b18df", "chapter": 20, "segStart": 9, "segEnd": 10 } ] }
```

- 每组一行：`groupId`（裸 ID，8 位随机十六进制）+ `chapter` + `segStart`／`segEnd`（段区间，段号 = 底本行号）。
- 只存**不可派生**的字段（ID、回、段区间）；组字数、组内块数等派生量不落表，需要时现算 —— 因此改切分参数（TARGET／CAP）不必动此表。
- 引用口径：表内写裸 ID；语料块字段写全 `{source}:xxxxxxxx`（与 `chunk_id` 同族）；段清单「组」列写裸 ID。
- 用段区间而非 `chunkIds` 做引用：块切分是派生的，段内切块一变整表就要重写；段区间才是稳定键。

**调整方式**：改一行就是改一个组 —— 组 ID 是表里的字面量，不动它就永不改变；新增组加一行（发一个新的 8 位 ID）；拆并组改行或删行，作废 ID 在 `meta` 下留注记防重用。**没有发放状态机、没有认领匹配、没有阈值。**

**派生关系**：`chunk.group_id` 由本表按段区间 join 得出（生成物、可重建），构建因此是纯函数（表与底本同为输入）。

**代价**：多一张需长期维护的表（人工可读、diff 友好）；手工可编辑即可能改错，靠 §7 自检兜底。

**注入上限**：单组 **1200 字** —— 依据是实测最大组 1069 字，1200 即规则层零拆分。超限时按「命中块 → 同组按段序前后扩展」装箱至 1200 封顶，其余以「同组另有 N 块 / 段号区间」形式给编排侧，需要时二次取。

**不承载的语义**：主题相关性不进 `group_id` —— 如第 20 回「献帝回宫 → 写密诏 → 董承拆袍见诏 → 密诏内容 → 董承读毕」整链（段 7~11，2186 字）由事件表行承载（`events.json` 已有「衣带诏」行）。规则判不出「读后反应算不算同一单元」这类语义相邻，不硬编码成不可复核的启发式。

## 7. 不变量（构建自检，任一不满足即构建失败）

| # | 不变量 |
|---|---|
| I1 | 拼接一个父段的全部子块 = 父段原文（逐字相等，含标点） |
| I2 | 正文块 ≤ CAP；诗词块整段不切；超 CAP 的块必须命中白名单（§10） |
| I3 | 所有切点落在句末标点（。！？；）之后，且该处引号深度为 0 |
| I4 | 块 ⊆ 父段；子块有序；`chunk_id` 可由 `parent_id + seq_in_parent` 回放 |
| I5 | 块内引号配平（段内校验，不跨段继承）；例外段见 §10 |
| I6 | 不存在跨段合并、跨段混装（块只能来自单一父段） |
| I7 | 尾块 < 60 字必须已回并前块，或登记为「并入即超 CAP」的例外 |
| I8 | 类型只能是 `正文`／`诗词`；不出现 `comment` |
| I9 | 段数 = 底本正文行数（2129），且段号 = 行号（逐段比对原文） |
| I10 | 组内段号连号、不跨回；`context-groups.json` 内 `groupId` 全表唯一、区间两两不重叠 |
| I11 | `role=引题` 的块数 = 19，且不出现在任何检索索引取值中 |
| I12 | 注入闭包（父段／组／事件行）内无重复块 |
| I13 | 语料 `group_id` 与 `context-groups.json` 逐组一致：表中每行在语料中都有对应块、每个带组的块都能回表，且区间吻合 |

构建产物需输出统计：段数、块数、一段一块数、被切父段数、子块数、块长分位、<60／<80 字数、白名单命中数、组数、覆盖段数、组字数分位、引题块数。

## 8. 与现行口径的差异（明确弃用的机制）

| 现行机制 | 本方案 |
|---|---|
| 行合并（`SENTENCE_END` 折行修复） | 弃用：本语料无真折行，合并只会造融合段 |
| `MERGE_LEAD_LINES` 卷首引题合并（第 1 回「词曰：」） | 弃用：段号 = 行号是硬口径，不做单点例外 |
| `refine_verse()` 诗句级切分 | 弃用：诗词已是独立自然段，无需段内再切 |
| 同回连续 `narration` 跨段装箱 | 弃用：块不跨段（保出处唯一、保住 A/B 可解释性） |
| `MIN=150` 跨段碎片回并 | 改为父段内尾块回并（阈值 60） |
| `comment` 类型 | 弃用（见 §4） |
| 评测判据「750／1000 字覆盖」 | 换成按当前注入规则复算的覆盖率（见 §11） |

## 9. 注入侧影响

当前线上注入规则（`mcp-orchestrator/src/citation.ts`）：`INJECT_HEAD_GUARANTEE = 5` 前 5 段整段保底、不裁剪；`INJECT_TOTAL_BUDGET = 2000` 第 6~10 名按预算依次纳入，超预算丢整段、不裁剪；`INJECT_TAIL_FALLBACK_ENABLED = true`。

本方案给注入带来的增量有两处，均纳入预算口径：
- **上下文组补全**：单组上限 1200 字；组字数中位 296 字，命中块本身通常已占其中一部分，增量期望约为单块的三分之一。
- **事件／典故行补全**：行内 `chunkIds` 上限口径按 **3000 字**预留（当前最长行 2186 字 —— 第 20 回「衣带诏」整链 7 块），不按块上限 600 字压。

## 11. 验证方式

1. **构建自检**：I1~I13 断言 + 统计输出（与 §3／§6 读数逐项对齐）。
