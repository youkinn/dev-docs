# feat-A013 缓存技术调研：Node.js 应用层 query→answer 语义缓存

> 调研对象：存疑 #1（Node.js 末尾淘汰机制可行性）、存疑 #2（清除时机 / 手动清除是否立即生效）。
> 日期：2026-09-23｜作者：Coco｜用途：支撑 `requirements/feat-A013-query-cache.md` 技术要点。

## 结论（先行）

1. Node.js 应用层 LRU 完全可行，成熟方案现成，无需重型基础设施。
2. 热缓存 = 进程内 LRU；记录 / 统计走现有 SQLite（better-sqlite3，总台已有）。
3. 手动清除立即生效（内存结构直接操作）；不需要定时清除任务——容量驱逐 + 版本失效已覆盖，重启即清空（MVP 接受）。

## 一、末尾淘汰（LRU）可行性：方案对比

| 方案 | 命中提升 | 驱逐 | 依赖 / 运维 | 结论 |
|---|---|---|---|---|
| `lru-cache`（npm，零依赖） | `updateAgeOnGet: true` 即命中置前 | `max` 超限按 LRU 驱逐；原生支持 `ttl` | 一行依赖，API 成熟 | 首选 |
| 自实现 Map 重插（`delete`+`set` 刷新顺序） | 天然支持 | 插入超限删首个 key | 零依赖，几十行 | 可行，条目 ≤1k 足够 |
| Redis | 无原生「命中置前」语义（需自维护访问序），且需引入 Redis 基建 | `maxmemory` 是近似的、非逐条精确 LRU | 新基础设施 + 每请求网络往返 | 不选（MVP） |
| SQLite 表 | 自实现 `last_access_at` 刷新 | 自实现 | 已有依赖；热路径写库有 IO；语义命中需全表取向量算 cosine | 不作热缓存，用作 `cache_logs` 审计 |

要点：

- 需求 b「命中后提升到缓存队列前面」= `lru-cache.updateAgeOnGet`（或自实现 Map 的 delete+set），标准语义，无技术障碍。
- 需求 c「阈值 + 末尾淘汰」= `max` 容量上限 + LRU 驱逐，标准能力。
- 本缓存特殊性在「语义命中」而非容器：命中判定是对新 query 的 embedding 逐一与条目 embedding 算 cosine（阈值 0.85）。条目 ≤1k、维度几百~几千时全扫为毫秒级（1k × 768 维 ≈ 76 万次乘加），LRU 容器本身不构成瓶颈。

## 二、清除策略（存疑 #2）

- **多久清一次：不需要定时清除。** 三个失效机制按需组合：
  1. 容量驱逐（`max` 上限，命中置前使热点保值）；
  2. 版本失效（语料 / 提示词 / 路由版本变更时全量清空，防升级后命中旧答案）；
  3. 可选 TTL（`lru-cache` 原生支持；本期默认不做——语义缓存追求跨会话复用，TTL 过短伤命中率，待数据说话）。
- **手动清除：立即生效。** 进程内结构直接清空 / 删条目，下一个请求即失效，无需重启、无异步延迟。「清除缓存」按钮 = 调后台 API → 内存结构 clear。
- **重启**：内存缓存随进程清空（非持久化）。MVP 接受：冷缓存只影响命中率、不影响正确性（未命中 = 走原链路）；跨重启持久化列为非目标，需要时再评估 Redis / SQLite 化。

## 三、语义判定实现落点（调研倾向，不拍板）

- 复用 A004 本地离线 embedding（mcp-server sango 侧）：与检索同源同维度，语义口径一致、零在线费用。
- 落点二选一：a) mcp-server 暴露轻量 embedding 工具（总台调用，多一次 MCP roundtrip，毫秒级）；b) 总台内置同款模型（进程内直调，最快，但引入模型加载与依赖）。倾向 a（边界清晰、复用现成设施、总台零新依赖）；最终由接口文档确认。

## 四、风险与已知约束

- 错误答案固化：命中跳过检索与生成，正确性依赖首次答案——缓解见需求文档（命中解释 / 开关 / 全清 / 单条删除），属设计边界，特此声明。
- 多实例：内存缓存各实例独立（命中率与数据不一致）；当前单实例，不阻塞。
- 与 provider 侧 prompt 缓存（A011/A012 `cached_tokens`）是两个层次：前者省「同一前缀重复传输」，后者省「整个问答重复生成」，互补不替代。

## 五、验证方式

- LRU 语义单测：小容量（如 max=3）注入 4+ 条 → 断言驱逐顺序与命中置前（测试即文档）。
- 清除立即生效冒烟：写入 → 手动清 → 同 query 再问 → 断言走 LLM 并重新写缓存。
- 命中链路耗时实测：embedding + 全扫 < 500ms 目标（对比 LLM 现况 7~17s），真实数据验收时读数。
