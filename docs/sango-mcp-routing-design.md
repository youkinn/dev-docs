# 问答系统 MCP 路由完整方案

---

> **演进注记（feat-A011，2026-09-22）**：路由判定流程已演进——auto 首轮由「带工具自主决策」改为「无 tools 轻量分类出编号（1 / 2 / 99）」+ 服务端按编号预调注入，快路径与生成轮一律不携带工具定义；天气能力已下线（总台不再装配 weather server），路由目标枚举移除 `weather`。本文按现状更新描述，旧「四分类含天气 / 带工具自主决策」段落标注废止。接口口径见 `mcp-orchestrator/api/feat-A011-prompt-slimming.md` §二 / §五。

## 一、方案总览

### 核心设计思想
**「确定性优先 + 轻量分类兜底」**——能用前端交互和本地规则搞定的，坚决不消耗 LLM 推理资源；当前三层都无法明确判定时，由 auto 首轮「无 tools 轻量分类出编号（1 / 2 / 99）」兜底，服务端按编号预调工具并注入，生成轮不再携带工具定义（2026-09-22 演进：原「单 Agent 带工具自主决策」路径废止，见 §2.4；最低限度减少 LLM 调用产生的 token 与耗时）。

### 整体四层路由架构
```
用户请求
    ↓
第一层：前端标签判定（domain 显式意图，0ms）→ 命中直接路由（快路径）
    ↓ 未命中
第二层：本地关键词硬匹配（规则拦截，<1ms）→ 命中直接路由（快路径）
    ↓ 未命中
第三层：向量相似度匹配（风云三国高置信识别，仅 auto，<100ms）→ 命中直接路由（快路径）
    ↓ 未命中
第四层：轻量分类出编号（auto 首轮，无 tools，~500ms）→ 服务端按编号预调工具并注入
    ↓
生成轮（无 tools，域提示 + 注入片段）→ 人名别名归一化（sango 检索）→ LLM 生成答案 → 返回用户
```

### 各层覆盖率预估
| 层级 | 覆盖率 | LLM 调用 | 耗时 |
|-----|-------|---------|------|
| L1 前端标签 | 60%~80% | 无 | 0ms |
| L2 关键词匹配 | 10%~20% | 无 | <1ms |
| L3 向量匹配 | 5%~10% | 无 | <100ms |
| L4 轻量分类（auto 首轮，无 tools） | <5% | 有（轻量分类，无 tools） | ~500ms |
| **最终答案生成** | 100% | 有 | 2~3s |

**整体收益**：95% 以上的请求路由环节零 LLM 消耗，总响应时间稳定在 3 秒以内，路由相关 Token 成本降低 90% 以上。

## 二、路由分层设计（2026-09-16 定稿；2026-09-22 按 feat-A011 演进：L1 已落地、L2/L3 已实现、L4 改为轻量分类出编号）

### 第一层：前端标签判定（优先级最高）【已落地：/api/chat 的 domain】
**触发条件**：用户点击顶部标签页（风云三国 / 三国演义；天气已下线，不再提供）

- 后端直接读取前端传参的标签标识，跳过所有后续路由判断，直接绑定对应 MCP 和专属系统提示词
- 设计依据：用户主动点选标签 = 明确告知使用场景，是最高优先级的意图信号，零延迟零误判
- 现状：`/api/chat` 的 `domain` 白名单为 `['fengyunsanguo', 'sango-novel']`（weather 已移除，传入 `domain=weather` → 400，文案 `domain 字段仅支持 fengyunsanguo、sango-novel`）

### 第二层：本地关键词硬匹配【已实现】
**触发条件**：用户未选择标签，进入后端自动路由

维护三个工具的专属关键词字典，命中任意关键词直接路由：

| 工具 | 专属关键词列表 |
|-----|--------------|
| 三国演义 MCP | 字、籍贯、官职、生卒年、原著、章节、第几回、原文、生平、演义、三国时期、罗贯中 |
| fengyunsanguo_query（MCP server） | 风云三国、MOD、骑砍、招募、答题、好感度 |

### 第三层：向量相似度匹配（风云三国高置信正向识别）【已实现】
**核心定位**：只做风云三国招募题的高置信正向识别，不做任何反向推定

1.  **预处理阶段**：将当前 88 道风云三国招募题全部向量化，存入内存
2.  **实时处理阶段**：用户提问生成向量后，与全量题库计算余弦相似度
3.  **阈值判定规则**：
    - 相似度 ≥ 0.9 → 高置信命中游戏招募场景，直接走 fengyunsanguo_query
    - 相似度 < 0.9 → 不做任何猜测，直接进入第四层轻量分类（仅 auto；域锁定 / L1 / L2 命中走快路径，不经过本层与第四层）
4.  **重叠题校正逻辑**："字、籍贯"这类重叠度极高的关键词，标记为模糊关键词，命中后不直接路由到三国演义，先进入向量层做二次判定，避免把游戏招募题误分到文史场景

### 第四层：轻量分类出编号 + 服务端预调注入【已实现（feat-A011）】
**触发条件**：`route === "auto"` 且 L3 向量识别未命中（域锁定 / L1 / L2 命中直接走快路径，不经过分类轮）

第 1 次调用改为轻量分类（**无 `tools`**）：只发 `[system: 分类提示] + [user: 用户问题]`，模型仅输出编号。编号表（`CLASSIFY_ROUTE_IDS`）：

| 编号 | 域 | 服务端预调 | 注入 | 生成轮 |
|------|-----|-----------|------|--------|
| `1` | 原著检索域 | `sango_novel_search`（source=sanguo-yanyi, query=用户问句, limit=10） | 【已检索到的《三国演义》原文片段】 | sango-novel 域提示 |
| `2` | 题库问答域 | `fengyunsanguo_query`（text=用户问句） | 【已检索到的题库候选】 | fengyunsanguo 域提示 |
| `99` | 自由模式兜底 | 无 | 无 | 自由对话提示 |

- 编号约定：`1`~`98` 预留给能力域（加能力 = 加编号分支，架构不变）；`99` 恒为自由兜底。
- 分类兜底取向：**不确定时倾向选 `1` / `2`**，不轻易落 `99`（宁可多一次服务端预调，不错失能力域）。
- 输出解析：取回复文本**首个数字**（`/^\d+/`）；无法解析 / 非 `1`/`2`/`99` → 按 `99` 处理，不重试。
- **预调注入时序**：分类轮输出编号 → 服务端按上表预调工具并注入 → 生成轮固定 `[system: 域提示] + [user: 用户问题] + [system: 注入片段]`（99 无注入），**一律不携带工具定义**。
- 分类轮日志 `stage = "classify"`（`LlmStage` 为 `"classify" | "generation"`）。
- **废止注记**：原「L4 大模型四分类兜底（1 天气 / 2 风云三国 / 3 三国演义 / 4 无关）」为 2026-09-16 历史设计，已由本编号表取代；天气下线后不再有天气分类。

## 三、工具调用与答案生成

路由确定目标工具后，进入答案生成流程：

### 1. 调用对应工具
- fengyunsanguo_query（MCP）→ 检索游戏招募题库答案 + 游戏属性数据
- 三国演义 MCP → 检索 120 章 JSON 知识库相关章节内容
- 天气能力已下线（feat-A011）：总台不再装配 weather server，无对应工具调用

### 2. 人名别名归一化（已实现：alias.json）
在三国演义检索前，先做本地人名映射，全程不消耗 LLM 资源：
- 已实现：`mcp-server/sango/data/alias.json`（别名 → 人物 ID，P001 起按规范名去重，关羽 → P002）
- 关羽 / 云长 / 关云长 / 美髯公 → P002；诸葛亮 / 孔明 / 诸葛孔明 / 卧龙 → P005
- 实现方式：本地哈希字典 O(1) 匹配

### 3. LLM 生成最终答案
将工具返回的原始数据 + 对应场景的系统提示词 + 用户原始问题，一起发给大模型生成白话文答案。

**各场景系统提示词核心约束**（feat-A011 起拆为域提示常量：能力二 5 条 / 能力三 6 条 / 自由对话；快路径与生成轮一律不携带工具定义，模型不再自主调工具）：

| 场景 | 系统提示词核心约束 |
|-----|------------------|
| 风云三国问答（能力二 5 条） | 1. 收到用户提问后必须先调用 fengyunsanguo_query 工具（参数 text 传用户原始问题），取回候选题目；2. 先理解用户问题含义，再判断候选中哪条含义相同（问法不同但含义相同即对应）；3. 判定出对应题目后，只输出该题答案原文，不输出题干、选项字母、解释或任何多余文字；4. 候选中没有含义对应的题（含只是字面相似、含义不同），只回复「题库未收录该题，请换个问法」；5. 禁止使用题库之外的知识作答、补充或改写答案 |
| 三国演义问答（能力三 6 条） | 1. 依据系统已注入的《三国演义》原文片段作答（快路径 / 编号 1：服务端已预检并注入片段，模型不再调工具，生成轮无 `tools`）；2. 只依据注入的原文作答：人物、情节、数字都必须能在原文里找到；3. 人名一律以召回原文为准：原文写谁就是谁，不得按常识/记忆替换、不得补别名、不得解释成别人；4. 原文里没有相关内容的问句，必须回答「演义中未涉及」，禁止用先验知识补全；5. 不评价、不纠正、不对比：不得说原文写错，不得提正史/影视/游戏，不得出现「实际上是…」这类转折；6. 回答格式固定：先写一句结论，然后写「引用的原文」（出处：第X回 回目），出处只到回目、不写段落编号，有多段时匹配优先度最高的那一段即可。服务端另做本地引用校验（答案人物 ⊆ 召回人物，本地别名表扫描，0 次 LLM）+ 固定格式校验，不过 → 兜底（原文片段 + 出处 + 结论句） |
| 自由对话（编号 99 / 无关问题） | 不调用任何工具、不带工具定义，按自由对话提示凭自身知识作答，简洁清楚；不套用题库话术，不确定时直接说明 |

## 四、风云三国题库维护方案（后面再做）

> 现状注记（feat-A005，2026-09-20）：当前风云三国检索为运行期确定性哈希向量（256 维，内存即时计算、不落盘；题库 88 题）。本节为题库规模扩充时的落盘向量库备选方案，未实施。

### 增量更新机制
不需要每次题库变化都全量重新向量化，采用增量追加方式：

1.  **新增题目**：出题机生成新题后，只对新题目单独向量化，直接追加到现有向量库末尾，毫秒级完成
2.  **修改题目**：只替换对应题目的向量条目，不影响其他题目
3.  **删除题目**：只移除对应题目的向量条目
4.  **持久化**：定期将全量向量保存到本地文件，服务重启时直接加载，不用重新计算

### 性能边界与升级标准

暴力遍历全量向量做相似度计算的性能天花板：

| 题库规模 | 单次检索耗时（单核 CPU） | 方案适用性 |
|---------|------------------------|-----------|
| 100 题 | <1ms | 完全适用，无压力 |
| 1,000 题 | ~5ms | 完全适用 |
| 10,000 题 | ~50ms | 完全适用，用户无感知 |
| 100,000 题 | ~500ms | 建议升级为 HNSW 近似索引 |

**结论**：当前 88 题起步，就算出题机疯狂生成到 1 万题，暴力遍历方式都完全够用，不需要提前上重型向量数据库。

## 七、方案优势总结

1.  **成本极低**：95% 的请求路由环节零 LLM 消耗，只有答案生成环节调用一次 LLM（auto 首轮多一次无 tools 轻量分类）
2.  **响应极快**：路由环节总耗时 <100ms，加上答案生成，整体稳定在 3 秒以内
3.  **准确率高**：前三层确定性逻辑准确率 100%，只有不到 5% 的请求交给大模型判断
4.  **维护简单**：关键词和题库都可以配置化更新，不需要改核心代码
5.  **扩展性强**：二期三国志功能完全预留，零侵入即可快速上线
