# 标签体系使用边界（sango 检索）

> 随 feat-A014 定稿。本档只记决策与理由、契约、风险与已知约束、验证方式（技术文档不写流水账）。

## 1. 现状与评审结论

| 项 | 现状 | 结论 |
|----|------|------|
| 数据 | event.json 1731（战役 766 / 政治事件 599 / 人物之死 335 / 谋略计策 203 / 结盟外交 129 / 人物之生 138 / stray「典故事件」2）；story.json 334（115 个典故名）；duel.json 39；去重 1780 / 2344 chunk | LLM 一次性批量生成、未经评审；四类事件判定主观不可信；生 / 死 / 单挑客观可验证；典故有通行名、数据质量较好 |
| 本意 | 标签 = 给同类 chunk 统一打标加权，让同一事件 / 典故的整组 chunk 一起浮现，抵消 chunk 碎片化带来的 LLM 断章取义 | 本意成立；碎片化问题真实（chunk 细 + 召回分散） |
| 机制 | 字符级 bigram 倒排第三路召回，命中 chunk 统一 +0.1（TAG_WEIGHT）；死亡意图置顶（排序两级，组整体置顶、组内按段序）；诊断 hitLabels | 死亡意图置顶实测有效（华雄 #8→#1）；0.1 加权在宽匹配面上无增益（几百 chunk 同吃 +0.1 = 平移） |
| 噪声 | 类型前缀随 bigram 成片命中：之战 610 / 政治 586 / 之死 268 / 登场 98 chunk | 噪声主源是数据面（主观四类 + 类型前后缀），删四类 + 索引剥壳后匹配面收窄为精准小集 |

## 2. 决定（2026-09-24 负责人拍板）

1. **数据保留**：人物之生 / 人物之死 / 武将单挑（duel.json）/ 典故（story.json）；删除 event.json 四类（战役 / 政治事件 / 谋略计策 / 结盟外交）与 stray「典故事件」。
2. **机制保留**：第三路召回与 0.6 / 0.3 / 0.1 加权（含 TAG 0.1）不动；死亡意图置顶保留；诊断 hitLabels 保留。
   - 理由：0.1 加权是「同类 chunk 脱颖而出」的工具，删除则标签失去意义（负责人定）；无增益的实测结论来自宽匹配面（主观四类 + 类型前后缀），数据治理后匹配面收窄为精准小集，0.1 恢复「整组提升」语义。
3. **匹配面治理**：索引层「标签剥壳」——tagPostings 只入库剥离类型信息后的文本（去 `人物之生-` / `人物之死-` 前缀与 `登场` / `之死` 后缀，duel 保留 `A-B`，story 原文即终型）；死亡意图字典与 hitLabels 仍用原始文本，数据文件不动。
4. **校验**：本特性内完成（静态校验脚本 + 人工抽检 + 补标修正）。
5. **另立特性（不在本特性）**：典故 / 事件名定向置顶与组内选段、别名表扩展（地名 / 典故名 / 战役名→规范名，即「白话问法→典故名」桥）。

## 3. 使用边界契约

- 标签定位：① 第三路召回 +0.1 的**定向提升源**（同类分组「脱颖而出」）；② 死亡意图置顶的**规则数据源**；③ 诊断 hitLabels 的**可解释性来源**。
- 匹配面约束：禁止类型前后缀、宽泛事件词进入 tagPostings（剥壳保证）；新标签必须精准小集，禁止实体共现式标注（§13.2 潘凤-华雄教训）。
- 0.1 的能力边界：只对「分数差距 ≤ 0.1」的组有效；gap 更大的案例由死亡意图置顶 / BM25 / 向量兜底，三者并存、互不替代。
- 未来接入前提：典故定向置顶、组内目标段优先、别名桥等均需先立特性评审，禁止绕过本契约直接改检索逻辑。
- 新增 / 修改标签：必须通过 §6 验证（静态校验 + 人工抽检），口径以 §4 为准；发现错漏走 bug 票。
- 降级策略：标签文件缺失 / 非法仅告警，降级为无标签路由，不影响启动与既有 BM25 / 向量检索。

## 4. 数据契约（保留四类）

- event.json：仅 `人物之生-XX登场`（首次出场才记，只记首次）与 `人物之死-XX之死`（叙事时间死亡事实，追忆 / 葬礼 / 提及不记）；人名用 alias 规范名。
- duel.json：`武将单挑-武将A-武将B`；A = 先发起 / 先出场者；多人围攻不算（三英战吕布不记）。
- story.json：仅典故名本体（无前缀、无解释、无句号）；通行名自带标点豁免（如「既生瑜，何生亮」）。
- 索引剥壳口径（**索引层**剥壳，数据文件与解析不动）：tagPostings 入库文本 = 人物之生 / 人物之死 → 纯人物名；duel → `A-B`（保留对阵信息）；story → 原文。原始标签文本保留，供 deathByPerson 解析与 hitLabels 回读。死亡 / 登场语义由结构（deathByPerson 人名词典）承载，不依赖倒排里的「之死 / 登场」字样。实测对照：华雄族问法命中面不变（2→2），「华雄之死」269→5 且死亡段 `0005:c0015` 仍在，三顾茅庐 20→20。
- **边界归属（Coco 决定）**：索引层剥壳与死亡意图链路（`search/intent.ts` 正则 + `deathByPerson` / `deathSpeechByPerson` 解析）无依赖；「华雄之死 → 死亡段 `0005:c0015` 置顶 #1」在剥壳前后行为一致。死亡语义由结构承载、不依赖倒排文本；后续变更该口径须经架构评审。
- 死键（chunkId 不在语料）必须为 0；多标签 `|` 分隔，去重。
- 校验脚本：`sango/scripts/`（静态规则，零 LLM），四类全量校验 + tagPostings 类型 bigram 断言。

## 5. 风险与已知约束

- 0.1 提升受 gap 限制：gap > 0.1 的组（如华雄类）0.1 无效，依赖死亡意图置顶兜底；非死亡类 gap 大案例仍可能抢救不回（已知，另立特性的定向机制解决）。
- alias 仅覆盖 148 个规范名：小人物（管亥 / 纪灵等）若在 alias 覆盖外，死亡意图路由对其问法可能失效，退化普通排序（不阻断检索）。
- 死亡覆盖不全：「许攸之死」类缺漏会漏救该人为问句，补标走 bug 票按本契约口径执行。
- 白话问法 → 典故名缺口（«刘备三请诸葛亮» → 三顾茅庐）：无别名桥前典故标签路只对直呼典故名的问法生效（另立特性）。

## 6. 验证方式

- 静态校验脚本全过（格式 / 死键 / 只记首次 / 人名口径 / 命名一致性 / tagPostings 无类型 bigram）。
- 10 例复刻（`sango-tag-route-audit.mjs`）at 0.6 / 0.3 / 0.1 权重：证据段 top3 / top10 不劣化。
- 死亡意图回归：华雄类「怎么死的」问法保持 #1（置顶机制未受影响）。
- 人工抽检：生 138 / 死 335 / 单挑 39 / 典故 334 抽样对照原文。
