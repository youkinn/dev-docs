# A018 事件表 · AI 初审任务书

> 分工：Coco 出包 → 负责人用外部免费 AI 初审（不占项目 LLM 预算）→ 负责人二审 → Coco 硬校验、落表、验收结论。
> 输入源：`docs/三国演义.txt`（仓库内已跟踪，原书全文 120 回）。
> 初审只产「事件识别」，不产 chunkId；段位定位由脚本按 事件名→回目录→chunk 完成，零 LLM。

## 输入
- `docs/三国演义.txt`：原书全文（120 回）。
- `test/events/input-回目清单.md`：120 回索引（回号 | 回目），由 txt 抽取生成，回号口径以此为准。

## 提示词（复制以下整段给外部 AI）

# 角色
你是《三国演义》事件标注员，为我们的问答检索系统构建「事件表」。用户提问都是白话口语（例如「关羽是怎么斩的华雄？」「三顾茅庐是哪几回？」），系统要用事件表把问句定位到原书回目，所以事件要按「用户会怎么问」来识别，而不是按文学评论来写。

# 输入
- 附件一《三国演义.txt》：原书全文，共 120 回；每回以「第X回 回目」行开头，部分行前有「正文」二字。
- 附件二《input-回目清单.md》：120 回索引，每行「回号 | 回目」。回号一律以附件二为准。

# 任务
逐回通读原文，识别「事件」，输出一张总表。要覆盖全部 120 回，不许漏回。

# 事件怎么算
满足以下任一条件就记一条：
1. 名场面 / 有固定专名的：温酒斩华雄、过五关斩六将、三顾茅庐、舌战群儒、草船借箭、借东风、空城计、七擒孟获、六出祁山等 → 类型 L1
2. 用户会问的情节：某一战怎么打的、某人被谁所杀、某城被围或攻破、某计如何实施、谁和谁结盟或翻脸等 → 类型 L2
3. 人物登场与死亡：重要人物首次登场、人物死亡（战死、病逝、被杀）→ 类型 L3

# 类型定义
- L1 专名事件：有约定俗成专名的事件
- L2 情节事件：无固定专名、但用户会问的完整情节
- L3 登场与死亡：登场、死亡、正式出场

# 抽取规则（全部必须遵守）
1. 以原文为准：只抽原文实际出现的情节，严禁凭记忆补充正文没有的内容
2. 宁多勿漏：拿不准的先记下，宁可多也不漏；后续有二审统一删
3. 只做事件识别：不写原文段落号、不写原文片段、不写 chunkId；回号一律以附件二清单为准
4. 问法要全：每条事件至少写 1 个白话问法；覆盖口语说法、常用别名、正反两种问法，多个问法用顿号分隔
5. 跨回事件合并成一行，回号写「起–止」，如 037–038
6. 类型只填 L1 / L2 / L3
7. 每回至少产出 1 条，120 回全覆盖

# 输出格式
Markdown 表格，列固定为 5 列，不许改名、不许加列：
| 回号 | 事件名 | 白话问法 | 类型 | 备注 |

- 回号：三位数字（如 005），跨回写 037–038
- 事件名：用约定俗成的说法，一人多事分多条
- 白话问法：口语问句，多条用顿号分隔
- 类型：L1 / L2 / L3
- 备注：人物别名、易混淆点、跨回说明、关键参与人物；没有就写「无」

# 示例（示例只是格式示范，正式输出必须覆盖全部 120 回）
| 回号 | 事件名 | 白话问法 | 类型 | 备注 |
|------|--------|----------|------|------|
| 005 | 温酒斩华雄 | 关羽怎么斩的华雄？温酒斩华雄是怎么回事 | L1 | 关羽成名事件 |
| 025 | 关羽斩颜良 | 颜良是谁杀的？关羽斩颜良发生在哪一回 | L1 | 白马之战，与斩文丑紧邻 |
| 037–038 | 三顾茅庐 | 三顾茅庐是哪几回？刘备怎么请到诸葛亮的 | L1 | 跨 37、38 两回 |

# 截断处理
如果单次输出放不下 120 回，允许分多次输出，但每次都要带完整表头；全部输出合并后必须覆盖 120 回，回号不许重复、不许遗漏。最终只回一份合并后的完整表格。

## 产出与回放
- AI 输出回放到 `test/events/first-pass.md`（或 first-pass.csv / first-pass.json）。
- 5 列固定：回号 | 事件名 | 白话问法 | 类型 | 备注。

## Coco 侧硬校验（verify，零 LLM）
1. 表头 5 列，无改名、无加列
2. 回号均在 001–120（跨回用 a–b 区间），无超范围
3. 120 回全覆盖，回号无重复
4. 事件名、白话问法非空；类型仅 L1/L2/L3
5. 总行数在预期区间（全集约 400–600 条，宁多勿漏）
