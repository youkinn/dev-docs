# A018 事件表 · 初审材料生成任务书

> 分工：Coco 出包 → **Coco 在项目链路内生成初审材料**（负责人 2026-09-28 拍板：不用外部免费 AI、不做人工逐条）→ 负责人二审（查漏补缺）→ Coco 脚本段位定位 + verify 硬校验 + 落表 + 验收结论。
> 背景：外部免费 AI 初审产物已证实偷工减料并弃用；初审材料改由 Coco 生成，构建期 LLM 调用按 AGENTS.md 原则 14 报备登记（生成轮 ≤6 次 + 复核 ≤1 次）。
> 输入源：`docs/三国演义.txt`（仓库内已跟踪，原书全文 120 回）。

## 输入
- `docs/三国演义.txt`：原书全文（120 回）。
- `test/events/input-回目清单.md`：120 回索引（回号 | 回目），由 txt 抽取生成，回号口径以此为准。

## 产出与回放
- 生成结果回放到 `test/events/first-pass.md`（或 first-pass.csv / first-pass.json）。
- 5 列固定：回号 | 事件名 | 白话问法 | 类型 | 备注。
- 只产「事件识别」，不产 chunkId；段位定位由脚本按 事件名→回目录→chunk 完成，零 LLM。
- L3 死亡 / 登场以 `mcp-server/sango/data/corpus/tags/event.json`（人物之死 / 人物之生）派生为准：逐 chunk 展开为（回号, 事件名）一行、不折叠、不造跨回（tags 侧无跨回口径）；手工初审只补 tags 未覆盖条目。派生脚本：`test/events/derive-l3-from-tags.mjs`（零 LLM）。

## 事件怎么算（满足任一即可记一条）
1. 名场面 / 有固定专名的：温酒斩华雄、过五关斩六将、三顾茅庐、舌战群儒、草船借箭、借东风、空城计、七擒孟获、六出祁山等 → L1
2. 用户会问的情节：某一战怎么打的、某人被谁所杀、某城被围或攻破、某计如何实施、谁和谁结盟或翻脸等 → L2
3. 人物登场与死亡：重要人物首次登场、人物死亡（战死、病逝、被杀）→ L3

## 类型定义
- L1 专名事件：有约定俗成专名的事件
- L2 情节事件：无固定专名、但用户会问的完整情节
- L3 登场与死亡：登场、死亡、正式出场

## 填写口径
- 按用户提问识别：白话口语（「关羽是怎么斩的华雄？」「三顾茅庐是哪几回？」），不按文学评论写。
- 覆盖全部 120 回，不许漏回；宁多勿漏（全集预期 400–600 条）。
- 跨回事件：回号列保持单回（起回），备注标注跨回区间。

## Coco 侧硬校验（verify，零 LLM）
1. 表头 5 列，无改名、无加列
2. 回号均在 001–120，无超范围（跨回事件回号列保持单回、备注标注跨回）
3. 120 回全覆盖，回号无重复
4. 事件名、白话问法非空；类型仅 L1/L2/L3
5. 总行数 ≥ 400（宁多勿漏）；分层以全集为准（当前 L1≈90 / L2≈150 / L3≈480）
