# feat-A001: 天气助手页面

> 特性号：feat-A001
> 状态：草稿
> 作者：Coco
> 涉及项目：mcp-web, mcp-orchestrator, mcp-server
> 日期：2026-09-11

## 背景

用户通过自然语言查询美国城市天气。当前链路：mcp-web（Vue 前端）→ mcp-orchestrator（LLM 编排）→ mcp-server（MCP 天气工具）→ weather.gov NWS API。页面已有基础聊天交互，但错误体验粗糙、有几个文案 bug。

## 目标

- [ ] 用户能用自然语言查询美国任意城市的天气预报和预警
- [ ] 错误场景下有明确、可操作的提示（区分"服务没启动"和"API key 无效"）
- [ ] 页面文案自洽，没有残留的历史引用

## 非目标

- 不支持美国以外城市（天气数据源限制）
- 不做对话历史持久化（刷新即清空）
- 不做多轮对话上下文记忆

## 验收标准

1. [ ] 输入英文城市名或天气问题 → 返回天气预报或预警信息
2. [ ] 消息为空时发送按钮 disabled
3. [ ] 超过 300 字符自动截断提示
4. [ ] orchestrator 未启动 → 提示"无法连接到后端服务，请确认已启动"
5. [ ] API key 无效 → 提示"模型接口认证失败，请检查 API_KEY 配置"
6. [ ] 请求超时 → 提示"请求超时，请稍后重试"
7. [ ] 加载中显示 spinner + "正在查询天气工具..."
8. [ ] 空状态文案与页面实际布局一致（无"左侧"提法残留）
9. [ ] 页面底部提示引导用户输入英文城市名
10. [ ] 助手回复可一键复制

## 接口影响

| 接口 | 说明 |
|------|------|
| `POST /api/chat` | 已有，不需要改 |
| `GET /api/health` | 已有，前端可用来做启动检测（目前未用） |
| `GET /api/tools` | 已有，前端可用来展示可用工具（目前未用） |

## 技术要点

- LLM 编排在 orchestrator 侧，前端只负责展示
- 错误信息由 orchestrator 返回 `{ message }` 格式，前端直接展示
- 目前 orchestrator 错误处理不够细分（所有错误统一 500），需要老陈改进

## 已知问题（本次需修复）

1. 空状态文案"试试左侧的快捷提问"——左侧面板已删除，文案残留
2. orchestrator 错误统一返回 500，前端无法区分"服务挂了"和"key 无效"
3. `getErrorMessage` 中"无法连接到 mcp-orchestrator"提示没有告诉用户怎么解决

## 风险 & 开放问题

- 天气数据完全依赖 weather.gov，该服务不可用时无降级方案（暂不处理）
- DeepSeek API 偶尔返回非标准 tool-call 格式（已在 agent.ts 中做兼容处理）
