# feat-A002: 风云三国知识问答（武将招募题库）

> 特性号：feat-A002
> 状态：已定稿
> 作者：Coco
> 涉及项目：mcp-web, mcp-orchestrator
> 日期：2026-09-14

## 背景

《风云三国》（骑马与砍杀：战团 mod）招募武将时需回答问题。玩家希望在现有聊天界面中快速查答案、练习答题，减少游戏内招将答错的成本。题库以 JSON 知识库维护，简单处理，不改动现有天气链路。

## 目标

- [ ] 聊天框上方提供「天气」「风云三国」单选标签（antd Tag），未选择时为普通问答（默认）
- [ ] 选中「风云三国」后，顶部出现「风云三国常见服务」模块（右上角 X 可关闭），内含「问题查询」「随机一题」两个子模块
- [ ] 选定子模块后，聊天框内展示当前模式标签（「风云三国-知识问答」或「风云三国-随机一题」），进入对应模式
- [ ] 风云三国-知识问答：用户问问题 → LLM 理解问法 → 从题库精确取答案返回；未收录 → 提示未收录
- [ ] 风云三国-随机一题：随机出题（题目 + A-D 选项，不含答案）→ 用户作答 → 判题（对错 + 正确答案）；支持「答案」指令；不走 LLM
- [ ] 天气模式：行为与现状一致（LLM + 天气 MCP 工具）
- [ ] 普通问答（无标签）：通用 LLM 对话，不调用天气工具与题库
- [ ] 题库启动时校验（坏行跳过、不挂服务）；判题支持全角/半角、大小写、标点归一化

## 非目标

- 不做按武将筛选题目（等题库补充 generalId 后再扩展）
- 不做计分、成就、连续测验
- 不做会话持久化（内存会话，重启即清）
- 不做通用多库管理（v1 固定单知识库：JSON 文件 + 进程内存索引）
- 随机一题的出题与判题不经过 LLM；知识问答的答案取自题库原文，LLM 仅理解问法、不生成答案内容
- 不做离线 embedding / 向量检索 / Top3 候选兜底（v1 不引入 embedding 方案，知识问答交给 LLM 理解）
- 不做「题干+答案」一条消息判定，随机一题分两步（先出题、再作答）
- 前端不做选择题按钮，保持纯文本对话
- 不做按内容自动路由，模式 / 子模块由用户显式选择

## 验收标准

1. [ ] 聊天框顶部有「天气」「风云三国」两个标签，单选；未选择时聊天为普通问答
2. [ ] 点击「风云三国」后，顶部出现「风云三国常见服务」模块（右上角 X 可关闭），内含「问题查询」「随机一题」两个子模块；选定子模块后聊天框内展示对应的「风云三国-知识问答」或「风云三国-随机一题」标签
3. [ ] 知识问答：`scenario=sango` + `service=knowledge`，输入「夏侯惇的字是什么？」→ 返回「夏侯惇的字是：元让」（答案来自题库）
4. [ ] 知识问答：题库未收录的问法 → 提示未收录，不硬编答案
5. [ ] 随机一题：`scenario=sango` + `service=random`，输入「随机一题」→ 返回随机题目与 A-D 选项（不含答案），记为当前题
6. [ ] 随机一题：同一 `sessionId` 下输入「元让」/「A」/「ａ」→ 答对提示；输入错误答案 → 「答错了」+ 正确答案
7. [ ] 随机一题：输入「答案」或「这题选什么」→ 返回当前题正确答案
8. [ ] 随机一题：无有效会话时作答 → 提示先发送「随机一题」
9. [ ] 不传 `scenario`（普通问答）→ 走 general，不调用天气工具与题库
10. [ ] 天气模式（`scenario: "weather"`）行为与现状一致，MCP 未连接返回 503
11. [ ] 题库某行缺字段或答案不在选项中 → 启动时跳过并告警，服务正常启动
12. [ ] 非法 `scenario` / `service` 值 → 400；其余错误码与 `{code,data,message}` 信封沿用现有约定

## 接口影响

| 接口 | 说明 |
|------|------|
| `POST /api/chat` | 扩展 body：`scenario`（general / weather / sango，缺省 general）、`service`（knowledge / random，scenario=sango 时必填）、`sessionId`（随机一题判题会话） |
| `GET /api/tools` | 不变；sango 为本地知识库，不进 MCP 工具列表 |
| 前端 | 标签单选 + 常见服务模块（可关闭）+ 子模块选择 + 聊天框内模式标签 |

## 技术要点

- orchestrator 新增 `src/sango.ts`：题库加载（环境变量 `SANGO_QUESTION_FILE`，默认 `data/sango-questions.json`）、启动校验、归一化匹配、判题、随机出题
- `server.ts` 按 scenario + service 分发：general → Agent（无工具）；weather → Agent（MCP 工具）；sango+knowledge → Agent + sango 查询工具；sango+random → SangoService 本地规则
- 知识问答：Agent 提供 sango 查询工具（输入问法 → 返回命中题目与答案），LLM 负责理解问法并组织回复，答案内容由题库规则提供、不生成；未命中 → 未收录提示
- 随机一题：纯本地规则（随机出题 / 判题 / 查答案），不经 LLM
- 判题归一化：全角→半角、去空白与标点、小写；接受选项字母（A-D）或选项文本
- 会话：内存 `Map<sessionId, 当前题>`，TTL 30 分钟，仅随机一题使用，单实例可接受
- 前端：antd Tag（checkable）单选；选中「风云三国」后顶部展示常见服务模块（X 关闭），选定子模块后聊天框内展示模式标签；切换模式时清空该模式聊天记录并重置 sessionId

## 风险 & 开放问题

- 会话状态为单实例内存实现，重启 / 多实例部署会丢（v1 可接受）
- 知识问答依赖 LLM 理解问法，题库未覆盖或问法歧义时可能未收录或误匹配 → 未收录提示兜底，后续可按需补充同义词表
- 题库固定选项顺序（与游戏内一致）；若后续需要乱序，判题按文本、展示需映射
- 已定：切换模式即清空聊天记录并重置 sessionId（防止上一题“幽灵状态”）；常见服务模块 X 关闭仅收起快捷入口，不影响已选子模式
