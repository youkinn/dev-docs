# feat-A010: 原文查看（A4 阅读器）+ 日志页筛选增强

> 特性号：feat-A010
> 状态：已提测
> 作者：Coco
> 涉及项目：mcp-web（前厅，主要）、mcp-orchestrator（总台）、mcp-server（器坊）
> 日期：2026-09-22
> 关联：feat-A004（演义 RAG，chunkId / 回目来源）、feat-A007 / A008（日志页）、feat-A009（候选分数表 `chunkId` 列，本特性点击入口）、feat-A006（引用卡片，聊天侧入口）

## 背景

feat-A009 让后台能看到「召回了哪几条、分数怎么算」，但**看不到 chunk 的原文**：候选分数表给出 `sanguo-yanyi:0063:c0021`，负责人仍无法核对召回内容对不对 —— 验证链路断在最后一米。当前只能去 `mcp-server/sango/data/corpus/` 手工翻 JSON，且前端/后台都不该接触语料目录。

同时日志页检索成本偏高：只能按 traceId 精确查或按时间范围翻，缺「按项目快速筛」；要拿某条记录的 traceId，得先展开明细再手动选中复制。

## 目标

- [ ] 日志页新增「项目」筛选：全部 / 天气 / 风云三国 / 三国演义
- [ ] 日志页列表末尾新增「操作」列（「复制」按钮，复制该行 traceId）
- [ ] 原文阅读器组件（A4 / PDF 预览观感）：按回展示原文，逐 chunk 标片段号，支持 chunkId 定位、上下回跳转、按回号跳转
- [ ] 两处入口复用同一组件：日志页候选分数表 `chunkId`；聊天页每条引用原文末尾的「查看原文」按钮。两处都定位到具体片段
- [ ] 阅读器底部区域可配置：聊天页「查看原文」入口不展示底部区域（「上一回/下一回」+ 回号跳转），日志页入口保留（负责人 2026-09-22 验收补充）

## 非目标

- 不生成 / 不导出 PDF（只做观感）
- 不做全文检索、跨回搜索、笔记 / 标注
- 不改召回算法、不动语料与切分（原文来源即现有 chunk 语料）
- 不给 `citations[]` 加 `chunkId`：聊天侧定位用 `citation.text` 与整回原文精确匹配，零契约变更
- 不做移动端 / 小屏适配
- 不改 `/api/chat` 与编排侧业务逻辑
- 原文弹框只针对三国演义：天气 / 风云三国无原文语料，不给入口（日志页「项目」筛选仍保留三项）
- `domain` 为空的历史记录不单列「未知」选项，只在「全部」中出现
- 不预留第三处入口

## 组件入参契约

| 入参 | 必填 | 说明 |
|------|------|------|
| `chapter` | 是 | 回号，1~120 |
| `chapterTitle` | 否 | 回目。接口必然返回 title，入参仅用于接口返回前的占位（避免标题闪烁）；拿不到就不传 |
| `chunkId` | 否 | 传入则滚动定位并高亮该片段；不传则停正文顶部 |
| `showFooter` | 否 | 默认 `true`；传 `false` 不渲染底部区域（「上一回/下一回」+ 回号跳转）。聊天页「查看原文」入口传 `false`，日志页入口不传 |

- 打开方式与关闭回调由小叶自定（`v-model:open` 或 `open()` 方法均可），不额外加业务入参
- 组件名建议 `SangoChapterReader.vue`，放 `src/components/`
- 片段号列只读显示短号；复制 chunkId 走「候选分数」表末尾「操作」列的「复制」按钮
- 不显示段号 `segFrom/segTo`（聊天页已无段号概念，阅读器不叠）

## 技术要点

- **原文链路**：前厅 → 总台 HTTP → 器坊 MCP 工具。feat-A004 约定「orchestrator 不读器坊语料目录」，本特性沿用；器坊复用现有语料加载路径按回取 chunks，不新建索引
- **新工具对模型不可见（硬约束）**：模型可用工具取自 `agent.ts:804`（`this.options.tools ?? transport.listTools()`），器坊注册 `sango_novel_chapter` 后会被自动带进模型上下文，模型会拿它当检索用（拉整回原文、烧 token）。总台须做「模型可见工具白名单」过滤，后台 HTTP 通道直调不受影响；具体机制由接口文档定
- **数据量**：单回语料 25~38KB，整回一次返回；不做分页返回，前端按回缓存、不预取
- **`domain` 口径**：`/api/chat` 由前端传 `domain`，quiz 固定 `fengyunsanguo`；`domain` 为空的记录只在「全部」里出现
- **剪贴板不依赖部署协议**：`navigator.clipboard` 只在 https / localhost 可用，前端实现降级（`document.execCommand('copy')` + 临时 textarea 兜底），http / https 都能复制；是否上 https 属部署议题，不在本特性
- **A4 观感**：固定 210mm 纸宽 + 长纸滚动，不做真实分页；底部区域显隐由 `showFooter` 控制，纯前端行为（无接口变更）
- **语料 schema v2**（`chunks[]`），阅读器片段号取 chunkId 尾段（`c0021`），不展示段号
- **页面上有三套「号」，不要混**：
  - 回答**正文**里的 `¹` = 总台渲染（`citation.ts:482 renderAnswerWithCitations`，`agent.ts:608` 调用），编号 = 该片段在回答里首次出现的顺序，只在本条回答内有效
  - 引用**卡片左上角**的 `¹` = 前厅复算（`WeatherView.vue:52` 渲染 `badge`，`buildCitationGroups()` 按 `toSuperscript(index + 1)`），总台不下发该字段、契约里没有 —— 两边靠复算对齐，属已知约束
  - 语料的号 = `chunkId` 尾段、段号 `segFrom/segTo`、`quotes[].qid`（Q1/Q2，工具出参已不带，只回 `offset/len`）
  - 阅读器的片段号与上述三套都无关，弹框内不渲染引用角标

## 风险 & 开放问题

- **模型可见工具白名单的落地方式**：总台过滤 vs 独立调用通道，由接口文档给方案（必须解决，否则模型会乱调）
- **`citation.text` 匹配定位**：同回内两 chunk 文本完全相同（重叠 0，概率极低）会落到第一处；匹配不到则停在正文顶部
- **数据量**：并发打开多回时以按回缓存兜住
- **卡片角标未入契约**：属已知约束，接口文档中记明；如需修另开票
