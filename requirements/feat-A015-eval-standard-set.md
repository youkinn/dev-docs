# FEAT-A015: 三国演义 RAG 回归标准集

> 特性号：FEAT-A015
> 状态：定稿（2026-09-25）
> 作者：Coco
> 涉及项目：dev-docs（标准集、验证脚本与结果）、mcp-server（sango 检索与评测执行接口）、mcp-web（执行结果页面）
> 日期：2026-09-25

## 背景

- 回归需要一个可信、可重复的基准。既有评测集由程序批量生成、问题质量未经验证，不能作为回归基准，本需求整体重建：评测集、验证脚本、判定口径全部现场新定。
- 判定口径（本需求唯一口径，不引用任何旧口径）：判对 = 正确证据段进入检索结果 top5（生产上前 5 整段保底注入，故不调 LLM、不评答案文本）；6–10 为过渡兜底、单列统计；其余为未命中。判分由脚本按评测集证据列的原文锚自动定位证据段完成，对检索结果只读分析、不写回评测集。
- 标准集 = 110 题（11 类 × 10），每次回归用同一验证脚本执行并将结果落档，用于定位切片 / 检索 / 重排 / 拒答等改动带来的召回变化。

## 目标

- [ ] 标准集 110 题：人物 / 地名 / 战役 / 典故 / 器物 / 身体部位 / 官职爵位 / 数字称谓 / 事件关系 / 死亡 / 拒答，11 类各 10 题；每题含标准答案与证据（回目 + 原文片段），逐题对语料核验可定位
- [ ] 全新验证脚本（零 LLM，直连 mcp-server 的 `SangoIndex.search()`）：逐题执行检索，按证据锚（证据列原文片段）在候选中定位证据段并判定是否进 top5，输出类别汇总与 JSON 快照
- [ ] 首次基线：执行脚本，结果回填评测集「回归测试结果」表，快照按 `feat-A015-日期` 命名落盘（同日可多次执行）
- [ ] 后续每次回归：同一脚本重跑，新快照与基线对比，作为回归结论依据
- [ ] 执行结果页面（mcp-web）：表格 + 「执行」按钮 + 类别展开明细 + 分布图表 + 历史快照列表，点击执行即跑评测并展示结果，可切换查看任意一次历史执行

## 非目标

- 不评价答案文本、不引入任何 LLM 判定（批量 LLM 评估由负责人另行决策）
- 不做切片 / 检索 / 重排 / 拒答策略的任何改进（本需求只测不改）
- 不沿用旧评测集、旧验证脚本、旧判定口径，旧描述一律不出现在本需求文档
- 不做判定口径扩展（三段判分固定）；执行接口仅本地 dev 可用，不注册为 MCP 工具
- 不修改检索结果 / 不写回评测集 / 不做任何影响线上检索行为的变更（纯分析）

## 验收标准

1. [ ] 标准集落地并逐题通过原文核验（回目与原文片段可在语料复现定位），110 题齐全
2. [ ] 验证脚本可重复执行：两次执行判定结论一致；判分 = 脚本按证据锚（证据列原文片段）在候选中的匹配 rank（1–5 / 6–10 / 其余），输出含每题与类别汇总
3. [ ] 首次基线已落档并回填评测集结果表；快照命名形如 `feat-A015-YYYY-MM-DD-HHMM.json`，支持同日多次执行
4. [ ] 负责人抽查 ≥3 题：题面答案与证据对应、脚本判分与人工核对一致
5. [ ] 需求文档与标准集内无旧评测集 / 旧脚本 / 旧口径引用
6. [ ] 页面「执行」按钮触发后台接口完成一次回归，表格展示本次摘要（类别 / 总题数 / 通过数 / 失败数 / Top5命中数 / 通过率）；执行中按钮禁用、异常可见
7. [ ] 类别行可展开查看该类别每题明细（序号 1–110 / 问题 / 参考答案 / 期望命中 / 排名 / 状态）；图表点击可联动展开对应类别
8. [ ] 历史快照列表展示多次执行记录（runId / 时间 / 摘要），点击任意一条切换表格、展开明细与图表为该次数据；通过率趋势折线展示历史执行整体对比；类别分布与通过率趋势两图置于独立「图表」标签页（整页共「类别汇总」「图表」两标签，标签选择跨刷新持久化）
9. [ ] 明细列表上方提供筛选下拉：全部 / top5（rank 1–5）/ top10（rank 6–10）/ top10+（rank>10 或未召回），筛选后明细与图表跟随变化

## 接口影响

- 对外（生产）无接口契约变化；页面与执行仅限本地 dev
- sango 进程内新增本地 dev HTTP 接口（仅绑定 127.0.0.1，不注册为 MCP 工具）：
  - `POST /dev/benchmark/run` → 执行评测，返回 `{ runId, summary, results }`（同步返回，执行中页面等待）
  - `GET /dev/benchmark/latest` → 最近一次快照
  - `GET /dev/benchmark/history` → 快照列表（runId / 时间 / 摘要）
- 评测判定逻辑收敛到 sango 内单模块，dev-docs 命令行脚本与 HTTP 接口共用，禁止两份实现漂移
- 原文查看复用前厅既有 `SangoChapterReader`（A010 原文查看）；如按 chunkId 精确定位章节内原文缺接口，由老陈在 sango 补一个只读的 chunk 原文入口（仅本地 dev）

## 执行流程（负责人确认）

1. 页面点「执行」→ 调 sango 本地 dev 接口 `POST /dev/benchmark/run`
2. 接口读评测集（兰台 `docs/sango-rag-regression-benchmark_v0.1.md`，当期全部题）→ 逐题调 `SangoIndex.search()` 返回 50 条候选（chunkId + 排名），引索常驻，二次执行秒级
3. 候选结果返回页面，候选列「查看」按钮打开候选弹框（全部候选：短 chunkId 去 {source}: 前缀 + 回目），点条目复用前厅既有 `SangoChapterReader` 组件（feat-A010 产物）打开原文核对
4. 候选弹框内点条目打开原文查看核对（展示用）；判分不依赖人工确认
5. 判分：脚本按证据锚（证据列原文片段）在候选中的匹配位置判定：rank 1–5 判对（top5）、6–10 兜底、>10 或未进候选为未命中
6. 结果写本地快照 `results/feat-A015-日期`（JSON + summary md，不入库），页面展示汇总表 / 展开明细 / 图表 / 筛选 / 历史对比

分析产物仅存本地。

## 技术要点

- 判分基准 = 证据锚（证据列引号内原文片段）在检索候选中的匹配 rank；匹配顺序：正文优先、回目锚限回次之；证据列是判分必需，无证据锚的题跳过并单独计数
- 判定输出三类：top5（rank 1–5 判对）/ 6–10（兜底）/ 其余（>10 或未进候选，未命中）
- 运行：`node --experimental-strip-types test/standard-set/feat-A015-verify.mjs`（含向量模型加载约 12 秒）
- 结果落 `test/standard-set/results/feat-A015-YYYY-MM-DD-HHMM.json`；类别汇总回填评测集「十三、回归测试结果」表
- 页面字段口径：通过数 = Top5 命中数（summary.top5）、通过率 = top5 / 总题数；失败数 = 兜底(6–10) + 未命中；明细展开按三等分展示排名与状态
- 图表：类别 ×（通过 / 兜底 / 未命中）堆叠柱状图 + 整体通过率，点击柱/图例展开对应类别明细
- 图表跟随当前选中快照切换；另提供通过率趋势折线（按 runId 依次对比，直观反映回归升降）
- 页面布局：整页分「类别汇总」（汇总表 + 展开明细 + 历史快照）与「图表」（类别分布 + 通过率趋势）两个标签页；标签选择跨刷新保持（sessionStorage）；「图表」标签未激活时容器尺寸为 0，不绘制，切回时重建并重绘
- 候选交互：候选列仅「查看」按钮，弹框列出该题全部候选（短 chunkId + 回目），点条目打开 SangoChapterReader 原文
- 历史快照来源 = `results/` 目录已有 JSON（含手工投放），页面不区分来源，仅作展示
- 明细筛选按 rank 区间：top5 = 1–5、top10 = 6–10、top10+ = >10 或未召回（rank=0），默认「全部」
- 执行复用 sango 常驻索引（进程内已 `load()`），二次执行秒级；并发执行串行化，重复点击幂等（同一次运行只落一份快照）
- 快照与汇总文件沿用现有产物格式（JSON + summary md），落本地 `results/`（不入库）
