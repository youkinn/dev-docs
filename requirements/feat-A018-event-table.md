# FEAT-A018: 事件表 + 事件名桥（白话事件召回 + 组内闭环注入）

> 特性号：FEAT-A018
> 状态：草稿
> 作者：Coco
> 涉及项目：mcp-server（主）、mcp-orchestrator（如需）
> 日期：2026-09-28
> 关联：docs/recall-quality-roadmap.md（§5 迭代 1）、requirements/BACKLOG.md BL-031（立项）、feat-A015（回归基线）、feat-A016（归一化 / 改写）

## 背景

- 回归基线（A015 120 题，快照 2026-09-27-2135）：top5 通过 73/120（60.8%）、兜底 9、未命中 38。未命中集中在战役 / 典故 / 事件关系 / 死亡 / 地名类——白话事件问法「词面落空」（query 说「三英战吕布」，原文段中无此四字）。
- A016 已落地人名 / 地名 / 战役 / 器物等归一化与 query 改写，仍不覆盖「白话事件名 → 原文情节」的整段映射。
- §13/§14 实测（零 LLM）：实体名数组加权无效（华雄题 #8 恒定、51 题搅动率 13.7%）；**事件文本当 query 扩展有效**（短事件名 5/7、长描述 7/7 进 top3）；§13.6 建议路线 = 标签表重定义为「事件表」（一行一事件 + chunk_ids[]，人工只列段、不判对错）。
- 断章取义根因之一 = 跨段事件只召回碎片：命中事件时应组内整段闭环注入（BL-031 立项动机）。
- 决策：负责人 2026-09-28——图谱暂缓（评估见 BACKLOG BL-032），A018 承接原图谱意向的窄口径「事件表」。

## 目标

- [ ] 事件表落地：一行 = 一个事件（event_name + 白话问法 / 别名 + chunk_ids[]，可选关联人物 / 回目元数据），人工只列段不判对错；起步覆盖 A015 未命中 38 题中的事件类 + 高频典故，规模 200–400 条目
- [ ] 检索侧事件名桥：白话事件问法 → 事件条目 → 第二路召回（事件名改写 / 事件路加权，融合方式实现时以实测为准），与三路 0.6/0.3/0.1 融合
- [ ] 组内闭环注入：命中事件时，事件涉及段整组进入注入候选（前 5 保底与预算机制不变，事件组不拆散）
- [ ] 评测：A015 同脚本同口径回归对比（基线 top5 60.8%），事件类逐类不倒退

## 非目标（明确不做的事）

- 不做知识图谱本体（实体-关系图、关系问答）——评估后暂缓，BACKLOG BL-032
- 不做事件因果 / 时序结构（概括型原因 / 结果问句属 feat-A021 专项）
- 不改 chunk / 向量 / 语料（零重建）
- 不引入 LLM 参与事件表构建与检索（纯人工清单 + 规则匹配，LLM 预算红线内）

## 验收标准（候选，待负责人确认）

1. [ ] A015 120 题同脚本回归：top5 通过率 ≥ 70%（基线 60.8%）；战役 / 典故 / 事件关系 / 死亡类逐类不低于基线
2. [ ] A015 未命中 38 题中事件类（战役 / 典故 / 事件关系 / 死亡）至少 50% 修复为 top5 或进入兜底 6–10
3. [ ] 新增 20 题白话事件问句（事件表覆盖场景）证据段进 top5 ≥ 80%
4. [ ] 事件组内闭环：随机抽 5 个跨段事件，注入清单包含该事件全部相关段（可读证）
5. [ ] 零新增 LLM 调用；事件表条目机器校验（chunk_ids 存在、event_name 非空、无重复）

## 接口影响

- mcp-server：检索入口新增事件表加载与事件名桥阶段；`sango_novel_search` 出参结构不变（诊断可增 eventHit 信号，以老陈接口文档为准）
- mcp-orchestrator：默认无契约变化；若事件组注入涉及注入侧选择逻辑，以接口文档为准
- 契约细节以老陈接口 / 表设计文档为准（接口文档先出）

## 技术要点

- 表结构：event_name（规范形）+ 白话问法 / 别名列表 + chunk_ids[]；与 A016 实体表边界：事件名可并入实体表改写键或独立事件表，实现时与老陈定（倾向独立表 + 事件名键并入改写入口）
- 融合：三路 0.6/0.3/0.1 之上加事件路，或事件命中时事件名改写 query；§13.8 / §14 实测提示 0.1 权重被量纲吃掉，事件路权重须实测校准
- 组内闭环：事件组段数受注入预算（INJECT_TOTAL_BUDGET=2000）约束，大事件组需组内子集策略（按事件内原始序优先）
- 零 LLM：事件清单人工 + 脚本统计（A015 未命中题逐题核对），无批量 LLM 调用

## 风险 & 开放问题

- 事件覆盖不全：起步只覆盖高频，覆盖不足时扩充（A015 扩充机制，走新特性号）
- 事件名歧义 / 误匹配：白名单式收录，只映射已确认事件
- 大事件组 vs 注入预算：子集策略取舍（验收 4 口径细化）
- 融合权重需实测：事件路与三路融合可能重蹈 §14「0.1 权重被量纲吃掉」覆辙
