## 目标

- [ ] **事件全集一次构建**：覆盖全书 120 回，规模 400–600 条（量级口径以分层全集为准），单批建完，不分批交付
  - L1 专名事件（三英战吕布 / 草船借箭 / 空城计…）≈ 100–200：有通行专名、白话问法多，优先
  - L2 情节单元（无专名但完整闭环，如三顾茅庐全过程）≈ 100–200
  - L3 死亡 / 登场（现有 tags 已覆盖，方向反转为「事件→chunks」）≈ 150–250
- [ ] 构建链：Coco 工程包（回目骨架 + 标签反查 + 实体表并入 + 输出模板）→ **AI 初审（仅事件识别：有哪些事件、怎么问，不产精确段位）** → 负责人二次审核（查漏补缺）→ 脚本段位定位（零 LLM，按回 / 事件在语料定位 chunk）→ verify-events 硬校验 → 落表
- [ ] 事件表结构：`data/corpus/events.json`，行 = { eventId, eventName（规范形）, aliases[]（白话问法 / 典故变体）, chunkIds[]（只列段、不判对错）, type（L1/L2/L3）, characters[]? }；主键 chunk.id（§13.6 裁决：不用语料行号）
- [ ] 检索侧事件名桥 + 组内闭环注入（目标与验收见下）
- [ ] 长期机制（不以标准集为目标）：事件缺口清单 + 批次补录回流、事件类问法覆盖率 KPI 探针、事件表 norm 版本化与语料重建漂移检测

- 不做运行时 LLM 抽取：AI 初审仅限构建期；**运行时检索 / 注入链路零新增 LLM 调用**

- 事件全集是一次性构建交付，不设多批次中途验收

## 技术要点

### 构建链（一次全集，AI 初审 + 人工二次审核）
1. 工程包（Coco，零 LLM）：120 回回目切分 → 候选事件骨架（回目词 + 标签反查 + 实体表典故 / 数字称谓类并入）；输出 JSON 模板（eventId / eventName / aliases / 涉及回 / type），供 AI 初审填空
2. AI 初审（负责人编排，仅事件识别）：按回给出「事件名 + 白话问法 + 涉及回」，**不产 chunkIds**；预算见「LLM 预算登记」
3. 负责人二次审核（查漏补缺）：全量过目 eventName / aliases、核对跨回事件、初审漏件登记
4. 脚本段位定位（Coco，零 LLM）：按「事件 → 回区间 + 标签 + 关键词」在语料定位候选 chunkIds，跨回邻接补全
5. 落表 + verify-events.mjs（零 LLM）硬校验 + 事件表 norm 版本递增
6. 长期回流（构建完成后持续）：
   - 缺口清单 `dev-docs/test/events/gap.md`：线上漏召 / 新题面 / 题库新问法统一登记，**批次补录**（攒批 → 补录 → 校验 → 回归 → norm 版本发布），不做单条即改
   - 覆盖率探针：事件类问法池为分母，按月统计事件表命中率，驱动补录优先级（长期 KPI，非一次性验收）

### 检索接线
- 表结构 `data/corpus/events.json`，与 `tags/` 平行、刻意分离（现有 tags 是「chunk→标签」方向，事件表是「事件→chunks」反查方向）
- `sango/src/search/event-table.ts`（对齐 entity-table.ts 单一实现模式）；加载失败降级为无事件路由（沿用 loadTags 降级先例），不阻断
- 事件名最长匹配先行 → 命中事件：① 事件名 / 规范形进 query 改写通道（复用 A016 改写位点），或 ② 事件组第二路召回并提权；事件命中优先保证证据组进候选池与注入，不重蹈 §14「0.1 权重被量纲吃掉」覆辙（事件路不做 0.1 式弱加权，实现时实测校准）
- 组内闭环：事件组整组进注入（前 5 保底之外的事件组闭环），受 INJECT_TOTAL_BUDGET=2000 约束
- 诊断：`_meta.diagnostics` 增 eventHit（命中事件名 + 组数），复用 A009/A016 诊断通道

## LLM 预算登记（2026-09-28 负责人拍板）

- 用途：构建期 AI 初审（事件识别），仅一次性数据整理，不属于运行时链路
- 口径：按 10 回一批 → 全书 12 批次，每批 1 次，总上限 **≤ 12 次**（建议）；或按回 120 次（负责人择一）
- 约束：初审只做事件识别、不产精确段位；输出全部经负责人二次审核；重跑 / 扩量另行报备
- 运行时链路零新增 LLM 调用（原有生成 1 次 / 复核 ≤1 次预算不变）

## 风险 & 开放问题

- AI 初审幻觉（虚构事件 / 错认白话问法）：负责人二次审核 + verify 硬校验 + 缺口回流三重兜底
- AI 漏事件（查漏补缺遗漏）：缺口清单持续回流，覆盖率 KPI 暴露盲区
- 命名口径漂移：事件名 / aliases 与 A016 实体表单一口径（实体表管「怎么写」，事件表管「在哪几段」）；新增事件名须同步实体表
- 大事件组 vs 注入预算：组内子集策略（验收 4 细化）
- 语料重建 chunkIds 漂移：norm 版本 + verify 漂移检测预警
