## 目标

- [ ] **事件全集一次构建**：覆盖全书 120 回，规模 400–600 条（量级口径以分层全集为准），单批建完，不分批交付
  - L1 专名事件（三英战吕布 / 草船借箭 / 空城计…）≈ 100–200：有通行专名、白话问法多，优先
  - L2 情节单元（无专名但完整闭环，如三顾茅庐全过程）≈ 100–200
  - L3 死亡 / 登场（现有 tags 已覆盖，方向反转为「事件→chunks」）≈ 150–250
- [ ] 构建链：Coco 出**初审任务包**（输入清单 + 输出模板 + 填写说明，`test/events/first-pass-spec.md`）→ **Coco 在项目链路内生成初审材料（仅事件识别：有哪些事件、怎么问，不产精确段位；构建期 LLM 调用已报备登记）** → 负责人二审（查漏补缺）→ Coco 脚本段位定位（零 LLM）→ verify-events 硬校验 → 落表 → **Coco 验收结果**
- [ ] 事件表结构：`data/corpus/events.json`，行 = { eventId, eventName（规范形）, aliases[]（白话问法 / 典故变体）, chunkIds[]（只列段、不判对错）, type（L1/L2/L3）, characters[]? }；主键 chunk.id（§13.6 裁决：不用语料行号）
- [ ] 检索侧事件名桥 + 组内闭环注入（目标与验收见下）
- [ ] 长期机制（不以标准集为目标）：事件缺口清单 + 批次补录回流、事件类问法覆盖率 KPI 探针、事件表 norm 版本化与语料重建漂移检测

## 非目标（明确不做的事）

- 不做知识图谱本体（实体-关系图、关系问答）——评估后暂缓，BACKLOG BL-032
- 不做事件因果 / 时序结构（概括型原因 / 结果问句属 feat-A021 专项）
- 不改 chunk / 向量 / 语料（零重建）
- 不做运行时 LLM 抽取：**运行时检索 / 注入链路零新增 LLM 调用**
- 初审不交由外部免费 AI 执行（外部 AI 产物证实偷工减料、已弃用）：初审材料由 Coco 在项目链路内生成，不依赖外部工具；其产物须过 verify 前置检查方可进入下一环节
- 初审材料不产精确段位：段位定位由脚本（零 LLM）+ 人工二审负责，收缩幻觉面
- 事件全集是一次性构建交付，不设多批次中途验收

## 验收标准（2026-09-28 负责人确认；开发完成后逐条验收）

1. [ ] 事件全集一次建成交付：120 回全部梳理、事件全集落盘 `data/corpus/events.json`，`verify-events.mjs` 全量通过（chunkIds 存在、eventName 非空、aliases 与实体表改写键不冲突、无重复、跨回事件有复核记录）
2. [ ] 初审产物（Coco 链路内生成）过 verify 前置检查（eventName 非空 / 回号合法 / 字段完整）并经负责人二审全量过目；查漏补缺记录落 `test/events/gap.md`（初审漏件 → 补录；线上新增 → 缺口清单回流）
3. [ ] 长期机制落地：缺口清单模板 + 批次补录流程文档化；覆盖率探针脚本上线（分母 = 事件类问法池：线上问题 + 题库全集 + 画像事件类，按月统计）
4. [ ] 检索侧事件名桥 + 组内闭环注入按接口文档实现（老陈接口文档先行），命中事件组整组进注入、大组按事件内序组内子集
5. [ ] 顺带门：A015 同基线回归不倒车（top5 ≥ 基线 60.8%，事件类逐类不倒退）——标准集不是目标，仅防倒退
6. [ ] 运行时链路零新增 LLM 调用；构建期初审材料由 Coco 生成（构建期 LLM 调用按原则 14 报备登记，口径见「构建来源与 LLM 口径」）

## 技术要点

### 构建链（一次全集：Coco 任务包 → Coco 初审材料生成 → 负责人二审 → Coco 定位/校验 → 验收）
1. 任务包（Coco，零 LLM）：`test/events/first-pass-spec.md`（输入清单 + 输出模板 + 填写说明）+ `test/events/input-回目清单.md`（120 回回目索引）；回目骨架同时由脚本生成（回目切分 + 标签反查 + 实体表典故 / 数字称谓类并入）作验收对照底表
2. 初审材料生成（Coco，链路内 LLM，按回分批）：按回给出「事件名 + 白话问法 + 涉及回 + 类型」，**不产 chunkIds**；生成轮预算见「构建来源与 LLM 口径」
3. 负责人二审（查漏补缺）：全量过目 eventName / aliases、核对跨回事件、初审漏件登记
4. 脚本段位定位（Coco，零 LLM）：按「事件 → 回区间 + 标签 + 关键词」在语料定位候选 chunkIds，跨回邻接补全
5. 落表 + verify-events.mjs（零 LLM）硬校验 + 事件表 norm 版本递增
6. **Coco 验收结果**：verify 全过 + A015 回归 + 覆盖率探针读数，出具验收结论
7. 长期回流（构建完成后持续）：
   - 缺口清单 `test/events/gap.md`：线上漏召 / 新题面 / 题库新问法统一登记，**批次补录**（攒批 → 补录 → 校验 → 回归 → norm 版本发布），不做单条即改
   - 覆盖率探针：事件类问法池为分母，按月统计事件表命中率，驱动补录优先级（长期 KPI，非一次性验收）

### 检索接线
- 表结构 `data/corpus/events.json`，与 `tags/` 平行、刻意分离（现有 tags 是「chunk→标签」方向，事件表是「事件→chunks」反查方向）
- `sango/src/search/event-table.ts`（对齐 entity-table.ts 单一实现模式）；加载失败降级为无事件路由（沿用 loadTags 降级先例），不阻断
- 事件名最长匹配先行 → 命中事件：① 事件名 / 规范形进 query 改写通道（复用 A016 改写位点），或 ② 事件组第二路召回并提权；事件命中优先保证证据组进候选池与注入，不重蹈 §14「0.1 权重被量纲吃掉」覆辙（事件路不做 0.1 式弱加权，实现时实测校准）
- 组内闭环：事件组整组进注入（前 5 保底之外的事件组闭环），受 INJECT_TOTAL_BUDGET=2000 约束
- 诊断：`_meta.diagnostics` 增 eventHit（命中事件名 + 组数），复用 A009/A016 诊断通道

## 构建来源与 LLM 口径（2026-09-28 负责人拍板）

- 初审材料由 **Coco 在项目链路内生成**（负责人 2026-09-28 拍板：不用外部免费 AI、不做人工逐条）；事件识别 + 白话问法，不产精确段位
- **构建期 LLM 调用登记（原则 14）**：初审材料生成 = 全集一次生成（按回分批，生成轮 ≤6 次）+ 复核 ≤1 次；仅本次全集构建使用，后续批次补录零 LLM
- 若未来改由外部或第三方工具执行初审，须按 AGENTS.md 原则 14 重新报备登记（带次数上限）
- 产物门禁：初审产物必须通过 verify 前置检查（eventName 非空 / 回号合法 / 字段完整）后才进入段位定位与落表
- 运行时链路零新增 LLM 调用（原有生成 1 次 / 复核 ≤1 次预算不变）

## 风险 & 开放问题

- 初审材料漏件 / 口径不一 / 格式不规范（漏事件 / 问法偏书面 / 漏字段）：verify 前置检查 + 负责人二审 + verify 硬校验 + 缺口回流四重兜底
- 初审材料漏事件（查漏补缺遗漏）：缺口清单持续回流，覆盖率 KPI 暴露盲区；回目骨架底表作对照（脚本零成本生成，初审漏件可对照检出）
- 命名口径漂移：事件名 / aliases 与 A016 实体表单一口径（实体表管「怎么写」，事件表管「在哪几段」）；新增事件名须同步实体表
- 大事件组 vs 注入预算：组内子集策略（验收 4 细化）
- 语料重建 chunkIds 漂移：norm 版本 + verify 漂移检测预警
