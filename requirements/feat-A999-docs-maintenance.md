## 背景

文档与仓库维护类工作（`AGENTS.md`、`docs/`、`templates/`、需求 / Bug 索引、样例与排查手册的维护）不属于任何业务特性。按基本原则 1「无票不动代码」，这类提交过去只能挂靠别的票或没有票，来源与追溯都不清楚。

## 目标

- [ ] 提供一个**长期特性号 + 故事号**，供 Coco 的文档 / 仓库维护类提交使用（提交格式 `#story-A999-01 docs: <中文描述>`）
- [ ] 该特性**不上线、不归档**，状态长期保持 `定稿`
- [ ] 不占用正常序号：业务特性仍按 `feat-A013`、`feat-A014`… 正常自增

## 非目标

- 不承载业务代码变更（业务代码必须挂对应 feat / bug 票）
- 不作为业务需求的挂靠（新能力走需求对接，bug 走 bug 对接）
- 不参与版本发布、不进提测 / 验收 / 合并流程（文档变更随常规 PR 合入）

## 验收标准

1. [ ] Coco 的文档 / 仓库维护类提交均带 `#story-A999-01`

3. [ ] 业务特性的编号与状态不受影响
