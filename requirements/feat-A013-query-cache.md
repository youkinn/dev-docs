# feat-A013: 三国演义问答缓存（应用层 query→answer 语义缓存）

> 特性号：feat-A013
> 状态：草稿
> 作者：Coco
> 涉及项目：mcp-orchestrator、mcp-web（mcp-server 视语义判定设施落点而定，接口文档确认）
> 日期：2026-09-23
> 关联：feat-A004（演义 RAG）、feat-A009（检索诊断 / 最终分可解释先例）、feat-A011 / feat-A012（provider 侧 prompt 缓存，与本特性互补不替代）、bug-00022（语义判定同族风险评估）

## 背景

三国演义解读（feat-A004）当前对用户的每个输入都调用大模型接口：同一问题前后两次提问，系统产生两次 LLM 调用记录。现状一次响应 7~17s（火山方舟无缓存 + 注入片段过长），重复问同一问题造成 Token 浪费与无谓等待。

## 目标

- [ ] 三国演义域（`sango-novel`）同一 / 等价问题二次提问：命中语义缓存，**0 次 LLM 调用**，直接返回与首次一致的回答
- [ ] 后台能解释「为什么命中」（用户输入原文 + 命中条目原文 + 相似度分值，做法对齐 A009 最终分）
- [ ] 后台图表展示用户输入与缓存命中的分布关系，为后续调整相似度阈值（当前 0.85）提供数据支撑
- [ ] 后台开关可一键启停缓存；可一键全量清除与单条删除（立即生效）
- [ ] 语义判定区分「换说法」（命中）与「问点不同」（不命中），不把相似问法误判为同一问题
- [ ] 后台可见当前缓存条目与近似内存占用（条目数 + 答案序列化字节合计，口径可复算）
- [ ] 后台可标记误判并查看误判率（区间口径）；图表在阈值邻域（±0.05）高亮并列出 query 对，支撑识别 0.85 附近误判

## 非目标

- **风云三国不接入缓存**（负责人 2026-09-23 确认）；普通问答（auto/free 域）、随机一题不缓存；风云三国题库召回重做（bug-00022「大改」，未立项）另立特性，本特性不涉及
- 不做 provider 侧 prompt 缓存（A011/A012 `cached_tokens` 已另立，两者互补不替代）
- 不做缓存持久化：进程重启缓存清空，MVP 可接受；跨重启持久化（Redis / SQLite 化）另立特性
- 不做动态调阈值：本期阈值做成配置项 + 图表供数，调整动作由人按数据拍板
- 不做 query 改写、命中后答案合并 / 再生成、缓存预热、多实例共享缓存
- 不做自动判定命中答案对错（无真值来源）；误判靠人工标记，不做智能纠错

## 验收标准

1. [ ] 同一问题连续两次提问（三国演义标签）：第二次 `llm_call_logs` 无新增行，接口返回与首次一致的答案对象（结论 / 引语 / 出处一致）
2. [ ] 等价问法（同一问题换说法，如「义释严颜是怎么回事」与「严颜是怎么被义释的」，两者都求经过）二次提问命中缓存，无 LLM 调用
3. [ ] 负例·问点不同不命中：「严颜被义释是哪一回」（求回目数字）与「义释严颜的经过」判定**不命中**，正常走检索 + LLM（相似但问点不同，防 bug-00022 同族误命中）
4. [ ] 低相似问法（明显不同问题，< 阈值）不命中，走检索 + LLM；未命中记录含本次最高相似度
5. [ ] 命中提升 + 末尾淘汰：以测试小容量验证，最早访问条目被逐出、最近命中条目保留；被逐出条目的 query 再次提问重新走 LLM
6. [ ] 歧义不命中：两条及以上缓存条目同时 ≥ 阈值（并列）→ 该 query 不命中，走原链路
7. [ ] 开关：后台关闭缓存后，同一问题第二次提问仍走 LLM；开启后恢复命中（真浏览器 + 真实数据验收）
8. [ ] 清除缓存（全量 / 单条）：点击后立即生效——被清 query 下一次提问走 LLM 并重新写缓存；单条删除后仅该条目失效，其余命中不受影响
9. [ ] 图表：展示指定区间内命中 / 未命中数量与相似度分布（含未命中最高相似度），与 `cache_logs` 记录对账一致
10. [ ] 命中解释：日志页对一次命中请求可见 用户输入原文 / 命中条目原文 / 相似度数值 / 阈值（算式代入，对齐 A009 最终分）
11. [ ] 回归：随机一题、普通问答行为不因缓存开关变化
12. [ ] 缓存概览：后台展示当前条目数与近似内存占用（口径 = 条目答案 JSON 序列化字节合计），与接口返回对账一致
13. [ ] 误判可见：后台可对命中记录标记误判 / 取消；区间误判率 = 区间标记误判命中数 / 区间命中总数（未标记不计为正确）；图表阈值邻域（如 0.80~0.90）列出命中 / 未命中的 query 对（用户输入原文 / 最相近条目原文 / 相似度），可定位 0.85 附近误判并直接单条删除

## 接口影响（如有）

- 新增后台 API（落点与契约由接口文档定）：缓存开关查询 / 切换、全量清除与单条删除、**缓存概览与条目明细**（条目数 / 近似内存占用 / 条目列表：query 原文、答案字节、命中次数、最后访问时间）、图表统计与**阈值邻域明细**、**误判标记 / 取消**、命中明细（或并入日志页 trace 明细）
- 命中请求无 MCP 检索与 LLM 调用：日志链路需兼容「无 LLM 调用但有缓存命中」的 trace 形态；A009 检索诊断面板对命中请求显示「缓存命中，未走检索」，避免误判为链路故障
- 新表（如 `cache_logs`）：traceId 关联、用户输入原文、命中条目原文、相似度、阈值、命中 / 未命中、时间；未命中记最高相似度**及其最相近缓存条目原文**（0.85 邻域分析的数据基础）；新增**误判标记字段**（标记人 / 时间，接口支持标记与取消）
- 缓存命中直接返回服务端渲染后的最终答案对象（A004/A006 契约：结论 + `quotes[]` + 出处），前端展示零改动

## 技术要点

- 缓存结构 = 进程内 LRU：条目含 `{query 原文, query embedding, 答案对象, 访问时间}`；命中按相似度判定并提升到队首；条目数超上限末尾淘汰。可行性 / 选型 / 清除策略见 `docs/feat-A013-cache-research.md`
- 命中判定 = 新 query 的 embedding 与各条目 embedding 逐一算 cosine，最高者 ≥ 阈值（默认 0.85，可配置）为候选命中；**仅当该候选是唯一 ≥ 阈值的条目时才真正命中**（并列即不命中）；条目规模 ≤ 1k 时全扫为毫秒级
- 语义判定设施：复用 A004 本地离线 embedding（同源同维度，判定与检索口径一致）；落点（mcp-server 轻量工具 vs 总台内置）由接口文档确认
- **误命中防御（bug-00022 同族风险，2026-09-23 评估后列入）**：embedding 余弦与 bigram 类似、对词序不敏感，且真命中与不相关分数交叠（风云三国实测：不相关余弦 0.716 > 真命中 0.602，见 `bugs/bug-00022-tie-candidate-wrong-answer.md`）——单靠 0.85 阈值必然存在误命中面。MVP 加两层轻防御：① 歧义不命中（唯一候选 ≥ 阈值）；② 问点 / 疑问焦点一致性轻校验（一方有焦点且双方焦点不交 → 不命中，如「经过」vs「是哪一回」）。残余误命中（如实体角色反转类问法）靠命中解释审计 + 单条删除 + 开关兜底；实现细节由接口文档定
- 缓存值只存「服务端渲染后的最终答案对象」，不含诊断 / 过程数据；拒答类（「演义中未涉及」）**不写缓存**（已定），防错误拒答固化
- 版本失效：缓存条目绑定答案产物版本（语料 / 提示词 / 路由相关版本），版本变更全量失效，防升级后命中旧答案
- 记录与统计：命中 / 未命中均落 `cache_logs`（未命中记最高相似度与其最相近条目原文），图表与阈值调整依赖该数据；开关关闭期间不产生命中记录（数据断档可接受）
- 内存占用口径 = 条目答案对象 JSON 序列化字节合计（query embedding 向量另列；进程 heap 无法逐条归属，后台标注「近似」并由接口给出口径以便复算）
- 误判率口径 = 人工标记制：误判率 = 区间标记误判命中数 / 区间命中总数，未标记不计为正确；不自动判定对错（无真值来源）

## 风险 & 开放问题

- 错误答案固化（存疑 #3）：缓存命中跳过检索与生成，若首次答案错误将持续输出 → 缓解：命中解释可见 + 开关一键停用 + 全量清除 / 单条删除（均已定本期做）
- 误命中风险（bug-00022 同族）：「问点不同但词面 / 语义相近」的问法可能互相命中 → 防御见技术要点；残余部分靠审计与人工干预；若数据证明误命中率高，另立课题根治（同 bug-00022 召回大改，不塞进本特性）
- 阈值 0.85 无判定依据（存疑 #4）：采纳「宁可放过不要误判」原则；阈值配置化（已定）+ 图表提供（含未命中最高相似度）分布数据，上线后按数据调整
- 上下文补充型提问（如「那下一回呢」）语义不完整，可能语义误命中 → 命中解释可见，数据积累后调阈值或加拒判
- 上限默认值（条目数 / 内存占用）已定：配置项，默认 500~1000 条，接口文档按实测答案体积校准
- 误判率依赖人工标记：不标记则误判率失真偏低；用阈值邻域清单 + 命中解释引导巡检，数据覆盖度上线后评估
- 多实例部署时内存缓存各自独立（命中率下降）；当前单实例，记风险不阻塞
- 命中链路延迟：embedding 计算 + 全扫时长需实测，目标远低于 LLM 调用（当前 7~17s）
- 语义判定设施如果新增 mcp-server 工具，触及 Transport 层契约，需老陈同步评估
