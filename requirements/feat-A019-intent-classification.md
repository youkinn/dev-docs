## 背景

- 死亡意图目前以规则实现（A014 保留），负责人认为「不得已」；战役 / 典故等事件类问法的意图覆盖不足。
- 候选：轻量 LLM 判断意图（死亡 / 战役 / 典故……），延迟代价 1–2s 可接受（后续流式输出守住首 token 可掩盖）。
- Coco 建议：优先并入现有分类轮（classify 已存在，避免新增一次 LLM 往返）；classify 仅在 auto 路径存在，域锁定（L1 / L2）路径需评估复用或规则兜底。

## 目标

- [ ] 三方案对比评估：轻量 LLM 独立意图判断 vs 并入现有分类轮 vs 规则兜底（现状）
- [ ] 事件类问法覆盖：战役 / 典故意图样例集评测（准确率 / 延迟 / 成本）
- [ ] 结论定案：是否切换、切换后规则保留为兜底的边界

## 非目标（明确不做的事）

- 不做流式输出改造（仅评估其作为延迟掩蔽手段的可行性，改造另议）
- 不扩大意图类型范围到本需求确认之外（先死亡 / 战役 / 典故）

## 验收标准

每个标准可验证（对 / 错，无灰色地带）：

1. [ ] 样例集 ≥20 问（死亡 / 战役 / 典故各 ≥5 + 负例），负责人抽样审定
2. [ ] 三方案对比报告：准确率（意图判定对错）、P50 / P95 延迟、token 成本，数据可复现
3. [ ] 定案结论落档：选型 + 理由 + 规则兜底边界；若并入分类轮，明确 auto / 域锁定路径接入方式
4. [ ] 结论不阻塞 A014 事件表合并（按原定进行）

## 接口影响

- mcp-orchestrator 分类轮 / 意图判定路径（若切换）；auto 与域锁定（L1 / L2）路径覆盖
- mcp-server / mcp-web 无契约变化

## 技术要点

- classify 现状：仅 auto 路径存在；接入评估需覆盖域锁定路径（复用或规则兜底）
- 延迟预算：1–2s 可接受；流式输出首 token 门槛为掩蔽项（本需求只评估、不改造）
- 评测遵守 token 控制：负责人抽样执行，程序不批量跑

## 风险 & 开放问题

- 分类轮与意图判定职责边界：并入后一次往返同时做路由 + 意图，输出格式需兼容
- 轻量 LLM 意图误判：规则保留为兜底，误判样例在报告中登记

## 候选方案记录：人物属性类问法（字 / 号）的证据锚定（待评估，未拍板）

> 来源：负责人 2026-09-30 设想（复用人物登场逻辑 / 轻量 LLM 意图路由）；数据调查见 `test/entities/birth-tag-intro-coverage.md`、`test/entities/courtesy-name-citation-rank.md`（零 LLM 实测）。
> 状态：候选记录，不实施；`bug-00053`（「X字什么」答「演义中未涉及」或引用落无关段）暂缓，随本特性讨论后定口径。
> 范围提示：本节若转为正式目标，属**扩大本特性范围**（现非目标为「先死亡 / 战役 / 典故」），需负责人确认。

需求场景：「X字什么」类问法，语料有明确断言段（第 1 回「某姓张名飞，字翼德」、第 7 回「姓赵，名云，字子龙」）时仍拒答，或答对但引用落在无关战斗段（引用不等于自我介绍段）。

数据支撑读数（141 位登场人物 / 其中 85 位语料内有字断言）：

- 登场位点组（±1）含姓名 92.9%、含字 49.6%；组内含**他人**字断言 24.1%（误答风险）。
- 全语料有该人字断言 60.3%（85 人）＝能力上限；其余 56 人语料未给字，应走高置信拒答。
- 理想引用段（该人字断言最早段）当前名次：top5 77.6% / 6–10 8.2% / 出窗 14.1%（含少量抽取误召，人工核后约 6–7 人）；78.8% 的理想引用段落在登场位点组内。

- 「登场段≈自我介绍」的数据支撑：位点组含姓名 92.9%（姓名几乎必有）、含字 49.6%（约一半）——进窗有普遍价值，含字属「大概率」而非前置条件。改写 query 实测（2026-09-30，零 LLM，`test/entities/courtesy-name-rewrite-probe.md`）：对「位点组内含本人字断言」的 53 人，`{人物}字什么`（现状）vs `{人物}登场`（改写 query，借现有登场结构路）各检索 top10 —— 现状 top1 25（47.2%）/ top5 44 / 出窗 5；改写后 **top1 4（7.5%）/ top3 53（100%）/ 出窗 0**。即改写保证断言段**进注入窗**（多落在组内第 2–3 位，不保证第一），对象限于「有登场标签且组内含本人断言」的 53/141（37.6%）；无标签 / 组内无断言者改写无效。
| 备选方案 | 做法 | 覆盖（按上述读数） | 代价 / 约束 |
|---------|------|------------------|------------|
| A 复用登场位点 | 字意图命中 → 取该人登场位点 ±N 组 → **整组置顶进窗（不设含字门槛；含本人断言的段组内优先为可选加固）** | 位点组含姓名 92.9% / 含字 49.6% | 组内含他人字断言 24.1%，由答案侧校验兜底；无登场标签者无解 |
| B 人物属性断言锚点 | 零 LLM 全语料扫「(姓X，)名Y，字Z」「Y字Z」生成断言锚点，置顶 + 引用优先自我介绍段 | 上限 60.3% | 新增一份锚点数据 + verify 校验；需与 A016 实体表口径一致 |
| C 轻量 LLM 意图路由 + 槽位 | LLM 输出「意图 + 槽位（人物）」，新增能力只加注册项 | 入口可扩展 | 新增 LLM 调用须报备登记 + 次数上限（原则 14/15）；判定方差影响 A015 回归口径；**只解决入口，锚点数据仍依赖 A/B** |

共同约束（方案定案时必须带）：

- 进窗优先、校验兜底（负责人 2026-09-30 口径）：登场段是否含字**不作为进窗前置条件**；答案侧仍做零 LLM 校验——答案的字须出自注入段，否则拒答，防「从登场段误推」。
- 单值答案零 LLM 校验：答案中的字须出自注入断言的字（挡「答成别人的字」）；兼容「字长生，后改云长」这类双值写法。
- 引用口径：答对但引用落无关段按不合格处理，理想引用 = 该人自我介绍 / 字断言段。
- 反向问法（「谁字子龙」）无人物锚，本期不做，边界写进实现票。
