## 背景

- 历史否决：MaxSim / RRF 在「目标 top3、注入前 3 段」时代均无法把证据段抬进 top3（bug-00003 §12）。
- 前提已变化（v2 重试理由）：注入已放宽 top5 保底 + 6–10 兜底（目标变 top10）；检索演进到 chunk v2 + BGE-M3 真向量 + 三路 0.6 / 0.3 / 0.1（华雄定点 #8→#2；A014 分支死亡意图补 death_age 后刘备之死段进 top10）；历史否决对象是线性 MaxSim / RRF，非 cross-encoder。
- 负责人 2026-09-24 拍板：值得重试（v2）。

## 目标

- [ ] 依据池覆盖探针（A015 T1-c0）结论决定选型：证据段入 50 路候选池覆盖率达标才接 cross-encoder 重排；不达标则优先 A017（query 改写 / 事件表）
- [ ] cross-encoder 类重排接入：候选池 50 路 → 返回 10
- [ ] 评测：标准集 top≤5 提升 + 定点（华雄 / 刘备）不倒车 + 延迟在预算内

## 非目标（明确不做的事）

- 不做端到端替换检索：重排只作用于已入池候选
- 不引入超过延迟预算的模型（预算按生产 P95 口径在评测期核定）
- 不改变注入策略（A016 / A020 范畴）

## 验收标准

每个标准可验证（对 / 错，无灰色地带）：

1. [ ] 选型结论落档：基于池覆盖探针覆盖率（标准集 + 定点样例）明确「接 / 不接」及理由
2. [ ] 重排接入后：候选 50 → 返回 10，输出顺序与诊断一致（可读证）
3. [ ] 标准集 top≤5 不低于无重排基线（recall-bench 同基线复跑对比；批量跑分经负责人放行后执行）
4. [ ] 定点不倒车：华雄、刘备两组案例 top10 排名不差于无重排
5. [ ] 延迟实测：单次检索重排阶段延迟 ≤ 预算（报告含 P50 / P95）
6. [ ] 失败样例登记 ≥3 例（重排把证据段排下去 / 排错），说明改进方向或关闭理由

## 接口影响

- mcp-server 检索 pipe 新增重排阶段；entries[] 对外结构不变，诊断可增重排信号（以接口文档为准）
- mcp-orchestrator / mcp-web 无契约变化

## 技术要点

- 候选池 50：三路（0.6 / 0.3 / 0.1）融合后取 top50 进重排，重排返回 top10
- 选型前提 = 池覆盖：证据段不在 50 路池内则重排无效（先探针、后选型）
- 恢复基线工具：recall-bench 同基线复跑（脚本零 LLM；批量跑分报备负责人）

## 风险 & 开放问题

- 覆盖率不达标 → 重排空转：按探针结论关闭或转投 A017，本需求以「选型结论」为最小交付
- cross-encoder 延迟 / 部署成本：模型选型与量化在评估期定，超预算即关闭
- 依赖 A015 探针：若 A015 延后，先以定点样例人工估值（风险提示，不作为验收替代）
