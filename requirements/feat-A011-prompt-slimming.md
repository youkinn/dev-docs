# feat-A011: 输入 token 优化（提示词瘦身 + 天气下线 + auto 轻量分类）

> 特性号：feat-A011
> 状态：已提测（2026-09-22 提测：Coco 审查通过，负责人在需求分支验收）
> 作者：Coco
> 涉及项目：mcp-orchestrator（总台，主要）、mcp-server（器坊）、mcp-web（前厅）
> 日期：2026-09-22
> 关联：feat-A003（统一路由提示词 + 三层路由，本特性替换其第 1 次调用形态）、feat-A004（原著域 6 条 + 域提示词 + 引用兜底）、feat-A005（题库域）、feat-A007 / A008（日志采集与页面）、feat-A010（模型可见工具白名单）

## 背景

单次对话输入 token 稳定在 3.3K 以上，`auto` 路径实测 **7.2K**（负责人日志数据）。按 `llm_call_logs` / `request_summary` / `tool_call_logs` 逐条拆开看，**「模型可见的静态文本」才是主成本，且在 tool-use 路径上按轮数重复计费**。

2026-09-22 实测（探针法：同一 messages 带 / 不带工具定义求差；日志法：`llm_call_logs.prompt_tokens` 与 `request_summary` 逐条比对）：

| 构成 | token | 说明 |
|------|-------|------|
| 工具定义（6 个模型可见工具的 description + schema） | **1364** | 探针实测；**每次调用固定携带**（天气 2 个 = 796 字符，其余 4 个 = 2080 字符） |
| 完整统一提示词 `UNIFIED_SYSTEM_PROMPT`（2363 字符） | **1430** | 探针实测；`auto` 与天气域使用（其中天气相关条款约 545 字符 ≈ 330 token） |
| 域提示词 `ROUTE_HINTS['sango-novel']`（477 字符） | 317 | 探针实测；域锁定快路径使用 |
| 注入原文片段（快路径 2000 字符预算） | 1600 ~ 1900 | 日志实测（1855~2139 字符） |

四条路径现状：

| 路径 | 调用轮数 | 输入合计 | 其中静态文本（工具定义 + 提示词） |
|------|----------|----------|-----------------------------------|
| 域锁定快路径 · 原著（`domain=sango-novel`） | 1 | 3301 ~ 3619（均值 3460，43 条） | 1681 / 49% |
| 域锁定快路径 · 题库（`domain=fengyunsanguo`） | 1 | 1520 | 1681 / >100%（工具定义全废） |
| **`auto` tool-use**（无域标签、L2 未命中、L3 未命中） | 2 | **7205**（2816 + 4389） | **5588 / 78%**（工具定义 2728 + 统一提示词 2860） |
| 天气域 tool-use（`domain=weather`） | 2 | 10008（2820 + 7188） | 5588 / 56%（其余为 NWS 预警出参） |

`auto` tool-use 逐轮实测（traceId `df9e5267`，问句「关云长义释曹孟德」）：

- 第 1 轮 2816 = 统一提示词 1430 + 工具定义 1364 + 问句
- 模型自主调 `sango_novel_search`（`auto` 路径无域内快路径），第 2 轮 4389 = **同一份提示词与工具定义再付一次**（2860）+ 检索出参 1565 字符

结论：

1. **静态文本在 tool-use 路径上按轮数重复付费**——`auto` / 天气路径 78% / 56% 的输入是静态文本；域锁定快路径只付一次，占比降到 49%（题库域工具定义纯浪费）
2. **系统提示词瘦身的收益高度依赖路径**：域锁定快路径里只占 9%（317），`auto` / 天气路径里占 40%（1430 × 轮数）
3. **工具定义 1364 是最大且最容易被忽视的一块**：第 1 次调用的唯一任务是「决定调不调工具、调哪个」，却要为此携带全部工具的 description + schema
4. **「路由到天气域」与「auto」发给模型的内容逐字节相同**（实测：两者首轮 system 均为 2363 字符完整统一提示词 + 同一套 6 工具）→ 单纯改路由一个 token 都省不了
5. 缓存命中当前完全不可观测：`llm_call_logs` 只记 `prompt_tokens` / `completion_tokens`，provider 回传的 `usage.prompt_tokens_details.cached_tokens` 被丢弃

## 目标

### 一、静态文本瘦身（认知口径：静态文本 = 工具定义 + 系统/域提示词）

- [√] 第 1 次调用与生成轮提示词分离：第 1 次只带「能力清单 + 编号约定 + 兜底」，**域格式条款移到生成轮追加**——这一轮只需输出编号，格式约束用不上
- [√] 快路径命中（域锁定 + 检索结果已注入）的调用**不携带工具定义**（确定是该域、不必让模型再决策调不调工具）
- [√] 单次调用的静态文本按路径达标：
  - 域锁定快路径：≤250（现状 317；只有域提示词，无工具定义）
  - `auto` 分类轮：≤400（现状 2794；不携带工具定义、不带格式条款）
- [√] 输入合计按路径达标：
  - 原著域快路径 ≤2400（现状均值 3460）
  - 题库域 ≤400（现状 1520）
  - `auto` 两轮合计 ≤2800（现状 7205）
- [√] 提示词写成「缓存友好」形态：静态前缀逐字节稳定、变化内容一律靠后

### 三、`auto` 第 1 次调用改为轻量分类（负责人 2026-09-22 决策：本次实现）

- [√] 第 1 次调用只做一件事：让模型**输出一个能力编号**——不携带工具定义、不带格式条款、输出一个数字
- [√] 编号表（服务端按编号分派；**加能力 = 加编号分支，架构不变**）：
  - `1` = 原著检索域（三国演义）→ 服务端预调 `sango_novel_search` → 注入 → 生成轮
  - `2` = 题库问答域（风云三国）→ 服务端预调 `fengyunsanguo_query` → 注入 → 生成轮

## 技术要点

- **静态文本按轮数重复付费（本特性核心事实）**：每轮把 messages 重发一次，静态文本成本 × 轮数。因此①静态文本越短，收益随轮数放大；②减少轮数或让某一轮变轻都是杠杆
- **第 1 次调用 = 轻量分类（负责人 2026-09-22 定调）**：这一轮的职责只有「决定调不调、调哪个」，格式条款与工具 schema 都用不上。实现为：system = 分类提示词（能力清单 + 编号约定 + 兜底，约 300 token），user = 问句，输出 = 一个编号 → 省掉工具定义 1364 与格式条款
- **服务端按编号分派**：`1` → 预调 `sango_novel_search`；`2` → 预调 `fengyunsanguo_query`；`99` → 不预调。预调结果作为注入视图（与域锁定快路径同源：纯原文 + 服务端编号）
- **生成轮追加格式条款，不替换 system**：messages = `[system(分类提示词), user, assistant(编号), system(注入片段 + 该域格式条款)]`——追加保持前缀不变（缓存可命中），且与既有 `system(域提示词) → user → system(注入片段)` 写法一致
- **加能力 = 加编号分支**：编号表是唯一扩展点，既有分支与调用结构不变（负责人明确要求）
- **快路径命中不传工具定义**：域已锁定 + 结果已注入 → 模型无需工具；省 1364 token
- **`auto` 必然多一次分类调用**：这是「无域标签自动识别」的代价——域锁定快路径 1 轮（≤2400），`auto` 2 轮（≤2800）；省 token 的正解仍是前端显式选场景
- **缓存机制（2026-09-22 探针实测，两次标定）**：provider 回传 `usage.prompt_tokens_details.cached_tokens`，命中按 64 token 块对齐（实测 1536 = 24 × 64）。
  - ① 瘦身前口径：连续两次同前缀请求，第二次命中 1408 / 2809（≈50%，静态前缀部分全部命中）
  - ② 瘦身后实测（本次 6 次调用探针）：**共享前缀只有 210 token（域提示）→ 第二次命中 0**；共享前缀 1613 token（常量块 ~1500）→ 第二次命中 1536。即 provider 的最小可缓存前缀落在 210 ~ 1536 之间，**A011 的 ~250 token 静态前缀够不到门槛 → 跨问句恒 0**
  - ③ 隐形脚手架：同一份 messages，思考关 210 / 思考开 235（差 **25** token）→ provider 在 messages 之外还会拼入内容（思考脚手架），它计入 `prompt_tokens`，也在缓存前缀里 → 思考口径变更（bug-00018）会让历史缓存整体失效
  - 结论：**命中只在「整段 prompt 逐字节重复」时出现**（全库 5 次命中全是同问句连打）；瘦身把静态前缀压到门槛以下，跨问句复用这条收益归零——这是本特性的固有取舍，不是实现缺陷
- **稳定前缀原则（缓存友好写法）**：
  - 分类提示词 / 域提示词 / 工具定义必须**逐字节稳定**，且置于消息最前
  - 禁止在系统文本里拼时间戳、traceId、随机 ID、按请求变化的清单（一处变化 → 整段前缀失效）
  - 变化内容（用户问句、注入片段）一律靠后
- **提示词单一来源**：域格式条款只保留一份（`ROUTE_HINTS[*]`），供快路径单轮与生成轮追加使用；分类提示词不重复格式条款

## 风险 & 开放问题

1. **分类漏判的后果比误判更重**：原著 / 题库问句被判成 `99` 自由模式 → 无检索依据、模型凭先验知识答三国内容，直接违反 feat-A004「禁止用先验知识补全」硬约束。因此兜底取向定为「不确定倾向选 `1` / `2`」；若标定集上漏判仍非 0，须给 `99` 分支补「无检索依据时不答三国内容」的约束
2. **模型侧 tool-use 链路整体退场（需负责人定去留）**：`auto` 与快路径都不再携带工具定义，模型不再直接调 MCP 工具 → 工具定义渲染、`MODEL_VISIBLE_TOOLS` 白名单、多轮 tool-use 循环、模型侧 `callTransportTool` 入口全部不再被走到。是**彻底清理（避免孤儿代码）还是保留作为将来「模型自主多工具」通道**，请负责人定；本特性按「不顺手删」处理
3. **既有设计文档必须同步**：feat-A003「模型自主工具路由（统一对话入口）」的原始设计被本特性替换（第 1 次调用从「带工具自主决策」变为「轻量分类出编号」），`docs/sango-mcp-routing-design.md` 与 `mcp-orchestrator/api/feat-A003-model-tool-routing.md` 需同步演进说明（文档过期与编译失败同级）
4. **语义收窄（需负责人确认）**：域锁定 + 快路径命中时不传工具 → 该场景下模型不再能自主调其他域工具（现状可以）。判定为可接受（域锁定即用户显式选定场景，域提示词已要求域内作答）

6. **天气下线的影响面**：默认场景问天气将不再有天气能力（按负责人 2026-09-22 决策）；`/weather` 改名为 `/chat`，旧链接直接 404（内部工具无外链，不做重定向）
7. **provider 缓存策略未文档化**：TTL 与命中粒度以实测为准。缓存是加成不是前提。**补充（2026-09-22 探针实测）**：瘦身把静态前缀从 2809 压到 ~250 token，同时把「可缓存前缀」压到 provider 门槛以下 → 跨问句命中恒为 0，只有同问句逐字节重复才可能命中（且仍受 provider TTL / 驱逐 / 账号级共享缓存干扰）。因此日志页「缓存命中」列是**观测指标，不作验收判据**；验收看输入 token（1841 vs 瘦身前 7205）
8. **工具描述属对外契约**：瘦身需老陈确认不破坏 MCP 契约文档与既有测试
9. **注入片段占快路径 50%**（1600~1900 token），是瘦身的下一站；直接砍预算会伤召回质量，需先有召回质量评测口径（关联 bug-00003 / bug-00007 / bug-00008），本期不动
