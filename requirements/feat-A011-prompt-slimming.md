## 背景

单次对话输入 token 稳定在 3.3K 以上，`auto` 路径实测 **7.2K**（负责人日志数据）。按 `llm_call_logs` / `request_summary` / `tool_call_logs` 逐条拆开看，**「模型可见的静态文本」才是主成本，且在 tool-use 路径上按轮数重复计费**。

2026-09-22 实测（探针法：同一 messages 带 / 不带工具定义求差；日志法：`llm_call_logs.prompt_tokens` 与 `request_summary` 逐条比对）：

| 构成 | token | 说明 |
|------|-------|------|
| 工具定义（6 个模型可见工具的 description + schema） | **1364** | 探针实测；**每次调用固定携带**（天气 2 个 = 796 字符，其余 4 个 = 2080 字符） |
| 完整统一提示词 `UNIFIED_SYSTEM_PROMPT`（2363 字符） | **1430** | 探针实测；`auto` 与天气域使用（其中天气相关条款约 545 字符 ≈ 330 token） |
| 域提示词 `ROUTE_HINTS['sango-novel']`（477 字符） | 317 | 探针实测；域锁定快路径使用 |
| 注入原文片段（快路径 2000 字符预算） | 1600 ~ 1900 | 日志实测（1855~2139 字符） |

四条路径现状：

| 路径 | 调用轮数 | 输入合计 | 其中静态文本（工具定义 + 提示词） |
|------|----------|----------|-----------------------------------|
| 域锁定快路径 · 原著（`domain=sango-novel`） | 1 | 3301 ~ 3619（均值 3460，43 条） | 1681 / 49% |
| 域锁定快路径 · 题库（`domain=fengyunsanguo`） | 1 | 1520 | 1681 / >100%（工具定义全废） |
| **`auto` tool-use**（无域标签、L2 未命中、L3 未命中） | 2 | **7205**（2816 + 4389） | **5588 / 78%**（工具定义 2728 + 统一提示词 2860） |
| 天气域 tool-use（`domain=weather`） | 2 | 10008（2820 + 7188） | 5588 / 56%（其余为 NWS 预警出参） |

`auto` tool-use 逐轮实测（traceId `df9e5267`，问句「关云长义释曹孟德」）：

- 第 1 轮 2816 = 统一提示词 1430 + 工具定义 1364 + 问句
- 模型自主调 `sango_novel_search`（`auto` 路径无域内快路径），第 2 轮 4389 = **同一份提示词与工具定义再付一次**（2860）+ 检索出参 1565 字符

结论：

1. **静态文本在 tool-use 路径上按轮数重复付费**——`auto` / 天气路径 78% / 56% 的输入是静态文本；域锁定快路径只付一次，占比降到 49%（题库域工具定义纯浪费）
2. **系统提示词瘦身的收益高度依赖路径**：域锁定快路径里只占 9%（317），`auto` / 天气路径里占 40%（1430 × 轮数）
3. **工具定义 1364 是最大且最容易被忽视的一块**：域已锁定、检索结果已注入的调用里完全用不上（域提示词已写明「不要再调用」）
4. **「路由到天气域」与「auto」发给模型的内容逐字节相同**（实测：两者首轮 system 均为 2363 字符完整统一提示词 + 同一套 6 工具）→ 单纯改路由一个 token 都省不了
5. 缓存命中当前完全不可观测：`llm_call_logs` 只记 `prompt_tokens` / `completion_tokens`，provider 回传的 `usage.prompt_tokens_details.cached_tokens` 被丢弃

## 技术要点

- **静态文本按轮数重复付费（本特性核心事实）**：`agent.ts` 的 tool-use 循环每轮把 tools + 全部 messages 重发一次，静态文本成本 × 轮数。因此①静态文本越短，收益随轮数放大；②减少轮数（快路径 1 轮 vs tool-use 2 轮）是更大的杠杆
- **路由轮 / 生成轮提示词分离**（负责人 2026-09-22 指示「第一轮还可以挤挤」）：tool-use 第 1 轮的唯一任务是「决定调不调工具、调哪个」，格式条款在这一轮用不上。因此第 1 轮只带 `ROUTING_SYSTEM_PROMPT`（能力清单 + 何时调 + 参数约定 + 兜底，约 450 token）；第 2 轮**追加**一条 system 消息承载该域格式条款（域由模型实际调用的工具推断），而非替换 system——追加保持前缀不变（缓存可命中，且与既有 `system(域提示词) → user → system(注入片段)` 写法一致）
- **快路径命中不传工具定义**：域已锁定 + 结果已注入 → 模型无需工具；省 1364 token
- **缓存机制（2026-09-22 探针实测）**：provider 回传 `usage.prompt_tokens_details.cached_tokens`；连续两次同前缀请求，第二次命中 1408 / 2809（≈50%，静态前缀部分全部命中，变化部分未命中）。当前代码只取 `usage.prompt_tokens` → 本特性补齐采集
- **稳定前缀原则（缓存友好写法）**：
  - 工具定义 + 系统/域提示词必须**逐字节稳定**，且置于消息最前
  - 禁止在系统文本里拼时间戳、traceId、随机 ID、按请求变化的清单（一处变化 → 整段前缀失效）
  - 变化内容（用户问句、注入片段）一律靠后；**现有消息顺序 `system(域提示词) → user(问句) → system(注入片段)` 保持不变**
- **两条独立前缀**：域提示词与统一提示词各自稳定即可，不强行合并（缓存按前缀分桶，跨域本就不共享）；同一域内不得混用两种 system 文本
- **提示词单一来源**：域格式条款只保留一份（`ROUTE_HINTS[*]`），供快路径单轮与 tool-use 生成轮追加使用；路由轮提示词不再重复格式条款（现状统一提示词与域提示词各写一份，双份维护易漂移）
- **工具描述瘦身口径**：保留「何时调用 + 参数语义 + 出参形状」，删除对模型决策无用的实现细节（如会话 TTL / 重启即清 / 不经 LLM），并删除指向模型不可见工具的对比（`sango_novel_search` 描述里提到的 `sango_query` 模型看不见）
- **天气下线范围（最终态）**：除器坊外不再出现天气——前厅入口与标签、总台 MCP 注册与工具可见性、统一提示词条款、`domain` 白名单全部移除；器坊 weather server 代码保留不删（恢复成本低，删代码属孤儿改动）

### `auto` 原著判定方案（检索自证 + 双信号，2026-09-22 实测标定）

- **机制**：`auto` 路径（无域标签、L2 未命中、题库 L3 未命中）先调一次 `sango_novel_search(query, limit=10)`，用出参携带的判定信号判断：
  - `labelHit === true` 且 top1 `finalScore ≥ 0.8` → 判定原著域 → **该次检索结果直接作为注入视图**（快路径），单轮生成、不传工具
  - 否则 → 丢弃该次结果，退回现有 tool-use 路径（行为与现状一致）
- **为什么不能只看分数**（实测 8 正 / 10 负，直打 SangoIndex，无 LLM）：
  - 正样本 top1 `finalScore` 0.745 ~ 0.894；负样本 0.689 ~ 0.768 → **分布重叠**，「帮我写一首诗」0.750 高于「桃园三结义」0.745，单阈值不可分
  - 叠加标签信号后：`labelHit && ≥0.8` → 正样本命中 5/8（0.855 / 0.869 / 0.878 / 0.879 / 0.894），负样本误判 **0/10**
  - 漏判 3 条（桃园三结义 0.745 label=false、诸葛亮第一次出场 0.788、夏侯惇的字 0.811）→ 退回 tool-use，**不降质量，只是没省到 token**
- **保守取向**：误判代价高（把闲聊套上原著格式：注入无关片段 + 引用校验介入），漏判代价低（退回现状）→ 宁可漏判，不可误判
- **标定集须扩大后复核**：上表样本量小（8 正 / 10 负），阈值须在 ≥30 正 / ≥30 负上复核；正样本可用 43 条历史原著 trace 的诊断 + 语料标签集构造，负样本用历史闲聊 / 题库 trace + 手工构造；工具用现成的 `scripts/probe/recall-bench.mjs`（直打 SangoIndex，秒级、无 LLM）
- **可扫特征**（诊断字段已齐备，无需新增）：`finalScore` / `bm25`（原始分）/ `bm25Norm` / `cosine` / `labelHit` / `sources`
- **收益**：命中的 `auto` 原著问句 7205 → ≤2400（-67%）；未命中不变
- **判定信号来源的取舍**：现信号在旁路 `_meta.diagnostics` 里，而判定属主链路决策 → 需器坊在出参正式提供（契约变更）；若沿用旁路，则「无 traceId 时无诊断 → 降级不判」，行为不一致，不推荐

## 风险 & 开放问题

1. **判定标定集样本量**：0.8 阈值来自 8 正 / 10 负的小样本；扩样后阈值可能上移（漏判变多）或下移。**误判率必须保持 0**，召回率可让步
2. **判定信号驱动的降级一致性**：判定依赖器坊出参信号；器坊调用失败 / 信号缺失时必须「不判 → 走 tool-use」，不得让主链路报错
3. **语义收窄（需负责人确认）**：域锁定 + 快路径命中时不传工具 → 该场景下模型不再能自主调其他域工具（现状可以）。判定为可接受（域锁定即用户显式选定场景，域提示词已要求域内作答）
4. **天气下线的影响面**：默认场景问天气将不再有天气能力（按负责人 2026-09-22 决策）；`/weather` 改名为 `/chat`（原为「天气/风云三国/原著」三场景共用页面），旧链接直接 404（内部工具无外链，不做重定向）
5. **provider 缓存策略未文档化**：TTL 与命中粒度以实测为准。缓存是加成不是前提
6. **工具描述属对外契约**：瘦身需老陈确认不破坏 MCP 契约文档与既有测试
7. **注入片段占域锁定快路径 50%**（1600~1900 token），是瘦身的下一站；直接砍预算会伤召回质量，需先有召回质量评测口径（关联 bug-00003 / bug-00007 / bug-00008），本期不动
